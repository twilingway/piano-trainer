# Twiling Keys — дополнение к roadmap: сольфеджио, слух и гармония

**Дата:** 2026-10-11

**Статус:** предложение для реализации после P1

**Основной документ:** `TWILING_KEYS_READING_ROADMAP.md` (2026-10-09)

**Исходное условие от владельца:** **P1 «Читаю пять нот» уже реализован**. Не реализовывать его
повторно.

> Этот документ **дополняет** основной roadmap и **точечно переопределяет** приоритеты P2–P5,
> перечисленные в разделе 2. Все не упомянутые архитектурные ограничения, правила безопасности
> репозитория и требования к тестам из основного документа остаются в силе. Факт реализации P1
> принят со слов владельца, не подтверждён новым аудитом исходников.

## 1. Цель

Развивать четыре взаимосвязанных навыка, не смешивая их показатели:

1. **Чтение нот:** от символа на стане к клавише и чтению новых фраз.
2. **Сольфеджио:** ритм, интервалы, внутренний и относительный слух, слуховые диктанты, по желанию —
   пение.
3. **Гармония:** интервальная структура аккордов, обращения, тональности, гармонические функции и
   сопровождение.
4. **Исполнение:** техника, координация рук, аппликатура, игра в темпе.

Принцип: теория должна проверяться действием — **вижу → слышу → узнаю → играю**, но не каждое
упражнение обязано включать все четыре этапа. Разделять тренировки и контрольные задания без
подсказок.

## 3. Порядок разработки и зависимости

```text
P1 (готов) ──> P2 (общая аналитика) ──> P3 (интервалы)
                       │                    │
                       ├──> P4a (ритм) ─────┼──> P5 (чтение с листа)
                       └──> P4b (бас/руки) ─┘
                                            │
                              P6 (гармония) ─┤
                              P7 (диктанты) ─┤──> P8 (интеграция)
```

Диаграмма — логическая, а не жёсткий запрет параллельной разработки. **Рекомендуемый следующий шаг —
P2**, затем маленький вертикальный срез P3. P4a можно делать параллельно после согласования событий
и тайминга. P6 не обязан ждать полного P5, если уже есть надёжная MIDI-проверка одновременных нот.

## 4. P2 — общая модель прогресса (высокий приоритет)

**Сначала найти существующую статистику и запись попыток.** Не создавать вторую базу/сервис
прогресса без обоснования.

- Ввести или расширить `skillId`, `exerciseId`, `attemptId`, `inputSource`, `startedAt`,
  `completedAt`, `hintLevel`, `firstAttemptCorrect`.
- Хранить метрики **по типу задания**, а не одну универсальную «точность»: для одиночной ноты —
  верность и задержка; для ритма — смещение onset и длительности; для интервала на слух — выбор и
  число прослушиваний; для аккорда — множество MIDI-нот и временное окно одновременности.
- Для оценки задержки реакции использовать монотонное время события предъявления/ответа; музыкальную
  синхронизацию оставить за `PracticeSession`.
- Сохранять историю подсказок; результат после подсказки не считать независимым распознаванием.
- Адаптация: чаще давать проблемные задания, оставляя контрольные новые комбинации и отложенное
  повторение. Пороги конфигурируемые, не выдавать их за валидированную педагогическую норму.
- Версионировать схему и предусмотреть миграцию существующего прогресса, если он хранится
  локально/на сервере.

**Приёмка:** P1 продолжает работать; есть отдельные метрики самостоятельного ответа; один и тот же
seed воспроизводит набор заданий; тесты на дубли MIDI note-on, неверный ввод, подсказки, паузу и
смену упражнения.

## 5. P3 — интервалы: визуально, на клавиатуре и на слух

### Последовательность уроков

1. Повтор звука, шаг вверх/вниз, скачок через ступень на нотном стане (без терминологической
   перегрузки).
2. Секунда и терция в знакомой пятинотной позиции; игра по нотам.
3. Кварта, квинта, октава после расширения диапазона; перемещения руки отдельно от распознавания.
4. Мелодический интервал: два звука последовательно; различение вверх/вниз и величины.
5. Гармонический интервал: два звука одновременно; визуальное и слуховое распознавание.
6. Качество интервала (большой/малый/чистый) вводить после уверенного счёта ступеней и знакомства с
   полутонами.

**Режимы:** `see-and-play`, `hear-and-choose`, `hear-and-play`, `read-new-phrase`. На слух сначала
дать опорный звук и возможность повторить прослушивание; не требовать абсолютного слуха.

**Проверки:** правильность интервала, направление, качество (если изучено), первая попытка,
количество прослушиваний. Для MIDI `hear-and-play` явно определить, разрешены ли транспозиции; в
начальном варианте проверять конкретные высоты при известной исходной ноте.

**Приёмка:** генератор не выдаёт неизученные интервалы, умеет повторять seed; Tone.js воспроизводит
ожидаемые высоты; упражнения работают без MIDI через существующий ввод; при переключении упражнений
нет зависших звуков.

## 6. P4a — ритмическое сольфеджио

- Сначала хлопок/тап одной клавишей под ровный пульс; затем четверти, половинные, целые и паузы.
- Затем восьмые, простые размеры 2/4, 3/4, 4/4, позже синкопы и составные размеры.
- Режимы: `listen-and-repeat`, `read-and-tap`, `play-with-pulse`.
- При MIDI учитывать `noteOn`/`noteOff`, задержки устройства и допустимое окно точности; паузы
  проверять отсутствием событий.
- В `Wait for note` не выдавать точность ритма как измеренную: для оценки ритма требуется режим с
  временным эталоном.
- Отдельно считать onset deviation, пропуски, лишние удары, при необходимости длительность
  удержания. Калибровка аудио/MIDI задержки должна быть доступна при необходимости.

**Приёмка:** тесты с фиксированным таймлайном, BPM, паузами, досрочными/поздними нажатиями,
повторными MIDI-событиями, паузой/возобновлением.

## 7. P4b — басовый ключ и координация рук

- Фиксированная позиция левой руки и опорные ноты басового ключа.
- Чтение коротких фраз только левой рукой.
- Одновременное нажатие одной ноты каждой рукой; затем удержание баса при движении мелодии.
- Простые независимые ритмы только после устойчивого пульса.
- Повторно использовать существующие OSMD/Pixi/MIDI, solver аппликатуры и механизм фраз.

**Приёмка:** корректная маршрутизация нот по рукам, одновременные события, удержания, отпускания и
отсутствие регрессии режима двух рук.

## 8. P5 — аппликатура и чтение с листа (сохраняется)

Сохранить требования старого P5. Добавить:

- Отдельный показатель чтения **новых** фраз, не смешивать с исполнением заученной пьесы.
- Предпросмотр 5–15 секунд как настраиваемый этап, без раскрытия клавиш.
- После освоения интервалов проверять распознавание групп (гаммообразный ход, трезвучие), а не
  только отдельных нот.
- Стандартный MIDI не определяет используемый палец; не штрафовать за «неверный палец» без
  достоверного датчика.

## 9. P6 — основы гармонии

### Уроки

1. Тон/полутон, мажорное и минорное трезвучие: сначала C–E–G и C–E♭–G.
2. Строение трезвучий на разных тониках; запись на стане и исполнение.
3. Обращения трезвучий и распознавание того же набора классов высот в другом расположении.
4. Тональность до мажор, ступени, аккорды I, IV, V и их функции (тоника, субдоминанта, доминанта).
5. Простые последовательности I–IV–V–I и I–V–vi–IV; сопровождение знакомой мелодии.
6. Основы голосоведения и плавных переходов между аккордами — позже, после уверенных обращений.

### Интерактивные режимы

- `build-chord`: сыграть набор высот одновременно.
- `name-chord`: распознать трезвучие на стане или на слух.
- `invert-chord`: исполнить заданное обращение.
- `complete-progression`: выбрать или сыграть следующий аккорд в контексте тональности.

**Проверка:** различать конкретные высоты, классы высот, бас и обращение. Не считать C–E–G и E–G–C
одной и той же **аппликатурой/позицией**, хотя это один класс трезвучия. Определить окно для
аккордового нажатия и правила педали/удержания; не оценивать только порядок MIDI note-on.

**Приёмка:** корректные мажор/минор, обращения, транспозиции, одновременные MIDI-ноты; тесты на
октавные дубли и посторонние звуки.

## 10. P7 — слуховые диктанты и пение

### P7a — без микрофона (сначала)

- Двух- и трёхнотные диктанты из изученного диапазона; позже 4–8 нот.
- Программа играет фразу через существующий аудиодвижок; ученик воспроизводит её на MIDI-клавиатуре
  или вводит в нотный редактор, если он уже есть.
- Сначала известна стартовая нота; затем добавлять задания с неизвестным стартом и относительным
  ответом.
- Ограничивать число повторов только в контрольном режиме; в учебном разрешать слушать повторно.
- Раздельные метрики высоты, порядка, ритма, количества прослушиваний.

### P7b — микрофон (опционально, после P7a)

- Пение коротких фраз с исходной нотой, выдаваемой приложением.
- Явное разрешение микрофона; предпочтительно локальная обработка, без сохранения сырого аудио по
  умолчанию.
- Проверять высоту с допуском, учитывать октавные ошибки и нестабильность голоса; не выставлять
  жёсткую оценку на основании одного мгновенного измерения.
- Не блокировать курс для пользователей, которые не хотят или не могут петь.

## 11. P8 — интегрированные мини-уроки

Шаблон «Одна тема — несколько навыков», например **до мажор**:

1. Найди C4–G4 на клавиатуре.
2. Прочитай незнакомую мелодию из этих нот.
3. Повтори услышанный ритм одной клавишей.
4. Узнай терцию и квинту на слух и сыграй их.
5. Построй C major, затем F и G major.
6. Сыграй короткую пьесу с басом и мелодией.
7. Пройди контрольный тест на **новом** материале без подсказок.

Делать уроки короткими, адаптивными, с возможностью повторять отдельный навык. Не объявлять освоение
гармонии по одному правильному аккорду.

## 12. Общие продуктовые правила

- **Два разных прогресса:** `repertoirePerformance` (выученная пьеса) и `sightReading` (незнакомая
  музыка). Сольфеджио и гармонию хранить как дополнительные профили навыков.
- **Постепенное снятие подсказок:** в тренировке разрешены названия нот, подсветка, повтор звука; в
  контрольной попытке — без них.
- **Никакой ложной проверки пальцев:** стандартный MIDI даёт клавишу, но не номер пальца.
- **Не путать интервалы:** диатонический номер (терция) и хроматическое качество (большая/малая) —
  разные свойства.
- **Не путать относительный слух с абсолютным:** не требовать угадывать ноту без опоры как
  обязательный базовый навык.
- **Не ломать текущий интерфейс:** новые режимы используют общие ноты, таймлайн, MIDI и рендереры;
  можно скрывать слои, но не дублировать их движки.
- **Доступность:** всё основное работает без MIDI через уже поддерживаемые средства ввода; слуховые
  задания имеют визуальный альтернативный учебный путь, если звук недоступен.
- **Локализация:** RU/EN через существующий механизм; названия нот и буквенные обозначения должны
  быть согласованы.
- **Педагогическая честность:** стартовые пороги освоения — гипотезы, которые корректируются по
  результатам учеников.

## 13. Рекомендуемый минимальный следующий релиз

**Релиз A: P2 + вертикальный срез P3.**

1. Проанализировать текущую реализацию P1 и существующие события/статистику.
2. Добавить только недостающие поля прогресса и миграции, если требуются.
3. Реализовать интервалы «повтор / шаг / терция» в режиме `see-and-play`.
4. Добавить `hear-and-choose` для тех же интервалов с Tone.js.
5. В UI показывать раздельный прогресс зрительного и слухового распознавания.
6. Покрыть pure-core тестами генератор, оценку, повтор по seed и крайние случаи MIDI.
7. Проверить регрессии P1 и старых режимов уроков.

**Не включать в релиз A:** микрофон, сложные аккорды, полный редактор диктантов, переработку общего
UI и новый сервис прогресса без необходимости.
