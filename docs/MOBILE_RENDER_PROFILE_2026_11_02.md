# Мобильный 3D: замеры 2 ноября 2026

## Условия и очередь

Лоадер готов отдельно: [PR #277](https://github.com/twilingway/piano-trainer/pull/277), не влит.
Итоговое решение игрока: первый запуск на телефонах/планшетах — классика, сохранённый вид имеет
приоритет. Ручной 3D использует полный desktop-свет. Задержки изменения настроек исправляются
отдельно от стоимости постоянной отрисовки. Bluetooth MIDI проверяется отдельно.

Исходный renderer: `origin/dev 9e95e937`; первые замеры на production-сборке PR #277 с тем же
renderer после завершения загрузчика. Chrome Android 13, реальное Wi-Fi ADB/CDP, видимая вкладка,
встроенный лёгкий «Гимн России», прямые ноты, пауза. Телефон M2101K6G / Adreno 618: DPR 2,75, buffer
2307×1003. Планшет SM-P610 / Mali-G72: DPR 1,5, buffer 2000×1074. Каждый основной замер — около 6,5
секунды. Отдельные ранние замеры были при раскрытой адресной строке; в таблице ниже сравниваются
одинаковые размеры buffer.

| Полный 3D                                                            |         4,71 |         5,26 |

В полном 3D 185/223 draw calls и 27/32 тысяч треугольников на кадр. Только CPU-вызовы draw занимали
примерно 1,5/4,1 мс; длительность кадра — примерно 217/200 мс. GPU timer query недоступен, поэтому
точное GPU-время не заявляется. Вклад GPU/сложности освещения подтверждён отдельным изменением
разрешения и состава света. Диагностические изменения не являются выпущенным исправлением.

## Зависание при настройке

Простая смена вкладок настроек не дала canvas resize или компиляции. После изменения диапазона «По
песне → 88 клавиш → По песне» на планшете зарегистрированы 17 deleteProgram, 10 createProgram, 20
compileShader, 10 linkProgram и кадры 2281/1182 мс. Canvas не менял размер. ThreeKeyEmission удалял
последних владельцев shader-программ перед созданием следующего поколения материалов. Исправление
удерживает одно прежнее поколение до успешного кадра.

Отдельно renderer повторно присваивал canvas.width/height при неизменном размере. Добавлена защита с
учётом реальных логических/физических размеров и переданного DPR. Этот путь не объявляется причиной
измеренного зависания диапазона.

## Согласованное изменение

После визуальной проверки игрок отменил облегчённое освещение: клавиши выглядели слишком тускло.
Экспериментальный профиль полностью удалён. На основном сенсорном указателе fallback вида —
классика; валидные сохранённые современные/прежние настройки не мигрируют. Desktop сохраняет
начальный 3D. Ручной 3D на всех устройствах имеет исходный полный свет, геометрию и разрешение.

Дополнительно выявлено ненужное запекание масок подсветки и запасных плоских текстур в 3D:
`generateTexture → readRenderTargetPixels` синхронизировал CPU с GPU при перестройке. В объёмном
виде эти текстуры не использовались. Запекание пропускается, собственные текстуры освобождаются; при
возврате в классику/аркаду создаются заново. Общие ресурсы оформления сохраняются.

## Замеры промежуточного облегчённого света

[PR #278](https://github.com/twilingway/piano-trainer/pull/278), отдельно от лоадера. Эти FPS
относятся к промежуточному профилю, который не входит в окончательную реализацию. Совместная сборка
#277 + #278 получена временным локальным слиянием без коммита; слияние отменено, preview сохранён
отдельно в игнорируемой папке. Основной dev не менялся.

- На паузе: телефон 40,52 FPS, планшет 36,78 FPS. Buffer 2307×755 / 2000×822; сопоставимые начальные
  полные 3D-замеры на этих размерах были около 5–6 FPS.
- Во время прогретого реального проигрывания: 27,71 / 25,72 FPS, P95 кадра 50 мс. Песня прошла 00:03
  → 00:08 на скорости 75%. После входа в полноэкранный режим buffer вырос до 2307×1157 / 2000×1218;
  разрешение не понижалось.
- В первом запуске воспроизведения с подготовкой звука/эффектов: 21,37 / 18,35 FPS. Эти холодные
  значения не смешиваются с прогретым проигрыванием.
- Видимые объёмные клавиши, ноты, свечение и частицы проверены на скриншотах устройств.
- По 20 изменений диапазона на каждом устройстве: **0 compileShader**, число программ 12 → 12,
  текущие клавиши 88, отложенные материалы после кадра 0.
- Остаточные длинные кадры при смене диапазона: телефон 383–667 мс, планшет 466–949 мс. Повторная
  компиляция устранена, но вся задержка перестройки пока не устранена.
- Реальный первый переход в fullscreen меняет размер canvas; он не подавляется resize-guard. Поздние
  смены диапазона не дали присваиваний canvas.width/height.
- Потери WebGL-контекста и ошибки во время замеров не зарегистрированы.

На промежуточной версии `pnpm check`: 4498 tests + 30 compiler; `pnpm spec:validate`: 87/87.
Гарантия 60 FPS в ручном полном 3D и полное устранение всех чёрных кадров не заявляются. Следующий
узкий backlog: стоимость перестройки UV/геометрии, с отдельным профилем кадра; не менять качество и
разрешение без согласованного решения.

## Вспышка при касании экрана

Причина воспроизведена отдельно от renderer: после небольшого движения пальца canvas получает
`cursor: pointer`, и Chrome накладывает свой `-webkit-tap-highlight-color: rgba(51,181,229,0.4)` на
всю игровую область. На планшете проверена классика, на телефоне — аркада. Стационарные касания до
первого движения пальца проблему не воспроизводили.

Запись реального экрана до/после отключения только tap-highlight подтвердила устранение вспышки.
Средняя Y-яркость неподвижного участка: планшет 25,3 → 71,25 при вспышке, после исправления
25,289–25,342 на 239 кадрах; телефон 25 → 71 до и ровно 25 на 144 кадрах после. Подсветка отдельной
клавиши и MIDI-ввод сохраняются. В CSS отключена только системная подсветка игрового canvas.

## Итоговая проверка

- Без сохранённого вида UI обоих реальных устройств выбирает классику; временные настройки
  восстановлены после проверки. Сохранённая аркада телефона и классика планшета не заменены.
- Вручную выбранный 3D содержит исходные Hemisphere/Directional, восемь SpotLight и RectAreaLight;
  на планшете это подтверждено также uniform-массивами реально используемых shader-программ.
- В полном 3D планшета при buffer 2000×822 изменение диапазона туда-обратно дало 0 compileShader, 0
  readPixels и 0 canvas resize; максимальный интервал кадра 216,3 мс. Полный свет остаётся дорогим.
- После перезагрузки собранной версии tap-highlight canvas прозрачен без временного inline CSS.
- `pnpm check`: 4508 тестов, 30 проверок компилятора, lint/format/typecheck/build прошли;
  `pnpm spec:validate`: 87/87. Независимое ревью — без блокирующих замечаний.
- Совместная сборка с PR #277: typecheck и 134 целевых теста прошли. На планшете один из запусков
  лоадера занял более 25 секунд; эти данные не объявляются быстрым стартом. Загрузка шрифтов и общих
  ресурсов может продолжаться дольше этого диагностического окна.

Bluetooth MIDI: устройство обнаружено в Chrome и Android, но нажатия не поступили ни в raw Web MIDI,
ни в отдельный нативный приёмник Android. Переподключение и сброс Bluetooth не восстановили поток.
Сброс системной MIDI-службы оставил старые записи и вызвал падение Chrome с `device does not exist`;
планшет перезагружен с разрешения игрока. После перезагрузки и нового подключения поток
восстановлен: Chrome получил NoteOn/NoteOff C4 дважды и C5; приложение распознало C5 и перевело
определение диапазона ко второму шагу. Проверка отменена без изменения диапазона. Chrome снова
запускается; в системе одно устройство без дубликатов. Исправление кода MIDI не понадобилось. Долгая
работа, повторное переподключение и другие браузеры этим коротким тестом не подтверждены.
Последующее исчезновение устройства игрок объяснил выключением самого пианино.
