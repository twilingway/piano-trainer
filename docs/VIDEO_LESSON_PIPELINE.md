# Разбор локального видеоурока

Этот порядок одинаков для Codex, Claude Code и локального Qwen. Он готовит данные для проверенного
урока: речь преподавателя, её тайминг и кадры с табами. Все исходники и результаты остаются на
компьютере. Сервер, ComfyUI и LM Studio для этого процесса не требуются.

## Среда и команды

Нужны Node.js из проекта, Python 3.10+, FFmpeg/FFprobe в `PATH`, драйвер NVIDIA и CUDA PyTorch. На
этом компьютере выбран `faster-whisper` с моделью `turbo`, CUDA и `float16` для RTX 4090. CLI не
переключается незаметно на CPU. Обычная текстовая модель Qwen не является распознавателем речи.

В основной папке репозитория:

```powershell
pnpm lesson-video:setup --no-download
pnpm lesson-video:setup --model turbo
```

Первый вариант готовит и проверяет GPU без загрузки модели; второй также получает модель. Повторный
запуск использует локальный кэш. Для другой базовой Python-среды передать
`--python "C:\путь\python.exe"` только команде `setup`.

Скрипт создаёт `.browser-artifacts/lesson-analysis/.venv` с `--system-site-packages`, чтобы
использовать уже установленный CUDA PyTorch. Он ставит `faster-whisper==1.2.1` и
`ctranslate2==4.8.2` в локальную среду. Если CUDA PyTorch недоступен, устанавливает туда
`torch==2.7.0` из официального индекса `cu126`. Глобальная среда Python не меняется. Модели и
Hugging Face cache также находятся в `.browser-artifacts/lesson-analysis/`.

Python helper генерируется из tracked TypeScript в той же игнорируемой папке. Для Windows он
добавляет DLL из `torch/lib` в `PATH` только своего процесса. Загрузка модели использует проверяемый
HTTPS; `HF_HUB_DISABLE_XET=1` обходит зависающий Xet transport. Таймаут получения метаданных/данных
— 60 секунд. Если модель не загрузилась, проверить сеть и повторить `setup`; не отключать проверку
TLS и не загружать видео в сторонний сервис. Загрузка весов обращается к сети, распознавание самого
урока выполняется локально.

## От видео к расшифровке

Выбрать конкретный файл и согласованный с пользователем диапазон. Время можно задавать секундами,
`мм:сс` или `чч:мм:сс`, с дробной частью секунд. `--start` по умолчанию 0, без `--end` команда
обрабатывает оставшуюся часть видео. Для первого прохода лучше короткий фрагмент.

```powershell
$courseRoot = "G:\папка курса"
$video = "$courseRoot\1 ступень\Урок 1. Вводный\Урок 1. Вводный.mp4"
pnpm lesson-video:prepare --video "$video" --course-root "$courseRoot" --id intro-60-120 --start 01:00 --end 02:00
```

CLI определяет длительность через FFprobe, извлекает выбранное аудио в mono PCM16 16 kHz, затем
распознаёт русскую речь с временными отметками слов. Пример выходной папки:

```text
local-lessons/.analysis/папка курса/1 ступень/Урок 1. Вводный/Урок 1. Вводный.mp4/runs/intro-60-120/
  source.json                 путь, размер, mtime, корень курса и названия
  metadata.json               источник, начало, конец, длительность и формат
  audio.wav                   только выбранный фрагмент
  audio-receipt.json          SHA256 успешно извлечённого аудио
  transcript.json             сегменты, слова и вероятность слова
  transcript.txt              текст для чтения агентом
  transcript.srt              субтитры для сопоставления с видео
  timeline-draft.json         кандидаты этапов по словам преподавателя
```

`--course-root` задаёт существующую папку курса над каталогами ступеней. Все вложенные папки и имя
видео, включая расширение, сохраняются. Для второго видеофайла того же урока будет отдельная папка;
для другого фрагмента или модели — новый каталог `runs/<id>`. Это ID анализа, а не этап тренажёра.
Повторные запуски не сваливают материалы разных видео в одну папку.

`source.json` хранит `courseRoot` (канонический абсолютный путь), `courseTitle` (имя папки курса),
`lessonTitle` (имя родительской папки видео), `relativeVideo` (путь видео от корня курса с `/`), а
также `path`, `size` и `mtimeMs`. Название урока в плане и поле `title` будущего манифеста берутся
из `lessonTitle`, например «Урок 1. Вводный». Название песни может быть отдельной подписью внутри
урока. CLI сохраняет названия, но не подключает урок автоматически.

Исходник после разрешения symlink/junction должен находиться внутри канонического `--course-root`.
Путь за пределами этой папки отклоняется. Названия сохраняются без латинизации. Если разные
физические курсы имеют одинаковые имена папок и совпадающую структуру, привязка `source.json`
отклонит смешивание источников; для второго анализа выбрать новый `--id` или более высокий корень,
от которого их папки различаются.

Без `--course-root` сохраняется прежняя схема `local-lessons/.analysis/<id>/` и формат старого
`source.json`. Уже существующие анализы не перемещаются и не перезаписываются. Для
структурированного анализа передавать тот же `--course-root` как в `prepare`, так и в `frames`.

Все отметки в JSON/TXT/SRT — **абсолютное время исходного видео**, а не время от начала вырезанного
аудио. Например, первое слово фрагмента `01:00–02:00` имеет отметку около 60 секунд. `--id` содержит
только латинские буквы, цифры, дефисы и подчёркивания; пути через него запрещены.

Подготовленные файлы используются повторно только при совпадении пути, размера и времени изменения
исходника, корня курса и названий, точного диапазона, формата и контрольной суммы аудио. Проверяется
также длительность WAV, чтобы не принять незавершённое извлечение. Другой файл, изменённое видео,
другой диапазон или другая ASR-модель требуют нового `--id`. FFmpeg запускается с `-n`: оригинал и
существующие аудио/кадры не перезаписываются. После аварийного неполного вывода выбрать новый ID; не
удалять исходное видео. Выходные пути с перенаправлением за пределы репозитория через
junction/symlink отклоняются.

При плохой речи можно сделать отдельный второй проход `--model large-v3` с новым ID. Модель
скачивается локально при первом использовании. Точность оценивается по самому фрагменту, а не по
названию модели.

## Этапы и нужные кадры

1. Сначала просмотреть каталог исходного урока. Прочитать приложенные PDF/DOCX и посмотреть схемы,
   табы, порядок разделов. При необходимости извлечь текст, изображения или страницы локально,
   сохранив ссылку на исходный документ. Реестр материалов и общие результаты урока размещать рядом
   с каталогом видео, как описано ниже; файлы конкретного запуска остаются в `runs/<id>`.
2. Агент читает TXT и JSON, отмечает объяснения правой/левой руки, соединение рук, названия нот,
   пальцы, счёт, повторы и смену упражнений. Составить главы с типами `theory`, `coordination`,
   `song`, `repetition`, `postroll`. Последний тип означает постороннюю часть после урока, а не
   задание. Отделить объяснения от исполнения и руки ученика от сопровождения преподавателя: автор
   может аккомпанировать, пока ученик разучивает одну руку; это не этап «Обе».
3. `timeline-draft.json` помогает найти упоминания рук, но это только кандидаты с цитатой и
   временем. Слова о правой руке могут быть советом, а не началом нового этапа. По нужным точкам
   извлекаются кадры исходного видео. Не пытаться просмотреть каждый кадр урока.

```powershell
pnpm lesson-video:frames --video "$video" --course-root "$courseRoot" --id intro-60-120 --at 65,74.5,01:30
pnpm lesson-video:frames --video "$video" --course-root "$courseRoot" --id storyboard --every 30 --start 0 --end 10:00
```

`--at` — список абсолютных времён через запятую. `--every` — шаг обзорной раскадровки; эти режимы
несовместимы. По умолчанию максимум 80 кадров; `--max-frames` допускает 1–200. Если обзор превышает
лимит, CLI предлагает увеличить шаг или сократить диапазон. Кадры сохраняются в `frames/`, а
`frames.json` связывает каждый JPG со временем исходника с точностью до миллисекунды. Конец
диапазона не включается. Новые точки можно добавлять той же командой с прежним ID и тем же
источником.

4. Агент смотрит кадры с табами и положением рук. Если таб изменился между обзорными кадрами,
   запросить более плотные точки вокруг изменения. Сопоставить буквы, октавы, пальцы, одновременные
   ноты, длительности, паузы и повторы с аудио и показом клавиш.
5. Подготовить локальный план урока и структурированные события с этапами, логическими фразами,
   повторами исполнения и ссылками на подтверждающие кадры/таймкоды. Замедленный показ или повтор
   фразы в конце урока не получают новый `phraseId` сами по себе: связать их через `performanceId`.
   Новое содержание получает отдельную фразу, исправление содержания — новую версию. Записать
   неясности. Не выбирать октаву, ритм или границу этапа только по тексту ASR.
6. После проверки содержания сохранить MusicXML в `local-lessons/.course/<lesson>/`, затем
   подключить `local-lessons/course.json` по [описанию курса](LESSON_COURSE.md). Путь фразы в
   манифесте: `.course/lesson-01/phrase-01.musicxml`. Только проверенное содержание получает
   `reviewed: true`; этот pipeline никогда не делает это автоматически.

Глубина `.course/<lesson>/` отделяет новые фразы от старого импорта библиотеки.
`local-lessons/.analysis/`, `local-lessons/.course/` и `.browser-artifacts/` уже игнорируются git. В
публичный PR входят инструменты и документация, а не музыка, видео, аудио, модели или кадры курса.

## Речь, музыка и темп

ASR переводит речь в текст. Он может пропускать слова, путать названия нот и галлюцининировать на
музыке; вероятность слова не доказывает правильность. Длинный сегмент над музыкальным вступлением не
доказывает точный момент произнесения. Даже пустой текст не означает отсутствие музыки. Нужна сверка
с кадрами и прослушиванием спорного фрагмента.

Музыку нельзя получить как достоверные ноты MusicXML этим распознавателем. Отдельная транскрипция
фортепиано в MIDI может помочь, но должна проверяться по табам, клавишам и слуху. В этой версии
отдельный музыкальный транскриптор не установлен. Темп самого упражнения определяется по счёту,
атакам нот и указаниям преподавателя; скорость разговора и длина видео не являются BPM партитуры.
Ритм и октавы фиксируются до подключения фразы в курс.

Музыкальные доли в плане и XML отделены от видеосекунд. Для BPM записывать `unit` и источник
подтверждения: четверть, восьмая, четверть с точкой и т. п. Внутренняя единица `startBeat` и
`durationBeats` — четверть. Например, BPM по четверти с точкой преобразуется в четвертной BPM
умножением на 1,5; исходное значение и единица сохраняются в evidence. Темп может отличаться у
замедленной демонстрации и полного исполнения. Лига продления соединяет длительности в одно нажатие;
её продолжение не является новой атакой. Стрелку переноса на октаву сверять с регистром клавиш,
документом и показом рук.

## Пальцы преподавателя и подсказки рук

Сохранять три независимых происхождения: `written` — цифра в табах/партитуре, `teacher` —
наблюдаемое нажатие преподавателя, `computed` — решение алгоритма аппликатуры. Одно не доказывает
другое. Для проверки преподавателя выбрать кадры до атаки, во время атаки и после, отметить руку,
клавишу, палец 1–5, видимость касания, регистр, смену позиции и передачу пальца. Не угадывать палец
под закрывающей рукой, по одному смазанному кадру или только по привычной аппликатуре. Неизвестное
значение — `null`; исходное наблюдение и степень подтверждения остаются в evidence.

Если написанный палец расходится с видимым, сохранить оба и отдельное решение для учебной фразы с
обоснованием. Подтверждённые пальцы записать как fingering в MusicXML; реестр их происхождения
остаётся локальным, вне XML. Расчёт тренажёра может предложить вариант, но не становится задним
числом наблюдением преподавателя.

В проекте уже есть [2D HandsLayer](../src/render/HandsLayer.ts) с
[handPose](../src/render/handPose.ts) и [3D liveHands](../src/render/three/liveHands.ts) с
[handPlacement](../src/render/three/handPlacement.ts). Этот разбор не меняет renderer и не обещает
восстановление движений преподавателя. При дальнейшей работе над подсказками проверенные MusicXML
пальцы должны пройти путь `scoreFinger` → `withFingering` → `finger`; при приёмке сравнивать
`finger` с `scoreFinger`, поскольку решение аккорда может заменить конфликтующие закреплённые
пальцы. Проверить выбранную руку и режим ожидания отдельно: существующий 3D источник получает
ноты/время без такой же информации о `hands`/`waitingFor`, как 2D. Все подсказки читают часы
`PracticeSession`; самостоятельных часов и автоматического motion capture этот pipeline не создаёт.

## План для следующего агента

Общий план, реестр и материалы находятся в папке урока рядом с каталогами видео. CLI создаёт только
каталог запуска; агент размещает общие материалы и сводный план локально:

```text
local-lessons/.analysis/<курс>/<ступень>/<папка урока>/
  materials/
    index.json                 исходные документы и локальные извлечения
  lesson-plan.md               читаемый сводный план
  lesson-analysis.json         главы, фразы, исполнения, события и evidence
  <имя видео>.mp4/runs/<id>/    source, audio, transcript, timeline-draft, frames
```

`materials/index.json` — локальный реестр документов: стабильный `id`, `kind` (`pdf`, `docx`,
`image`), исходный абсолютный путь, размер, mtime и SHA256, пути локальных извлечений и номера
страниц. Другие видео этого же урока имеют собственные папки и запуски; сводный план ссылается на
каждый источник. Уже созданный план внутри `runs/<id>` можно сохранить как заметки конкретного
прохода, а сводную версию создать рядом с видео. Реестр не добавлять в git.

`lesson-plan.md` содержит:

- Название урока из папки (`lessonTitle`), корень курса, исходное видео, ID анализа, интервал,
  ASR-модель и ссылки на JSON/SRT/кадры.
- Цель урока, предусмотренные этапы и рекомендуемый порядок фраз со стабильными ID.
- Для каждой фразы: начало/конец демонстрации, ноты с октавами, пальцы, длительности и паузы,
  одновременность рук, повторы и их порядок.
- Темп в BPM с единицей доли, источник подтверждения (счёт автора, видимый метроном или измерение
  атак) и уверенность. Изменения темпа указать отдельно. Видеосекунды не заменяют музыкальные доли.
- Неизвестные значения и противоречия, необходимые дополнительные кадры/прослушивание и вопросы.
- После сверки: соответствие каждой фразы её MusicXML и результат проверки в синтетическом
  тренажёре. До этого план и timeline остаются `reviewed: false`.

### Структура для обмена с агентами

`lesson-analysis.json` — договорённость для локального анализа, а не автоматически импортируемый
формат приложения. Минимальная заготовка без музыки:

```json
{
  "schemaVersion": 1,
  "reviewed": false,
  "lesson": { "id": "lesson-id", "title": "Имя папки урока" },
  "sources": [],
  "musicalTime": { "beatUnit": "quarter", "tempo": null },
  "chapters": [],
  "phrases": [],
  "performances": [],
  "evidence": [],
  "contradictions": []
}
```

- `sources`: `id`, `kind`, относительный путь к `source.json` запуска или записи материала.
- `chapters`: `id`, `kind`, `sourceId`, `[startSeconds, endSeconds]`, краткая цель, этап ученика
  (`right`, `left`, `both` или `null`), роль преподавателя и ссылки на evidence.
- `phrases`: стабильные `id`, `version`, требуемые руки, порядок, список `events`. Повторное
  исполнение в видео не дублирует этот список. Музыкальный повтор внутри задания записывается явно в
  его последовательности событий, чтобы MusicXML воспроизводил весь требуемый проход.
- `performances`: `id`, `phraseId`, `sourceId`, диапазон видеосекунд, этап ученика, порядок, темп
  именно этого исполнения, evidence. Через них сопоставляются демонстрация, практика и повтор.
- `tempo`: `bpm`, `unit`, `quarterBpm`, `evidenceIds`, подтверждение. Если темп не проверен —
  `null`.

Нотное событие хранит значение отдельно от доказательств. Схема одного события:

```json
{
  "id": "event-id",
  "hand": "right",
  "pitch": { "name": null, "octave": null, "midi": null },
  "startBeat": null,
  "durationBeats": null,
  "fingers": {
    "written": { "value": null, "evidenceIds": [] },
    "teacher": { "value": null, "evidenceIds": [] },
    "computed": { "value": null, "algorithm": null }
  },
  "fingerDecision": { "value": null, "origin": null, "reason": null },
  "evidenceByField": { "pitch": [], "timing": [], "finger": [] }
}
```

Одновременные события имеют одинаковый `startBeat`. Пауза указывается отдельным событием `rest` с
долями и длительностью; её пальцы и высота отсутствуют. Для продления лигой событие содержит
совокупную длительность и ссылки на исходные связанные ноты, без второй атаки.

`evidence`: стабильный `id`, `sourceId`, `kind` (`frame`, `document`, `speech`, `audio`,
`calculation`), видеовремя или страница, путь к локальному файлу, краткое наблюдение, подтверждение
(`observed`, `corroborated`, `inferred`, `unresolved`). Для пальцев дополнительно записывать
`attackSeconds`, кадры `before`/`during`/`after`, руку, регистр, видимость, смену позиции и передачу
пальца. Пример подтверждения: кадр показывает касание; соседние кадры и таб согласуются. Одной
вероятности ASR недостаточно. Неустановленные значения остаются `null`.

`contradictions`: `id`, затронутые `eventIds`/поля, конфликтующие `evidenceIds`, статус `pending`
или `resolved`, принятое решение и основание. Проверка перед `reviewed: true`: нет
pending-противоречий в необходимых нотах/ритме/октавах/учебных пальцах, главы и реальные этапы
согласуются с видео, исполнения сопоставлены с фразами, MusicXML соответствует подтверждённым
событиям. Наблюдение скрытого пальца преподавателя может остаться неизвестным, если учебный палец
надёжно подтверждён другим источником; это не повод подменять наблюдение расчётом.

Для текстового Qwen передавать TXT/JSON и этот план. Кадры может разбирать модель с поддержкой
изображений; текстовому агенту нужны проверенные описания кадров от агента, который их видел. Не
приписывать обычной текстовой модели возможность видеть видео. Работа по этому документу не требует
отдельного инструмента Codex и сохраняет тот же формат для Claude Code.

Исходные инструменты: [faster-whisper](https://github.com/SYSTRAN/faster-whisper) (CUDA/cuDNN,
отметки слов, VAD) и [PyTorch](https://pytorch.org/get-started/previous-versions/).
[Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR) — отдельная модель распознавания речи для
возможного сравнения; обычный Qwen в LM Studio её не заменяет. Qwen3-ASR этим pipeline не
установлен.

Все команды работают в управляемом процессе без фоновых серверов. Ctrl+C останавливает текущий
дочерний процесс. `--help` у любой команды только показывает справку и не готовит файлы.
