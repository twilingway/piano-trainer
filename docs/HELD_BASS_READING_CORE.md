# Чистое ядро «Держу бас и играю мелодию»

`HeldBassSession` хранит журнал курса и доказательства текущего фрагмента. Она не запускает таймеры,
не интегрирует музыкальное время и не получает звук: единственный clock принадлежит
`PracticeSession`. Генератор создаёт десять отдельных MusicXML/Song: пять на две доли и пять на
четыре, каждая басовая высота C3–G3 встречается дважды; мелодия C4–G4 содержит тридцать четвертей.
Первое начало имеет два noteId, следующие — по одному. Идентификаторы сверяются с parsed Song.

## Соединение с оболочкой

1. `prepare(fragmentId, performanceMs)` выбирает очередной фрагмент или подтверждает полный retry.
   При удержанных физических владельцах начало не меняется. `present` отмечает показ двух станов;
   `setActive` задаёт raw gate активности, `markStarted` отдельно получает календарную дату.
2. Перед вводом/кадром оболочка передаёт фактический `clockReceipt`: скопированные `ClockSegment`,
   songTime, waiting, ended и dueNoteIds. История дополняется без изменения прежних anchors.
3. `input` принимает raw down/up, origin, owner и offset с возрастом 0–250 мс. `tick` читает clock;
   `pendingCommit` появляется только строго после последней принятой атаки +250 мс. Оболочка
   вызывает ограниченный `commitVerifiedOnset`, затем
   `acknowledgeOnset(request, accepted, receipt)`.
4. `retryCommand` появляется после ошибки/отмены и реального полного отпускания. Оболочка создаёт
   новый Song/PracticeSession того же фрагмента; `prepare` сохраняет прошлые попытки и помощь.
   Следующий фрагмент выбирается лишь после окончательного доказательства предыдущего.
5. `showHint(fragmentId, step, level, performanceMs)` учитывает только реально показанную помощь
   актуального шага. `snapshot.hintLevel` относится к текущему шагу и сохраняется при retry этого
   фрагмента, не раскрывая другие шаги; результат хранит максимум и весь журнал помощи фрагмента.
   `suggestHint` читает активное ожидание шага, исключая движение и прежние ожидания.
   Имена/подсветка клавиш требуют отдельной квитанции рендера.

## Физическое удержание и границы

Начальная группа допускает любой порядок и raw-разницу до 200 мс включительно. Origin един для всей
попытки; MIDI channel соответствует входному контракту 1–16. Повтор владельца/дополнительный
владелец уже удержанной высоты не создаёт атаку. Повтор мелодической высоты требует отпускания всех
её владельцев. Две разные удержанные RH высоты разрешают legato; третья даёт одну ошибку попытки.

События воспроизводятся в raw-порядке; равенство разрешает порядок доставки. Prefix up не позволяет
позднему down воскресить уже отпущенного владельца. Более старый up не снимает новую атаку. Возраст
251 мс у matching up отменяет попытку без оценки и освобождает только своего владельца.
Pause/hidden/input loss отменяют кандидата; local cancel сохраняет прочих физических владельцев.

Начальный offset фиксируется для попытки. Raw определяет совместность/ownership/gate; raw−offset
проверяет готовность RH и отпускание баса в единственной временной карте. Конец — crossing
`song.duration`, без обычного inputGrace. Просьба отпустить появляется только после достигнутого
музыкального конца и rawEnd = correctedEndPerformance + offset. Результат окончателен при полном
физическом отпускании и now > max(rawEnd, lastPhysicalRelease)+250 мс; отпускание за 1 мс до rawEnd
— ошибка.

## Проверка локальной истории

`validateHeldBassResult` возвращает отделённое JSON-доказательство целой серии либо null. Она
восстанавливает материал генератора, raw ownership, onset IDs/порядок, gates, помощь, latency и
удержание. Anchors должны быть непрерывны, скорость только 0/1; ожидание замораживается на реальном
onset, движение возобновляется лишь подтверждённым commit. Первый inactive prefix загрузки/паузы
допускается до атак; учебная попытка не может пересечь inactive clock. Прыжки/ускорения/выдуманный
конец, несовместимые поля и незавершённая серия отвергаются. Неизвестные runtime поля не
сохраняются. На попытку ограничены 256 событий ввода и 64 clock transitions/квитанции активности;
переполнение отменяет кандидата, сохраняя реальные held до отпускания.

`summarizeHeldBassResults` ограничивает двадцатью завершёнными проходами и устраняет повторы runId.
Source filter выбирает фрагменты по успешной попытке, сохраняя все их прежние ошибки/помощь. Пустые
медианы равны null. Независимым считается весь фрагмент, решённый первой попыткой без помощи;
промежуточные hits не дают педагогического результата. Метрики других курсов и P2 не меняются.

Проверки рядом с ядром используют реальные `PracticeSession`, XML DOM и фиксированные raw/clock
события. Проверены обе длины, offsets, точные 200/201 и end±1, поздние доставки, 15/60 FPS,
legato/повтор высоты/owners, полный retry, пауза, показанная помощь и поддельные сохранённые proofs.
Аппаратный MIDI/мультитач и слышимость проверяются отдельно после всех этапов по просьбе игрока.
