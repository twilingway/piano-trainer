# Геометрия художественной проекции

`src/render/stylizedProjection.ts` — чистый модуль без Three.js, DOM, таймеров и MIDI-ввода. Все
входные и выходные координаты — **CSS-пиксели** относительно canvas. DPR применяется только
рендерером, не формулой. Якоря приходят из существующей 3D-сцены; модуль не моделирует клавиатуру
заново и не сортирует ошибочно спроецированные клавиши.

## Контракт и радиус

Вход — ровно 88 якорей, MIDI 21–108 по возрастанию, с собственной шириной и высотой чёрных/белых
клавиш. `pitchToProjectionIndex(60) = 39`. Источник каждого pitch имеет постоянный ранг
`(index + 0.5) / 88`; смена песни или повтор ноты не меняет этот ранг.

Центр окружности по X — `W/2`, базовая высота — `horizonY × H`, радиус — `horizonRadius × W`.
Полуширина линии — `W × horizonSpread / 2`. Стрела прогиба:

```text
dx = x - W/2
sag = dx² / (R + sqrt(max(0, R² - dx²)))
y = horizonY × H ± sag
```

Рационализованная формула не теряет точность на больших радиусах. Знак `+` соответствует выпуклости
вверх: середина выше краёв. `horizonYAtX(layout, x)` используется также фоном.

Эффективный радиус не меньше полуширины плюс один CSS-пиксель. Дополнительный нижний предел
`R = (halfSpan² + sagBudget²) / (2 × sagBudget)` сохраняет место для плавного перехода и
вертикального прилёта. Для обратной дуги он также удерживает верхнюю границу в кадре. Если радиус
ограничен, диагностика возвращает `horizonTooCurved` и `effectiveRadius`; сохранённое
пользовательское значение не заменяется ограниченным.

## Почему дорожки не пересекаются

У всех дорожек общий экранный переход по Y:

```text
q(y) = clamp((y - joinY) / (straightenY - joinY), 0, 1)
B(y) = q² × (3 - 2q)
X_i(y) = (1 - B(y)) × H_i.x + B(y) × K_i.x
Y_i(u) = H_i.y + (K_i.y - H_i.y) × u^depthExponent
```

`joinY` ниже всех источников, `straightenY` выше всех контактов. На общем горизонтальном сечении
разность соседних X — положительная взвешенная сумма двух положительных расстояний. Поэтому дорожки
сохраняют порядок независимо от разницы высот чёрных и белых клавиш. `Y_i(u)` строго монотонна.
Нулевая производная smoothstep на обеих границах даёт C1-переход; последний участок полностью
вертикален.

Ширина тела ограничена 80% расстояния до ближайшего соседнего центра **на той же Y**, а не при
одинаковом `u`. Это удерживает ноты в своих коридорах. Масштабы у горизонта и контакта независимы;
размер чёрной клавиши приходит из сцены.

## Диагностика и стоимость

Проверяются неправильные/повторяющиеся pitch, неупорядоченные X, нечисловые контакты, выход за экран
и отсутствие места между горизонтом и посадкой. Плохой порядок не «исправляется» скрытой
перестановкой. Выход за экран отдельно диагностируется и допускает обычное clipping. Счётчик
`offscreenAnchors` учитывает сумму невидимых источников и контактов; одна дорожка может дать две
невидимые точки. Входные якоря копируются при построении: обновление переиспользуемых буферов сцены
не изменяет уже закешированную геометрию.

`countProjectionCrossings(layout, steps)` проверяет **все пары полилиний** по общей сетке Y,
дополненной `joinY`, `straightenY` и индивидуальными концами. Такая же сетка требуется при
тесселяции отображаемых лент: независимые редкие сэмплы по `u` способны срезать сильный изгиб и
создать пересечение хорд, хотя непрерывные кривые не пересекаются. `sampleProjectionLaneAtY`
предназначен для общей сетки рендера. Для каждой пары два указателя обходят реальные сегменты по
общим интервалам Y; сравниваются X на обоих концах интервала. Проверка обнаруживает пересечения при
разных `u`, в отличие от сравнения одинаковых индексов сэмплов. Полная проверка включается пятым
аргументом `buildProjectionLayout(..., true)` при диагностическом перестроении, а не на каждом
анимационном кадре. Обычная сборка использует доказанный порядок семейства. Самплирование принимает
переиспользуемый `target`; вычисление ширины не создаёт объектов.

## Автоматическая проверка

Команда: `pnpm exec vitest run src/render/stylizedProjection.test.ts`.

| Экран     | Flat Horizon               | Curved Horizon | Cinematic Sunset |
| --------- | -------------------------- | -------------- | ---------------- |
| 1920×1080 | 88 дорожек / 0 пересечений | 88 / 0         | 88 / 0           |
| 1366×768  | 88 / 0                     | 88 / 0         | 88 / 0           |
| 375×667   | 88 / 0                     | 88 / 0         | 88 / 0           |
| 390×844   | 88 / 0                     | 88 / 0         | 88 / 0           |

Дополнительно проверены крайние параметры: `horizonY=0.6`, `spread=1.5`, `radius=0.05`,
`landingStraighten=0.4`, оба направления дуги и глубина 0.5/3. Во всех четырёх сочетаниях 88 дорожек
/ 0 пересечений; заведомая перестановка контактов действительно обнаруживает пересечение.
Невозможный ракурс с контактами выше горизонта явно отклоняется.

Та же таблица 12 сочетаний дополнительно проверяется в `projectionKeyAnchors.test.ts` на настоящих
Three Camera-матрицах и 88 физических метаданных клавиатуры через `ProjectionKeyAnchors` →
`buildProjectionLayout(..., true)`: во всех случаях 88 дорожек, 0 пересечений и валидный фронтальный
ракурс. Отдельно проверяется совпадение с независимым `worldCamera.project`, pan, offset, FOV,
масштаб, движение hinge и невидимые контакты за камерой. Это интеграционная проверка
матриц/метаданных, а не приёмка GLB-изображения в браузере. Тесты также проверяют точные концы,
симметрию круга, плоский предел, безопасный малый радиус, C1, ошибочный порядок и детерминированные
голову/хвост длинной ноты. Реальные камеры, FPS и скриншоты проверяются интеграционным этапом.

## Параметры версии 1

По умолчанию: `legacy`; высота `0.17`, ширина `0.92`, радиус `2.0`, направление `up`, глубина `1.6`,
выпрямление `0.16`, ближний/дальний масштаб `1.0 / 0.12`, оба glow `1`, диагностика выключена.
Пресеты активируют `stylizedProjection`: `flat` использует радиус 10000, `curved` — 0.75, `sunset` —
1.4 и усиление нот 1.4. Прежние метрические настройки свободного мира сохраняются отдельно.
