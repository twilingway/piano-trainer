## Выполнено

Экран курса имеет выход, прогресс, меню, короткую цель, стан и одно главное действие. Полный текст,
прослушивание, скорость, язык и настройки доступны через меню. Обычная игра сохраняет свой toolbar.
До1024 CSS px показаны1–2октавы ученика; выше — сохранённый фиксированный диапазон либо88 клавиш для
«По песне». Временное отображение не сохраняется поверх предпочтений.

| Окно CSS px | Учитель        | Результат раскладки                            |
| ----------- | -------------- | ---------------------------------------------- |
| 320×568     | скрыт          | стан, клавиши и действие одновременно доступны |
| 390×844     | 144px, портрет | персонажи и стан не перекрывают управление     |
| 667×375     | скрыт          | стан целиком над кнопкой, подписи не обрезаны  |
| 768×1024    | 160px, портрет | крупная учебная октава и полная партитура      |

| 1920×1080   | скрыт          | проверены88 клавиш и сохранённые49             |

Во всех шести ready-окнах глобальный горизонтальный overflow равен0, все SVG-тексты находятся внутри
стана, главное действие ниже стана. Снимки просмотрены, метрики сохранены в
`.browser-artifacts/clay-lesson-viewport-metrics.json`; финальные кадры — `clay-lesson-final-*.png`.
Дополнительно проверен эквивалент200% раскладки:960×540CSS px,DPR2, без наложений и обрезки. Это
проверка эффективного CSS viewport, а не отдельный замер системного масштаба Windows.

## Ввод и персонажи

- В настоящем UI-показе этапа «Собираем до, ре и ми» последовательно наблюдались позы
  `mi → re → do`, затем idle. Позы используют нормализованные512×544 кадры.
- При принятом удержании до учитель показывает do; после настоящего up — idle, компаньон correct.
  При неверной ре на ожидаемую до: idle/gentle-wrong и прогресс0.
- Четыре реальных PC-нажатия с удержанием завершили первый этап: три звезды, pitch100%, hold100%.
  Отдельный pointer/touch ввод через canvas в новом ракурсе дал правильное C4 и прогресс25%.
- Пауза с25% сохранилась через1024↔1025 и390×844↔844×390 при неизменном `performance.timeOrigin`.
  Смена самого mobile-флага DevTools перезагружает документ и не выдаётся за обычный resize.
- При обычной ошибке декодирования изображения учитель исчез, а стан, старт и готовность урока
  остались рабочими. Перезагрузка восстановила рисунок.
- Реальные CSS-правила reduced-motion принудительно активированы для проверки каскада:
  `animation-name:none`, atlas `background-size:400%300%`. Системное предпочтение ОС не
  переключалось.
- Клавиатурные Enter/Escape открывают/закрывают меню с возвратом фокуса. Настройки доступны в низком
  альбоме, после закрытия фокус возвращается к меню. Новый текст проверен в RU/EN.

## Музыкальное время

Во время видимого длинного demo сохранены92 кадра: scrollLeft205→1437, X указателя
268,19995…268,20001px. Движется партитура, указатель остаётся фиксированным. Данные —
`.browser-artifacts/clay-lesson-scroll-proof.json`. Demo не засчитывается как ответ ученика.

Изображения восьмых используются отдельными компаньонами; целые, половинные, штиль и флажки
настоящей партитуры не подменены. Independent/performance не раскрывают ожидаемую высоту
компаньоном. Другие октавы, пальцы и F не получают выдуманную нажимающую позу.

## Проверки и пределы

Независимые spec- и code-review: GO. `pnpm check`:5109passed/10skipped плюс30compiler tests;
TypeScript, ESLint, Prettier и build прошли. `pnpm spec:validate`:97passed/0failed. Unit-тесты
покрывают скрытие вкладки, старые session/run/presentation, неправильный палец, неверную октаву,
release/rehold, ошибку картинки и отсутствие повторного запуска той же эмоции.

Реальный USB MIDI и субъективная слышимость аудио в этой задаче не проверялись. Незавершённый
пункт2.2 прослушивания старого `song-led-beginner-course` не закрыт. Учитель пока имеет idle и три
проверенные press-позы, а не полный плавный скелетный цикл. Исходные фотографии не публикуются;
точные промпты и производные исходники находятся рядом с manifest.
