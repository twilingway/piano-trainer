# Twiling Keys / Нотопад — план развития обучения чтению нот

Дата: 2026-10-09. Основа: публичная ветка `dev` репозитория
https://github.com/twilingway/piano-trainer, доступные `AGENTS.md`, `package.json`, скриншот
приложения. **Это предварительный аудит, не полный code review:** дерево `src/` не удалось
прочитать. Все предположения ниже проверять по коду перед реализацией.

## 1. Цель

Научить новичка видеть ноты на нотном стане и играть их на MIDI-пианино, постепенно переходя от
одной ноты к чтению незнакомых фраз двумя руками. Не путать заучивание пьесы с чтением с листа.

## 2. Уже есть — не переписывать

Согласно `AGENTS.md`: USB Web MIDI и резервный ввод клавиатурой/мышью; падающие ноты Pixi; нотный
стан OSMD; вычисление аппликатуры; ожидание правильной ноты / игра в темпе; воспроизведение другой
руки; запись попыток и сравнение с партитурой; MusicXML/MIDI; единые часы `PracticeSession`. Стек:
React, TypeScript, Redux Toolkit, PixiJS, OSMD, Tone.js, Vitest, Vite, pnpm. Проверить фактическое
состояние каждого компонента в коде.

## 3. Приоритеты

### P0 — аудит существующего функционала (без реализации)

- Прочитать `AGENTS.md`, `docs/CODE_STYLE.md`, релевантные `docs/` и `openspec/`.
- Найти существующие уроки, генераторы упражнений, хранение прогресса, статистику попыток, настройки
  отображения, MIDI-проверку и подсказки.
- Составить матрицу `реализовано / частично / отсутствует` с путями файлов и тестов.
- Не создавать новые сущности, если уже существуют эквиваленты.

### P1 — минимальный курс «Читаю пять нот»

- Отдельный педагогический режим внутри существующего UI, без копирования движка воспроизведения.
- Правая рука в позиции C4–G4 (MIDI 60–67, только C4 D4 E4 F4 G4); одна нота за раз, затем короткие
  последовательности.
- Нотный стан — основной источник информации. Скрывать названия нот, падающие подсказки и подсветку
  ожидаемой клавиши; разрешить включать их вручную.
- Не скрывать факт реального нажатия клавиши или MIDI-состояние подключения.
- Подсказки поэтапно: сначала попытка, затем название ноты, затем нужная клавиша. Задержки
  настраиваемые; в ознакомительном режиме подсказки могут быть сразу.
- Разделять правильный ответ с первой попытки и ответ после подсказки.
- Генерировать новые последовательности детерминированно по seed, избегая бесконечного повторения
  одной пьесы.

### P2 — измерение навыка и адаптация

- Для каждой попытки: `exerciseId`, `noteId`, `expectedMidi`, `playedMidi`, `firstAttemptCorrect`,
  `responseLatencyMs`, `hintLevel`, `inputSource`, время попытки.
- Не использовать одну лишь итоговую точность; отслеживать самостоятельность, скорость и ошибки по
  отдельным нотам.
- Алгоритм выбора следующего задания: чаще проблемные ноты, но сохранять разнообразие; возвращаться
  к освоенным через интервалы.
- Порог освоения — конфигурируемый и предварительный, не выдавать его за научно подтверждённый.
- Проверка переноса навыка на ранее не показанные последовательности и отсроченная проверка через
  несколько дней.

### P3 — интервальное чтение

- Повторение звука, шаг вверх/вниз, терция, затем более широкие интервалы.
- Учить узнавать контур и относительное движение, а не только названия нот.
- Разделить ошибки чтения и ошибки перемещения руки.

### P4 — ритм, басовый ключ, две руки

- Ритм отдельно от высоты: ровный пульс, четверти, половинные, паузы, затем размеры.
- Басовый ключ и фиксированная позиция левой руки.
- Сначала синхронные действия двух рук, затем удержание баса и независимые движения.
- Не начинать новичков сразу с 6/4 и двух рук, если они ещё не знают клавиатуру.

### P5 — аппликатура и настоящее чтение с листа

- Использовать существующий solver аппликатуры, не заменять его.
- Разделять рекомендованный палец и реально нажатую MIDI-ноту: стандартный MIDI не определяет палец.
- Добавить короткий предпросмотр незнакомой пьесы, выбор начальной позиции и чтение с опережением.
- Для проверки чтения с листа использовать новые пьесы, не уже разученные.

## 4. UX-режимы

| Режим          | Нотный стан | Названия         | Падающие ноты | Подсветка ожидаемых клавиш | Пальцы                        |
| -------------- | ----------- | ---------------- | ------------- | -------------------------- | ----------------------------- |
| Разучивание    | Да          | Да               | Да            | Да                         | Да                            |
| Чтение нот     | Да          | Нет по умолчанию | Нет           | По запросу                 | По уровню                     |
| Чтение с листа | Да          | Нет              | Нет           | Нет                        | Опционально на сложных местах |

Настройки не должны нарушать общий таймлайн и работу существующих компонентов. Сохранять доступность
и поддержку RU/EN.

## 5. Архитектурные ограничения

- Соблюдать `AGENTS.md`: pure core / thin shell; логика упражнений и оценки — чистый TypeScript,
  React только UI, Pixi/OSMD только визуализация.
- Единственный источник музыкального времени — `PracticeSession`; для измерения реакции на
  предъявление отдельной ноты использовать явно определённые timestamps, не заводить конкурирующие
  часы песни.
- MusicXML остаётся источником нотной партитуры, когда исходник — MusicXML. Не переизвлекать музыку
  из отображённого OSMD.
- Не менять без необходимости `src/fingering`, `src/song`, `src/recording` и их публичные контракты.
- Не публиковать материалы из `local-lessons/`.
- Локализовать все новые строки через `t()` с русским ключом и английским переводом.

## 6. Тесты и критерии приёмки P1

1. Новичок видит одну из пяти нот в скрипичном ключе, без буквенной и падающей подсказки.
2. Правильная MIDI-клавиша засчитывается, неверная не засчитывается; ввод мышью/клавиатурой
   продолжает работать.
3. При отсутствии ответа появляется последовательная подсказка; ответ после неё отмечается отдельно.
4. Можно пройти серию из 10–20 нот и увидеть ошибки по каждой ноте и долю самостоятельных ответов.
5. Повторный тест генерирует новую последовательность; один и тот же seed воспроизводит ту же
   последовательность.
6. Существующие режимы разучивания, курсор нот, метроном, запись попыток и подсчёт результатов не
   регрессируют.
7. Есть unit-тесты генератора, оценки ответа и логики подсказок; по возможности интеграционные тесты
   ввода.
8. `pnpm check` и `pnpm spec:validate` проходят; если нет — перечислить причины.
