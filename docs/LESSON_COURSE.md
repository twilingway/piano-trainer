# Первые десять уроков

Карточки курса отделены от прежних партитур. Пока содержание урока не проверено, его карточка
показывает «Скоро». Этапы рук не заменяют уровни сложности прежних упражнений.

Название урока брать из исходного каталога, например «Урок 1. Вводный». Название песни — часть
содержания, оно не заменяет название всего занятия. До проверки музыки название карточки можно
задать отдельно в `local-lessons/course.json`:

```json
{
  "lessonTitles": { "1": "Урок 1. Вводный" },
  "lessons": []
}
```

`lessonTitles` содержит названия по номерам от 1 до 10. Это только metadata: карточка остаётся
«Скоро», идентификаторы и прогресс сохраняются. Пустые и неверные значения игнорируются. После
проверки урока его собственное `title` имеет приоритет.

## Подключение проверенного урока

Музыка, кадры, видео и рабочие расшифровки остаются в игнорируемой папке `local-lessons/`. Не
добавлять их в git. После сверки нот, октав, ритма, повторов и пальцев с видео добавить урок в
`local-lessons/course.json`:

```json
{
  "lessons": [
    {
      "id": "lesson-01",
      "number": 1,
      "title": "Название проверенного урока",
      "goal": "Краткая цель упражнения",
      "reviewed": true,
      "stages": ["right", "left", "both"],
      "phrases": [
        {
          "id": "phrase-01",
          "version": "1",
          "musicXml": ".course/lesson-01/phrase-01.musicxml"
        }
      ]
    }
  ]
}
```

`number` — номер от 1 до 10. `musicXml` — относительный путь внутри `local-lessons/.course/`. Такая
вложенность не попадает в старый каталог локальных партитур. Каталог подключает только локально
найденные XML, а не произвольные внешние пути. Для урока с двумя этапами перечислить только
фактические этапы, например `right`, `both`. Без `tasks` каждый этап проходит все фразы в порядке
массива `phrases`: сначала правая, затем левая, затем обеими предусмотренными руками. Одну партитуру
можно использовать на нескольких этапах. Для написанных агентом целей и названий фраз сразу добавить
переводы в `src/i18n/courseMessages.ts`; интерфейс выводит эти тексты через `t()`.

### Порядок заданий и финал

Необязательный `title` фразы даёт упражнению собственное название. `tasks` задаёт точный порядок пар
этапа и фразы, если разные этапы требуют разных упражнений. Например, учебная разминка может быть
назначена только левой, а полное исполнение — только обеим рукам:

```json
{
  "tasks": [
    { "stage": "left", "phraseId": "warmup" },
    { "stage": "right", "phraseId": "fragment" },
    { "stage": "left", "phraseId": "fragment" },
    { "stage": "both", "phraseId": "fragment" },
    { "stage": "both", "phraseId": "whole" }
  ],
  "finalTask": { "stage": "both", "phraseId": "whole" }
}
```

Это пример метаданных без музыки: `warmup`, `fragment` и `whole` должны быть объявлены в `phrases`,
а использованные этапы — в `stages`. Каждая пара уникальна; каждая объявленная фраза и каждый этап
должны участвовать хотя бы в одном задании. Подсчёт прогресса и селектор фраз учитывают только
назначенные этому этапу задания. Координацию и полный проход не добавлять в одноручные этапы, если
видео этого не требует.

`finalTask` явно обозначает проверенную полную финальную мелодию обеими руками. Эта пара должна быть
среди заданий урока. Финал не выводится автоматически из названия, длины или положения фразы в
массиве. Полное исполнение сверяется отдельно: склейка учебных фрагментов может обрезать хвост баса
или изменить паузы и повторы. Ошибочные явно заданные `tasks` или `finalTask` оставляют карточку
«Скоро».

Идентификаторы урока и фразы остаются постоянными при переименовании. Изменение XML автоматически
меняет эффективную версию фразы. При намеренном пересмотре задания также увеличить `version`.
Прежний зачёт сохраняется в хранилище, но не относится к новой версии.

## Зачёт и сохранение

Фраза засчитывается после естественного окончания полного прохода от начала в режиме ожидания или
темпа, с хотя бы одним фактическим попаданием игрока и результатом **не меньше 75% без округления**.
Все ноты выбранной руки или рук имеют равную стоимость: 30% результата дают попадания, 70% —
физическое удержание клавиш в пределах положенной длительности каждой ноты. Знаменатель — все
оцениваемые ноты композиции, включая пропущенные. Бонус Overdrive, множитель и точность момента
нажатия не входят в этот процент; точность и ранг по времени показываются отдельно.

Позднее правильное нажатие после пропущенной атаки даёт очки за оставшееся удержание, но не
возвращает очки за попадание. Отпускание и повторное нажатие учитываются отдельными интервалами,
пропущенный промежуток не засчитывается. Педаль sustain не заменяет физическое удержание.

Пауза допустима. Перемотка, неполный диапазон, прерванный проход, прослушивание и воспроизведение
дубля не дают зачёт. Не использовать закрытие записи `onTake` как завершение задания: зачёт получает
отдельный сигнал естественного завершения упражнения.

Зачёт связан с неизменным контекстом урока, этапа, фразы и её эффективной версии, а также с
идентификатором загруженной песни. Поздний результат другого задания не принимается. Этап завершён
после всех фраз, урок — после всех предусмотренных этапов. Повтор пройденной фразы не удаляет
прогресс. Полностью пройденный урок можно начать снова. Если есть следующее задание, после зачёта
любой фразы доступна кнопка «Следующее задание»; она выбирает его и не запускает автоматически.

Следующий подготовленный урок открывается после актуального зачёта `finalTask` всех предыдущих
номеров. Отдельные фразы, одноручный финал и прослушивание не открывают следующий урок. Открытие
следующего урока и завершение всех этапов текущего — разные показатели: карточка показывает число
зачтённых фраз каждой руки, этапов и общий прогресс завершённых уроков. Без `finalTask` урок
сохраняет задания, но не открывает следующую карточку.

На локальном Vite dev-сервере (`pnpm dev`, `http://localhost:5190/`) все подготовленные уроки
открыты для проверки без предыдущих зачётов. Карточки, команды открытия, смена рук и восстановление
после перезагрузки используют один режим свободного доступа. Это не добавляет отметок прохождения:
зачёт по-прежнему требует полного прохода с результатом не ниже 75%. Непроверенные или отсутствующие
материалы остаются «Скоро». Production-сборка сохраняет последовательное открытие; режим dev не
является настройкой игрока и не сохраняется в браузере.

Ключ зачёта включает политику `note-result-30-70-v1`. Прежние отметки, полученные до перехода на
30/70 и порог 75%, остаются в хранилище, но не считаются актуальными: их нужно получить заново.
Изменение версии или XML финала также требует нового зачёта для открытия следующего урока, не удаляя
сохранённые отметки.

Redux хранит прогресс, последнюю учебную позицию, вид и сопровождение курса. Сохранение выполняет
отдельный listener по ключу `lesson-course-v1`; загрузка не записывает defaults. Последняя позиция
восстанавливается только при доступной локальной фразе, а прежние зачёты сохраняются и при временном
отсутствии материалов. Ошибки чтения и записи видны через общий механизм ошибок хранилища; при сбое
записи текущий прогресс остаётся в памяти.

## Вид и сопровождение

Пианинные табы и нотный стан независимо включаются в основном меню «Вид» и могут отображаться
одновременно. Сверху остаётся тот вид, который включили первым; следующий появляется ниже. Выбор и
порядок сохраняются между запусками. Для нового курса исходный вид — табы. Два вида делят
ограниченную по высоте область, оставляя место падающим нотам и клавиатуре.

Табы показывают исходные ноты песни и заданные пальцы, время берут из `PracticeSession` и не
запускают свои часы. MusicXML остаётся источником высот, ритма, октав и письменной аппликатуры.
Сопровождение курса по умолчанию выключено. Оно сохраняется отдельно от глобальных настроек рук и
сопровождения обычных песен.
