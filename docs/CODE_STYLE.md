# Стиль кода Piano Trainer

Правила раскладки и роста кода. `AGENTS.md` описывает рабочие соглашения, `CLAUDE.md` — команды и
архитектуру; этот файл отвечает на вопрос «куда положить новый код, чтобы через месяц не
перекладывать». Правила перенесены из towerdefander (`docs/CODE_STYLE.md`) после того, как здесь
`App.tsx` вырос до полутора тысяч строк, а `FallingNotesView.ts` — почти до тысячи.

## Где живёт файл

Раскладка по владению, а не по слоям:

```text
src/
  App.tsx        композиция: хуки состояния и разметка оболочки, ничего больше
  app/           состояние игрока без разметки: хуки (трейнер, библиотека, вид, дубли)
  ui/            компоненты оболочки: верхняя полоса, окна, вкладки настроек, разбор
  render/        вид Pixi: ноты, клавиатура, дорога, руки, эффекты; чистые расчёты рядом
  staff/         нотный стан OSMD
  practice/      сессия и трейнер (чистая логика и кадровый цикл)
  song/          модель песни, чтение MusicXML и MIDI, проходы по партитуре
  recording/     дубли, сравнение, запись в ноты
  library/       песни игрока и папка
```

Компонент лежит там, где его единственный потребитель; в `ui/` он поднимается, когда появляется
второй. Копировать вместо подъёма нельзя.

## Размер модуля

`App.tsx` — только композиция: вызовы хуков из `app/` и разметка оболочки из `ui/`. Никаких расчётов
и больших JSX-веток.

Потолок production `.ts`/`.tsx` — 500 строк; его держит ESLint (`max-lines`, без пустых строк и
комментариев). Файл крупнее режется. Исключение возможно только с комментарием в шапке, почему
делить хуже, и отключением правила в этом файле. Тесты под потолок не попадают.

Ветка `if`/`switch`, которая растёт вместе с каталогом данных, — сигнал резать по таблице, а не
удлинять файл.

## Данные в UI

Компонент из `ui/` принимает чистые пропсы и не знает ни про трейнер, ни про хранилища. Подключение
к данным живёт в хуках `app/useX.ts` и вызывается в `App.tsx`. Стора нет: состояние живёт в хуках
рядом с тем, кто им пользуется.

## Что рисует картинку

`Graphics` — инструмент рисования, а не объект сцены: Pixi триангулирует его на каждом кадре, где он
виден. Фигура постоянной формы **запекается один раз** в текстуру (клавиши, карточки нот, свечение,
наклейки) и на сцене живёт спрайтом, меняя только положение, размер, тон и прозрачность. `Graphics`
остаётся там, где геометрия честно новая каждый кадр (линия удара, контурные руки).

Кадровый цикл не выделяет память без нужды: без массивов и объектов на каждую ноту в каждом кадре,
без пересчёта того, что не изменилось.

## Расширение вместо правки

Новый вариант добавляется записью в таблицу, а не веткой (`EXERCISES`, `FINGER_COLOR`, позы рук).
Реестр вводится на втором независимом варианте, не раньше: три похожие строки лучше преждевременной
абстракции.

## Тесты

Тест лежит рядом с исходником: `foo.ts` и `foo.test.ts` в одной папке. Вычисления живут в чистых
функциях, чтобы их можно было проверить без Pixi, React и таймеров.

## Стили

Обычный CSS, один `src/styles.css`. Токены цвета, шрифтов и движения — в `:root`. Без CSS-in-JS и
UI-фреймворков.

## Язык и именование

Идентификаторы и комментарии английские. Строки интерфейса и артефакты OpenSpec — русские.

## Проверка

Полный гейт — `pnpm check`; для изменений поведения дополнительно `pnpm spec:validate`. На ревью
глазами проверяется то, что не ловит линтер: файл лежит на своём месте, `App.tsx` не набрал логики,
новый вариант добавлен записью в таблицу.
