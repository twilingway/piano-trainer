# Видео → ноты и наблюдения рук

Эти команды готовят локальный пакет для Claude Code: ноты, точки кистей, временную шкалу и
контрольные кадры. Blender, риг тела, ретаргетинг и приложение они не меняют. Существующие
`lesson-video:prepare` и `lesson-video:frames` продолжают работать отдельно.

## Подготовка

Нужны Node.js проекта, FFmpeg/ffprobe в PATH, Python 3.11, NVIDIA CUDA GPU и, на Windows, MSVC Build
Tools для сборки `ncls`. Если Python 3.11 отсутствует, его можно получить через uv в локальный
каталог артефактов, не меняя системный Python. Передайте путь к его `python.exe`:

```powershell
pnpm lesson-video:setup-capture --python "C:\Python311\python.exe"
```

Зависимости закреплены в `tools/video-capture/requirements.txt`. Среда, кэш и модель MediaPipe
создаются в `.browser-artifacts/video-capture/`. Музыкальная модель поставляется с Transkun. Модель
рук проверяется по SHA-256. Установка требует сети, обработка медиа выполняется локально.
Существующая ASR-среда не затрагивается. При отсутствии CUDA музыка завершается с диагностикой;
автоматического перехода на CPU нет. MediaPipe обрабатывает кадры на CPU.

## Получение исходника

```powershell
pnpm lesson-video:download --id seven-nation-army --url "https://www.youtube.com/watch?v=iSu-MrCm-lA"
# Либо локальный файл:
pnpm lesson-video:download --id local-01 --video "G:\Урок\исполнение.mp4"
```

Команда получает один ролик в лучшем доступном качестве, без перекодирования изображения; извлекает
PCM-аудио с сохранением частоты и каналов. URL очищается от дополнительных параметров. Логин,
cookies и обход ограничений не выполняются. Ошибка YouTube не создаёт успешный source; при
необходимости используйте доступный локальный файл с новым id.

Результаты лежат в `local-lessons/.analysis/<id>/capture/`: `input.*`, `audio.wav`, `source.json`. В
source сохранены SHA-256, версии инструментов, потоки и полный индекс кадров с исходными PTS.
Совместимый повтор использует готовый результат после проверки контрольных сумм. Изменение
источника, параметров или незавершённый этап требует нового id; исходные файлы не затираются.

## Музыка и руки

```powershell
pnpm lesson-video:music --id seven-nation-army
pnpm lesson-video:hands --id seven-nation-army --calibration "G:\analysis\calibration.json"
# Для отдельного пилотного id можно ограничить руки:
pnpm lesson-video:hands --id pilot-01 --start 0 --end 20
```

`music.raw.json` содержит кандидаты Transkun: pitch, onset, offset и velocity. Offset модели не
доказывает физического отпускания клавиши. Педаль и звучание после отпускания проверяются отдельно.
Распознавание речи не используется для получения нот.

`hands.raw.jsonl` содержит по записи на декодированный кадр выбранного диапазона, включая пустые
детекции. Сохраняются `frameIndex`, целочисленный `pts` строкой, `timeBase` и `time = PTS*timeBase`.
При VFR время не вычисляется через FPS. Ненулевые начала видео и аудио не теряются: для сравнения
времени от нуля вычитайте одно общее начало; не обнуляйте потоки независимо.

Точки `landmarks` относятся к полному исходному изображению даже при ROI. X направлен вправо, Y
вниз; z — относительная оценка глубины от запястья. `worldLandmarks` — предсказанная форма кисти в
метрах с центром в кисти, а не мировое положение руки над пианино. Глубина и закрытые суставы не
измерены. Модель не предоставляет достоверность каждой точки: значение не выдумывается.

Порядок суставов: 0 — запястье; 1–4 — большой палец; 5–8 — указательный; 9–12 — средний; 13–16 —
безымянный; 17–20 — мизинец. Кончики: 4, 8, 12, 16, 20. `trackId` меняется после
потери/неоднозначности связи. Diagnostics сообщает разрывы и смены предсказанной стороны; скрытой
интерполяции нет. Анатомическая сторона остаётся `null` до ручной сверки; `predictedSide` сохраняет
исходную оценку модели отдельно.

Наложения суставов для контрольных кадров находятся в `overlays/`, статистика — в
`hands.summary.json`. Для контакта с клавишей нужна визуальная сверка, близости кончика
недостаточно.

## Калибровка клавиатуры

JSON задаётся относительно полного исходного кадра, координаты нормализованы от 0 до 1. SHA-256
берётся из `source.video.sha256`. Полигон каждой видимой клавиши задаёт именно её область; не
включайте видимую поверхность чёрной клавиши одновременно в полигон белой. Для видео с падающими
нотами ROI позволяет оставить модели только реальную клавиатуру и руки.

```json
{
  "schemaVersion": 1,
  "sourceSha256": "SHA256_VIDEO",
  "mirrored": false,
  "roi": { "x": 0, "y": 0.45, "width": 1, "height": 0.55 },
  "keys": [
    {
      "pitch": 60,
      "polygon": [
        { "x": 0.45, "y": 0.5 },
        { "x": 0.47, "y": 0.5 },
        { "x": 0.47, "y": 0.7 },
        { "x": 0.45, "y": 0.7 }
      ]
    }
  ]
}
```

Это пример структуры, не калибровка Seven Nation Army. Значения требуют сверки на исходном кадре.
Без калибровки выдаются сырые наблюдения; достоверные клавиши/пальцы не назначаются. Калибровка не
определяет мировой масштаб и перспективу скрытых суставов.

## Сверка и передача

```powershell
pnpm lesson-video:export --id seven-nation-army
pnpm lesson-video:export --id seven-nation-army --review "G:\analysis\review.json" --bundle reviewed-01
```

По умолчанию создаётся новый `bundle/`. Повторный экспорт требует нового имени, чтобы сохранить
предыдущую передачу. Manifest публикуется последним; каталог без manifest — неполный экспорт. В
пакете: source, raw-предсказания, notes JSON/MIDI, доступная калибровка, review, evidence и
`HANDOFF.md` с соглашениями для Claude. Сами видео и модели не дублируются; путь исходника доступен
через каталог capture. Checksums перечислены в manifest без самоссылки.

Для каждой атаки экспортируются ближайшие кадры до, во время и после неё. `evidence/index.json`
связывает JPG с PTS и идентификаторами `frame-<frameIndex>`. Ноты, пальцы и геометрия имеют
независимые статусы `missing/draft/reviewed`; полный проход модели не даёт reviewed автоматически.

Пример review (id и ссылки замените данными реального пакета):

```json
{
  "schemaVersion": 1,
  "sourceSha256": "SHA256_VIDEO",
  "inputs": { "music": "SHA256_MUSIC_RAW_JSON", "hands": "SHA256_HANDS_RAW_JSONL" },
  "notes": [
    {
      "eventId": "note-000001",
      "hand": "right",
      "teacherFinger": 2,
      "reviewNotes": true,
      "reviewFinger": true,
      "evidence": ["frame-12", "frame-14", "frame-16"],
      "reason": "Клавиша и палец видны на атаке и соседних кадрах."
    }
  ],
  "hands": { "reviewedRanges": [], "issues": ["Суставы закрыты рукой"] }
}
```

Допустимые исправления нот: pitch, onset, keyRelease, hand, teacherFinger, writtenFinger,
computedFinger. Неизвестные значения — null. Расчётный палец не является наблюдением учителя. Raw
остаётся неизменным; исправленные события выдаются в notes.json. Неизвестное keyRelease не
заполняется наблюдением автоматически: MIDI использует estimatedOffset с явной политикой экспорта.

`notes.json.midiHandPolicy` равен `complete-hands`, только если рука известна для каждой ноты: тогда
MIDI содержит отдельные дорожки `left`/`right` для присутствующих рук. При любой неизвестной руке
политика — `unassigned`: все ноты идут в одну дорожку, а частичные назначения сохраняются в JSON.
Так отдельная проверенная нота не превращает остальные события в ложную партию. Это не
восстановление исходных рук: импорт одной дорожки в тренажёр использует обычное разделение по
высоте. При нескольких дорожках импортёр также определяет руки эвристически и игнорирует их имена;
для точной аппликатуры и партий нужен полностью проверенный JSON.

Подтверждение пальца требует руки, teacherFinger, основания и evidence. Проверенные диапазоны рук
задаются start/end и evidence; непроверенные интервалы и issues сохраняют draft. По одному ракурсу
точная трёхмерная постановка не гарантируется.

`inputs` берётся из receipt соответствующих этапов (поле `files`); для отсутствующего этапа — null.
Это защищает от переноса исправлений на другой проход того же видео с иными нотами. Повтор анализа
также проверяет версии пакетов, веса, конфигурацию модели и SHA-256 адаптера.

В git входят только инструменты, тесты и документация. Видео, музыка, точки, кадры, модели и пакеты
передачи остаются в игнорируемых каталогах, не импортируются в приложение или production.
