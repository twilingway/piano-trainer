## Context

Генератор (`src/wordTyping/optimizer.ts`) ведёт beam search по позициям нот; состояние несёт mapping
«InputToken → высота» на всю песню, `prune` убирает дубли по mapping. Словесный ввод
(`src/input/computerKeyboard.ts`) превращает нажатие в высоту по статической таблице `tokenToPitch`.
Вид клавиатуры ПК (`src/render/computerKeys.ts`) рисует клавишу каждой ноты по её токену, но нажатие
мышью и подсветку нажатой клавиши считает по высотам токенов всей песни — то есть по постоянному
mapping. Мотивация — proposal.md, «Why».

## Goals / Non-Goals

Цели дизайна: один генератор для обеих раскладок, ввод по слову — чистая функция, тестируемая без
DOM; нотный стан не меняется, кадр Pixi получает только id ожидаемой ноты.

Не цели: перенос перегенерации в Trainer, сохранение номера варианта, тонкая настройка длины слов из
UI.

## Decisions

### Раскладка — параметр поиска, а не второй генератор

`generateWordTyping` получает шестой аргумент `{ layout?: "song" | "word"; variant?: number }`. В
раскладке «word» каждое новое состояние начинает слово с пустым mapping; проверка «осталось
достаточно свободных клавиш для всех высот песни» не нужна и отключается вместе с копией mapping на
каждое слово. Ключ `prune` для «word» — ранги двух последних блоков (mapping у всех состояний пуст,
пары зависят от предыдущего слова, штраф повторов — от недавних; по одному последнему слову
сливались бы, например, все состояния, оканчивающиеся fallback); для «song» — mapping, как прежде.
Fallback в «word» всегда занимает `F` / `А`: mapping не переживает слово, поэтому первая свободная
клавиша каскада (`Q` / `Й`, мизинец верхнего ряда) досталась бы каждому fallback.

Слова, подходящие к позиции, в «word» не зависят от состояния и ищутся один раз; на состояние идут
лучшие `maxCandidatesPerState × 8` из них. Бонус пары может поднять слово из-за этой границы,
поэтому часть связных пар теряется ради скорости; границы ×16 и ×32 на гимне не дали ничего и стоили
до 1.7 раза больше времени. `WordTypingResult.mode` становится `"strict" | "word"`; в «word»
`tokenToPitch` и `pitchToTokens` пусты, высота каждого токена — в `tokens`. Альтернатива — отдельный
DP-модуль для «word»: дублирует оценку слов, пар и fallback, отвергнута.

### Вариант — детерминированный шум в оценке слова

Вариант 0 — нынешний результат. Для варианта `v > 0` к оценке слова добавляется
`variantNoise × длина × u(v, rank)`, где `u` — хэш (mulberry-подобный) пары чисел в `[0, 1)`. Шум
зависит от слова, а не от позиции, поэтому вариант стабилен и меняет выбор слов целиком.
Альтернатива — исключать слова прошлых вариантов: требует истории вариантов в хуке и раздувает ключ
кеша.

### Повторы — штраф по недавнему пути

Кандидат, чьё слово уже встречается среди последних 16 блоков пути состояния (слов и fallback),
получает `repeatPenalty × длина`. Проход по связному списку состояний ограничен 16 шагами, без
копирования множеств на каждое состояние: счёт по блокам, а не по разным словам, чтобы повторы и
хвосты fallback не уводили проход к началу пути.

### Ввод по слову — чистая функция и функция в опциях клавиатуры

Новый `src/wordTyping/wordInput.ts`: `wordKeyPitch(tokens, owedNoteId, tokenId, pool)` находит
текущее слово (слово токена ожидаемой ноты, иначе последнее), возвращает высоту токена этого слова с
тем же `tokenId`, иначе — для клавиши из `pool` фальшивую ноту: ближайшую к `owed` высоту
(`owed − 1`, `owed + 1`, `owed − 2`, …), которой нет у токенов в пределах секунды от ожидаемой ноты,
иначе `undefined`. Секунда шире любого окна попадания (≤ 0.3 с при скорости ≤ 1), поэтому фальшивая
нота не может засчитаться попаданием по соседней ожидающей ноте в темпе.
`KeyboardInputOptions.wordMapping` заменяется на `wordPitch(tokenId)`: для «song» это поиск по
`tokenToPitch`, для «word» — `wordKeyPitch` с ожидаемой нотой от Trainer. Ожидаемую ноту определяет
`PracticeSession.owedNote()`: в ожидании — первая из `nextDue()`, в темпе — ближайшая ко времени
песни из ещё не сыгранных, иначе пропущенная нота держала бы прежнее слово ещё на окно опоздания.
Trainer читает её через `nextDueNoteId()` и кладёт в кадр как `owedNoteId`; владельцем времени и
статуса нот остаётся PracticeSession. Высота считается в момент нажатия, поэтому отпускание по
`WordKeyboardState` снимает именно сыгранную высоту.

### Вид клавиатуры в «word»

`ComputerKeyboard` несёт ту же `wordPitch`, `ComputerKeys` берёт ожидаемую ноту из кадра. Нажатие
мышью играет `wordPitch` для токена ожидаемой ноты на этой клавише, иначе для клавиши без
модификатора. Удержанная клавиша запоминает сыгранную высоту (слой клавиатуры передаёт токен
нажатия), и подсветка с оценкой ищут клавишу по ней, а не по высотам токенов всей песни — так
фальшивая нота светится на нажатой клавише, а не на чужой клавише той же высоты.

### Перегенерация в хуке

`useWordTyping` хранит номер варианта вместе с базовым ключом (линия, партия, язык, раскладка); при
смене базы вариант равен 0. Вариант и раскладка входят в ключ кеша и в запрос к воркеру. Совпадение
текста нового варианта с прежним показывается сообщением в строке режима. Раскладка хранится в
`word-typing-prefs-v1` полем `layout`; отсутствующее поле читается как `"word"`.

## Risks / Trade-offs

- [В «word» ключ `prune` по последнему слову оставляет меньше разнообразия путей] → beam 48 по
  разным предыдущим словам; benchmark сравнивает длину и долю связных пар.
- [Время генерации растёт с длиной слов: обход trie глубже] → прототип: ~0.45 с на 10 000 слов
  (beam 64) в воркере; benchmark показывает мс.
- [Фальшивая нота совпадает с высотой соседней ожидающей ноты в темпе] → фальшивая высота обходит
  высоты нот в пределах секунды.
- [Кадр Pixi] → функция ввода вызывается по нажатию, не в кадре; в кадре только `owedNoteId`.
- [Высота удержанной клавиши в виде считается по ожидаемой ноте прошлого кадра, ввод — по текущей] →
  расхождение не больше кадра на границе слов.
- [Порядок архивации] → `word-typing-fingers` архивируется первым, MODIFIED-текст написан поверх его
  редакции.

## Migration Plan

Настройки читаются с новым полем по умолчанию; кеш генерации живёт в памяти и сбрасывается
перезагрузкой; `ALGORITHM_VERSION` повышается до `word-typing-v4`. Откат — revert ветки.
