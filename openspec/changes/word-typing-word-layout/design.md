## Context

Генератор (`src/wordTyping/optimizer.ts`) ведёт beam search по позициям нот; состояние несёт
mapping «InputToken → высота» на всю песню, `prune` убирает дубли по mapping. Словесный ввод
(`src/input/computerKeyboard.ts`) превращает нажатие в высоту по статической таблице
`tokenToPitch`. Вид клавиатуры ПК (`src/render/computerKeys.ts`) уже рисует клавишу каждой ноты по
её токену и от постоянного mapping не зависит. Мотивация — proposal.md, «Why».

## Goals / Non-Goals

Цели дизайна: один генератор для обеих раскладок, ввод по слову — чистая функция, тестируемая без
DOM; кадр Pixi и нотный стан не меняются.

Не цели: перенос перегенерации в Trainer, сохранение номера варианта, тонкая настройка длины слов
из UI.

## Decisions

### Раскладка — параметр поиска, а не второй генератор

`generateWordTyping` получает шестой аргумент `{ layout?: "song" | "word"; variant?: number }`. В
раскладке «word» каждое новое состояние начинает слово с пустым mapping; проверка «осталось
достаточно свободных клавиш для всех высот песни» не нужна и отключается. Ключ `prune` для «word» —
ранг последнего слова (mapping у всех состояний пуст, а пары слов зависят от предыдущего слова); для
«song» — mapping, как прежде. `WordTypingResult.mode` становится `"strict" | "word"`; в «word»
`tokenToPitch` и `pitchToTokens` пусты, высота каждого токена — в `tokens`. Альтернатива — отдельный
DP-модуль для «word»: дублирует оценку слов, пар и fallback, отвергнута.

### Вариант — детерминированный шум в оценке слова

Вариант 0 — нынешний результат. Для варианта `v > 0` к оценке слова добавляется
`variantNoise × длина × u(v, rank)`, где `u` — хэш (mulberry-подобный) пары чисел в `[0, 1)`.
Шум зависит от слова, а не от позиции, поэтому вариант стабилен и меняет выбор слов целиком.
Альтернатива — исключать слова прошлых вариантов: требует истории вариантов в хуке и раздувает ключ
кеша.

### Повторы — штраф по недавнему пути

Кандидат, чьё слово уже встречается среди последних 16 слов пути состояния, получает
`repeatPenalty × длина`. Проход по связному списку состояний ограничен, без копирования множеств на
каждое состояние.

### Ввод по слову — чистая функция и функция в опциях клавиатуры

Новый `src/wordTyping/wordInput.ts`: `wordKeyPitch(tokens, owedNoteId, tokenId, pool)` находит
текущее слово (слово токена ожидаемой ноты, иначе последнее), возвращает высоту токена этого слова
с тем же `tokenId`, иначе — для клавиши из `pool` фальшивую ноту `owed − 1` (`+ 1` у нуля), иначе
`undefined`. `KeyboardInputOptions.wordMapping` заменяется на `wordPitch(tokenId)`: для «song» это
поиск по `tokenToPitch`, для «word» — `wordKeyPitch` с ожидаемой нотой от Trainer. Trainer
получает только чтение `nextDueNoteId()` (первая нота `session.nextDue()`); владельцем времени и
статуса нот остаётся PracticeSession. Высота считается в момент нажатия, поэтому отпускание по
`WordKeyboardState` снимает именно сыгранную высоту.

### Перегенерация в хуке

`useWordTyping` хранит номер варианта вместе с базовым ключом (линия, партия, язык, раскладка); при
смене базы вариант равен 0. Вариант и раскладка входят в ключ кеша и в запрос к воркеру. Совпадение
текста нового варианта с прежним показывается сообщением в строке режима. Раскладка хранится в
`word-typing-prefs-v1` полем `layout`; отсутствующее поле читается как `"word"`.

## Risks / Trade-offs

- [В «word» ключ `prune` по последнему слову оставляет меньше разнообразия путей] → beam 48 по
  разным предыдущим словам; benchmark сравнивает длину и долю связных пар.
- [Время генерации растёт с длиной слов: обход trie глубже] → прототип: ~0.45 с на 10 000 слов
  (beam 64) в воркере; benchmark показывает мс.
- [Фальшивая нота совпадает с другой ожидаемой высотой аккорда] → линия монофоническая
  (`extractLine`), аккордов в ожидании нет.
- [Кадр Pixi] → функция ввода вызывается по нажатию, не в кадре; вид не меняется.
- [Порядок архивации] → `word-typing-fingers` архивируется первым, MODIFIED-текст написан поверх
  его редакции.

## Migration Plan

Настройки читаются с новым полем по умолчанию; кеш генерации живёт в памяти и сбрасывается
перезагрузкой; `ALGORITHM_VERSION` повышается до `word-typing-v4`. Откат — revert ветки.
