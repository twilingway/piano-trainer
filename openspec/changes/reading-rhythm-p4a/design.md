# Design

## Context

База — dev 7fb4e45 после #153. P2/P3 используют reading repository и schema 3. TrainerReadingPolicy
требует waiting, useTrainer(reading) включает wait и выключает метроном. Это не точка подключения
ритма. Обычный tempo игнорирует часть лишних атак и может поглощать повтор внутри половинной через
recoverActive; статистика обычной игры не подходит.

Практика уже имеет songTimeAt/performanceTimeAt, tick/pauseClock и delivery grace. SessionAudio
планирует метроном относительно этих часов. Текущий LEAD_IN_S равен двум секундам, поэтому полный
такт отсчёта надо добавить как явную опцию PracticeSession.

## Goals / Non-Goals

Техническая цель — переиспользовать один clock, аудиопланировщик, калибровку и ввод, добавив чистую
оценку всех ритмических атак. Границы продукта — proposal.md. Звуковой scheduler не двигает время.

## Decisions

### Генератор и источник

src/rhythm хранит типы, генератор XML, временной эталон, оценщик и сводки. Четыре шаблона тактов: Q
Q Q Q; H Q R; Q H R; Q R Q R. Seed переставляет только эти четыре целых такта с сохранением квот.
Каждый шаблон занимает четыре доли и начинается нотой. XML — исходный источник; parser создаёт Song.
Паузы извлекаются чистым проходом XML, хвостовая пауза включается в score duration. Новизна при
смене seed не обещается. Половинная оценивается только по onset.

### Часы, отсчёт и завершение

Фиксированный профиль P4a: tempo, speed 1, правая рука, accompaniment false, noteResult false,
normal ±150 мс; метроном включён. Профиль не перезаписывает пользовательские настройки песни.
Практика получает countInBeats=4; отсутствие опции сохраняет прежние две секунды обычной игры.
SongTimeline покрывает отсчёт и упражнение; никакой UI countdown не продвигает время.

Финальный тихий участок в той же PracticeSession длится 250 мс плюс положительная эффективная
компенсация ввода. Он нужен для доставки событий, не расширяет четыре учебных такта. Оценщик
принимает музыкальные времена только от −150 мс до score end, а пропуски финализирует после late
boundary + delivery grace. Метроном/стан заканчивают учебную часть на score end; завершённый
результат появляется после тихого участка. Не сокращать tail по последней ноте.

### Отдельный observer и чистая оценка

В Trainer нужен небольшой P4 observer кадров/ввода/завершения, отдельный от reading policy. Он
получает every fresh down, raw/corrected/performance receipt, source/device, songTimeAt(corrected) и
identity текущего прохода. Если событие старше 250 мс по raw receipt, из paused/чужого run либо до
старта подготовки, оно отбрасывается. Компенсация не превращает недопустимое raw в допустимое.
Snapshot offsets фиксируется на старте и совпадает с применением Trainer.

RhythmSession сопоставляет с ближайшим pending onset внутри окна, затем классифицирует unmatched как
extra/rest-extra. Для hit хранит знак и величину. Miss до закрытия grace не финализируется. Игровые
grades/score/recoverActive не источник этих метрик; observer видит и атаки без PracticeEvent. Общая
статистика обычных песен не меняется.

### Ввод и границы курса

Серия заранее объявляет источник, чтобы у misses был определённый источник. MIDI сохраняет реальный
pitch, но нормализует его в единый C4 для ритмического тренажёра. Space и экранный Tap также создают
C4. Down/up gate различает исходные устройство/канал/клавишу до remap; release всегда снимает held.
Две разные ноты аккорда дают две атаки, не один collapsed C4. Педаль игнорируется. Space в P4
отключает обычные sustain/play shortcuts; при focused Tap его Enter/Space keydown создаёт один удар
keyboard. В pointer-серии такая клавиатурная активация не оценивается, как любой чужой способ.
Формы/кнопки паузы не перехватываются как Tap. В keyboard-серии пробел вне форм либо native
Enter/Space на Tap создаёт один keyboard удар; pointer-серия принимает pointerdown на этой кнопке.
MIDI-серия принимает выбранное MIDI-устройство. Raw pointer timestamp берётся из исходного
PointerEvent.timeStamp, keyboard — из KeyboardEvent.timeStamp на keydown; delivery time хранится
отдельно. Последующие click/keyup подавляются для оценки; авто-repeat не создаёт новую атаку.

### Прерывание и готовность

Явная пауза/hidden/окно/смена конфигурации/потеря AudioContext прекращают проход без результата.
Сначала остановить PracticeSession и отменить аудиоработы, затем инвалидировать identity. Повтор
после прерывания ручной, тот же seed и новый runId, полный отсчёт; это простой контракт первого
среза вместо оценки атак на границе resume. Обычная практика сохраняет свои прежние правила.

Метроном требует отдельной готовности click audio; ensureSound Promise<void> не доказательство.
Готовность стана принимается по receipt-time после painted frame с identity guard, как исправлено в
#153. При отсутствии звука/стана никакой timeline не стартует и пропуски не копятся.

### Сохранение и UI

Расширить прежний reading state/repository/listener до schema 4, activeCourse += rhythm-training.
Root P2, intervals и rhythm атомарно сливаются; результат идемпотентен по runId. История P4a — 20
суммарно, не по каждой комбинации. Сводки разделены по BPM/source/rules/offset snapshot. Тонкие
hooks владеют ресурсами; App остаётся композицией. Все строки сразу RU/EN. Стан рендерится один раз
на серию, кадр обновляет cursor/snapshot только при изменении состояния.

## Risks / Trade-offs

- Нет датчика пальца/слышимости физического выхода → не заявлять их измерение.
- Положительные offsets/поздняя доставка → тесты окна и grace на 15/60 FPS.
- Ошибки паузы возле следующей ноты → сначала matching, затем rest classification.
- Прерывание уничтожает незавершённые ответы → явное сообщение о повторе без результата.
- Старые вкладки и поздний hydrate → схема 4 блокирует старую запись, sibling merge сохраняет курс.
- Стан/RAF → тесты переходов времени и visible browser, включая подтверждение старым frame
  timestamp.

## Migration Plan

Только согласованный schema 4 расширяет прежний ключ reading-course-v2 в базе piano-trainer.
v1/v2/v3 мигрируют последовательно; legacy backup не трогается. При rollback прежнее приложение
увидит будущую схему, покажет ошибку сохранения и не должно перезаписать её. Новый сервис не нужен.
