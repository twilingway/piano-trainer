## Context

B1 дал `openMidiOutput` (`src/input/midiOutput.ts`): выбор порта, паника при смене и уходе со
страницы, проверочная нота. Контроллер живёт в `useMidiOutput`, который вызывается из `useKeyInput`;
наружу отправка не открыта. `Trainer` (`src/practice/Trainer.ts`) каждый кадр двигает
`PracticeSession` и рисует вид; `session.keyHints()` — ноты в окне 0,3 с песни × скорость (300 мс
реального времени), которые вид подсвечивает на экранной клавиатуре. `parseMidiMessage` отбрасывает
канал. `App.tsx` — 497 строк из 500 по `max-lines`. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:** что горит, решает чистая функция над сессией; отправка и фильтр эха — отдельный объект
без `MIDIAccess`, проверяемый подставной отправкой; в кадре нет лишних сообщений.

**Non-Goals:** протоколы конкретных моделей, звучащие ноты на выходе, общий `MIDIAccess`.

## Decisions

### D1. Что горит — чистая функция в практике

`src/practice/keyLights.ts`: `keyLightPitches(session, active): number[]` — пустой массив, если
`active` ложно; иначе высоты без повторов из `keyHints()` в обоих режимах. Подсветка совпадает с
экранной клавиатурой: `keyHints` уже берёт только ноты игрока (чужая рука и ноты вне клавиатуры
игрока не горят), окно в 300 мс не дублируется, а в режиме ожидания стоящая песня держит ноту в
окне, пока её не нажмут. `nextDue()` отвергнут: он зажигал следующий аккорд сразу после попадания,
когда нажатие по нему ещё не засчитывается.

### D2. Trainer сообщает, не отправляет

`Trainer.onLights: ((pitches: readonly number[]) => void) | undefined`, как `onSnapshot`. `frame()`
после `tick` вызывает его с `keyLightPitches(session, this.playing && !this.performanceMode)`;
`silence()` (её зовут загрузка, перемотка, пауза, конец песни и повтор участка) вызывает его с
пустым массивом. После `silence()` следующий кадр зажигает нужное заново: так перемотка и повтор
гасят клавиши и зажигают по новому положению. `destroy()` проходит через `setPlaying(false)` →
`silence()`. Практика не знает про MIDI: `src/practice` остаётся без импортов из `src/input`.

### D3. Отправка и эхо — `src/input/keyLights.ts`

`createKeyLights(send, now = () => performance.now())` возвращает
`{ show(pitches), configure(settings), forget(), isEcho(event) }`:

- `show` сравнивает нужные высоты с горящими и шлёт только разницу: `[0x80 | ch, p, 0]` для
  погасших, затем `[0x90 | ch, p, velocity]` для новых (`ch` = канал − 1). Выключенная подсветка —
  ничего не шлёт. Каждой отправке ставится отметка `now()` по высоте и направлению.
- `configure` при смене включения, канала или громкости гасит горящие на прежнем канале; следующий
  `show` зажигает их с новыми настройками.
- `forget` забывает горящие без отправки: им пользуется смена порта (прежний уже получил панику), и
  следующий кадр зажигает их на новом.
- `isEcho({ type, pitch, channel, timestamp })` — истина, если подсветка включена и либо `channel`
  равен каналу подсветки, либо для той же высоты и того же направления (`down` ↔ Note On, `up` ↔
  Note Off) была отправка, отстоящая от `timestamp` не больше чем на 30 мс, а у нажатия ещё и
  громкость равна громкости подсветки. Отметки входа (`MIDIMessageEvent.timeStamp`) и
  `performance.now()` — одна шкала.

Окно 30 мс и громкость вместо первоначальных 50 мс (решение игрока). Если до следующей ноты меньше
300 мс, она загорается в кадре после попадания, и быстрая следующая нота игрока могла попасть в
широкое окно; громкость эха равна нашей, громкость живого нажатия совпадает с ней редко. Отпускание
громкости не несёт: Note Off уходит в кадре после попадания, поэтому теряется только отпускание
клавиши, которую держали меньше ~46 мс (кадр + окно). Эхо через USB приходит за единицы миллисекунд;
Bluetooth-MIDI с задержкой больше 30 мс окно может пропустить — тогда остаётся фильтр по каналу.

### D4. Канал на входе

`parseMidiMessage` добавляет нажатиям и отпусканиям `channel` (1–16); `KeyEvent.channel`
необязателен — у компьютерной клавиатуры и мыши его нет, и они фильтром не проверяются.

### D5. Выход отдаёт `send`

`MidiOutputControl.send(message)` шлёт на текущий подключённый порт через `sendSafely`; без порта
ничего не делает. Смена порта видна хуку по `OutputState.current`: при изменении id хук вызывает
`lights.forget()`.

### D6. Хук и хранение

`src/app/keyLightPreferences.ts`, ключ `key-lights-v1`, `{ enabled, channel, velocity }` с откатом к
`{ false, 3, 64 }` по каждому полю. `useMidiOutput(trainerRef, trainerReady)` создаёт `KeyLights`
поверх `control.send`, по готовности тренажёра ставит `trainer.onLights = lights.show` (и снимает
при размонтировании), применяет настройки через `configure` и возвращает в группе `output` поля
подсветки и `isEcho`. `useKeyInput` получает `trainerReady` и в `onMidiKey` отбрасывает нажатия и
отпускания, для которых `isEcho` истинно, раньше перехвата диапазона и тренажёра. `App.tsx` передаёт
`trainer.trainerReady` четвёртым аргументом: +1 строка, 498 из 500.

### D7. Интерфейс

`MidiSettings` в блоке выхода: флажок «Подсветка клавиш»; включённый — `<select>` «Канал подсветки»
1–16 с предупреждением при 1 и числовое поле «Громкость подсветки» 1–127, значения вне пределов не
принимаются. Переводы в `settingsMessages3.ts`.

## Risks / Trade-offs

- [Кадр] → `keyHints()` уже считается в каждом кадре; ещё один вызов и сравнение двух наборов из
  единиц нот; сообщения уходят только при изменении. Нотный стан не затронут.
- [Скрытая вкладка останавливает кадры] → клавиши горят до возврата, но и песня стоит; уход со
  страницы гасит их паникой выхода.
- [Канал подсветки совпал с каналом пианино] → предупреждение при канале 1; на другом канале
  совпадение маловероятно, но нажатия тогда пропадут — игрок увидит это сразу и сменит канал.
- [Синтезатор без подсветки] → по умолчанию выключено; тихие ноты слышны, громкость настраивается.
- [Модель понимает подсветку иначе] → только Note On/Off на канале; SysEx-протоколы вне задачи.
- [Нет железа] → тесты на подставной отправке; ручной прогон loopMIDI + MIDI-OX откладывается до
  появления устройства.

## Migration Plan

Новый ключ хранилища, по умолчанию подсветка выключена. Откат — удалить ключ.
