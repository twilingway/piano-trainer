# Design

## Context

Общий zoom применяется в Staff и PianoTabs. fitCompactStaff после ручного zoom уменьшает OSMD.Zoom
до фиксированного CSS height cap совместного вида. В scoreTabLabelSize размер ограничен расстоянием
до следующей атаки той же руки: при плотной правой партии этот предел уже активен, при редкой левой
— нет. Простое удаление предела создаст перекрытия.

## Goals / Non-Goals

Цель — два независимых визуальных коэффициента с совместимым хранением и читаемыми руками. Музыка и
время остаются в существующих pure song/PracticeSession. Не меняются оценка, MIDI, special auto-fit
начальных P1–P8, стиль курсора, конечная прокрутка и камеры.

## Decisions

1. Сохранить zoom как staff zoom; добавить tabsZoom в StaffPrefs (default=1, 0.5–2). При
   отсутствующем tabsZoom нормализованный legacy zoom служит его начальным значением. Явное
   повреждённое tabsZoom получает безопасный default, не скрывая валидный zoom. Существующие
   preferencesSlice/persistence сохраняют canonical object под staff-prefs.
2. Два регулятора в StaffSettings с уникальными RU/EN labels/aria. Drag-handle стана меняет только
   zoom. Остальные настройки остаются общими. Нового storage/формата курса нет.
3. Базовая viewport-подгонка определяет масштаб при 100%; пользовательский коэффициент применяется
   после неё. Сохраняется ограничение области чтения, при увеличении используется внутренняя
   прокрутка. Не применять CSS transform готового SVG: иначе координаты и hit-testing разойдутся.
4. PianoTabs читает tabsZoom. Буквы и пальцы обеих рук получают один коэффициент. Минимальная
   горизонтальная дистанция учитывает размер подписей в sharedReaderSpacing/uniformStaffLayout. Это
   может расширить интервалы обоих видов, но не размер нотных символов стана. Альтернатива
   фиксировать ось и убрать cap отвергнута из-за наложения плотных названий.
5. Workspace передаёт только недостающие параметры общей раскладки в Staff; после её завершения
   публикуется один ReaderGeometry. Табам не добавляются часы и сглаживание. При single/wrapped,
   смене фразы/порядка сохраняется существующая инвалидизация геометрии.
6. Профильные регрессии принадлежат группам prefs/UI и renderer. По просьбе игрока тесты запускаются
   в конце всей реализации задачи, а не после каждого редактирования.

## Risks / Trade-offs

- OSMD fit/wrapped и единицы spacing: проверить фактические glyph bbox и минимальные промежутки, а
  не только число prefs. Увеличение табов может изменить переносы обеих панелей.
- Общая ось обязательна: нельзя компенсировать размер правой руки отдельным transform.
- Разные font RU/EN требуют измерения ширины подписи. Не растягивать всю разреженную песню.
- При tiny viewport увеличенное содержимое прокручивается в своём окне; клавиатура не вытесняется.
- PR227–229 ещё не в dev: изменения не включаются в этот PR; совместимость проверяется отдельно и
  при необходимости после обновления базы.

## Migration Plan

Новый параметр нормализуется существующим адаптером до создания store; старые данные не удаляются.
Откат production-кода обратим, прежний zoom остаётся совместимым.
