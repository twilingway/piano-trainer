## Context

В исходной песне есть три ми, поэтому четыре разные исходные ID выбрать нельзя. Дублировать один
canonical ID недопустимо: разрушится 1:1 и одно удержание сможет отвечать за несколько событий.

## Goals / Non-Goals

Дать четыре независимых повторения ми без подмены исходной песни и без утраты старой истории. Не
менять rubric, sourceHash, XML полного финала, таймеры и схему сохранений.

## Decisions

Новый node `notes-e-repeat-v1` содержит typed repeat-definition с origin ID и count=4. Чистый XML
pass копирует оригинальную ми4/finger3/half четыре раза в два такта 4/4, сохраняя темп. Копии имеют
уникальные derived IDs, явно отличимые от исходных. Общий helper ожидаемых ID используется builder и
проверкой завершения. Source loader продолжает проверять уникальность и явные роли; неизвестные
source IDs не получают общего исключения. Производный XML сохраняет accompaniment part с паузами.

Старый `notes-e-intro` хранится в legacyNodes, разрешается для истории и прямой загрузки прежнего
материала. Старый selection явно переходит к новому node в ready. Следующий этап после старого
выбора остаётся смешанной фразой. Однократный receipt не завершает новый четырёхнотный узел. Review
для repeat-intro недоступен: обычный retry остаётся на тех же четырёх ми.

## Risks / Trade-offs

Старые звёзды не переносятся в новый node. Это сохраняет честность четырёх ответов. Исходная ми
половинная и держится две доли; учебная полоса показывает длительность без новой терминологии.

## Migration Plan

Без переписывания истории и исходника: новый node и явный alias выбора, старый материал доступен.
