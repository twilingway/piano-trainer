## Context

`src/input/midiInput.ts` запрашивает `MIDIAccess`, слушает все входы и занимает
`access.onstatechange`. `useKeyInput` подписывается один раз за жизнь приложения; выбор входа не
сохраняется. Предпочтения игрока хранятся в `localStorage` маленькими модулями
`src/app/*Preferences.ts` с откатом к значению по умолчанию. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:** выход как отдельный объект с понятным временем жизни; правила выбора и паники покрыты
тестами на подставном `MIDIAccess`; таймеров нет.

**Non-Goals:** общий `MIDIAccess` для входа и выхода, отправка нот песни, выбор канала.

## Decisions

### D1. Свой `MIDIAccess` и `addEventListener`

`src/input/midiOutput.ts` запрашивает свой `MIDIAccess` и слушает `statechange` через
`addEventListener`, а не `onstatechange`: так выход не перетирает обработчик входа, даже если
браузер вернёт тот же объект. Разрешение то же, что у входа (без SysEx), второго запроса прав игрок
не видит.

### D2. Контроллер выхода

`openMidiOutput(choice, onState)` возвращает `{ select(choice), test(), dispose() }` и сообщает
`{ devices, current }` (`current` — выбранный подключённый выход) при открытии, каждом `statechange`
и смене выбора. `choice` — `{ id, name }` или `null`. Чистая `findOutput(devices, choice)` ищет по
id, затем по имени. Порт с `state === "disconnected"` в список не входит.

### D3. Паника без таймеров

`panicMessages()` — 16 сообщений `[0xB0 | channel, 123, 0]`. Контроллер шлёт их на прежний порт,
когда `select` меняет порт, в `dispose()` и в обработчике `pagehide` окна. Каждая отправка обёрнута
в `try`: отключённый порт бросает `InvalidStateError`. Отключение порта само паники не шлёт — слать
некуда.

### D4. Проверка через отложенную отправку

`test()` шлёт `[0x90, 60, 64]` сразу и `[0x80, 60, 0]` с отметкой `performance.now() + 1000` вторым
аргументом `MIDIOutput.send`: браузер сам отложит сообщение, `setTimeout` не нужен. Если за эту
секунду выход сменится, паника на прежний порт гасит ноту раньше.

### D5. Хранение и хук

`src/app/midiOutputPreferences.ts`, ключ `midi-output-v1`, значение `{ id, name }` или `null`. Хук
`src/app/useMidiOutput.ts` открывает контроллер один раз; запрос, отменённый двойным монтированием
StrictMode, через `AbortSignal` ничего не открывает и паники не шлёт, а выбор, сделанный, пока
браузер спрашивал доступ, применяется после открытия, держит список и выбор и отдаёт чистые пропсы
разделу «Пианино». Выбор сохраняется при каждой смене игроком; переподключение выбор не меняет. Хук
вызывается из `useKeyInput`: он становится MIDI-узлом в обе стороны и отдаёт готовую группу
`settings` для раздела «Пианино» (вход, ошибка, выход). `App.tsx` уже стоял на потолке в 500 строк,
а отдельный вызов и четыре пропса входа его превышали (решение игрока).

### D6. Интерфейс

`MidiSettings` получает группу `output`: список, выбор, `connected`, `onSelect`, `onTest`.
Выбранный, но отсутствующий выход показывается в списке строкой «{name} — нет связи», чтобы
`<select>` не сбрасывался на «Нет». Без поддержки Web MIDI группа не передаётся и блок не рисуется.

## Risks / Trade-offs

- [Chrome на Windows меняет id портов после переподключения] → поиск по имени после id.
- [Два порта с одинаковым именем] → по имени берётся первый; id обычно совпадает, поэтому выбор
  стабилен.
- [`pagehide` при уходе в bfcache] → паника безвредна; после возврата выход остаётся выбранным.
- [Нет железа] → тесты на подставном `MIDIAccess`; ручной прогон loopMIDI + MIDI-OX. Поведение на
  настоящем пианино с подсветкой остаётся непроверенным.

## Migration Plan

Новый ключ хранилища, по умолчанию «Нет». Откат — удалить ключ.
