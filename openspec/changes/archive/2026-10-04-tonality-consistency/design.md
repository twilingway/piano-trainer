# Design

## Context

См. proposal.md. Сейчас название вычисляется из pitch class одной таблицей, а MusicXML выбирает
другой энгармонический ключ. По правилам репозитория модель и XML-проходы остаются чистыми.

## Goals / Non-Goals

Цель — единый результат для интерфейса, ключевых знаков, звучащих высот и буквенных ступеней. Темп,
длительности, сетка тактов и единые часы сессии не меняются. Микротональная и нетрадиционная
нотация, отдельный выбор энгармоники и транспонирующие инструменты не расширяются этим исправлением.

## Decisions

- `src/song/keySignature.ts` владеет `Key` с необязательным авторским `fifths`, названием,
  полутоновым сдвигом и диатоническим переносом высоты. Для ненулевого сдвига сохраняется
  существующая нормализация `−5…+6`; ноль сохраняет оригинал. Альтернатива с семью диезами во всех
  до-диезных вариантах изменила бы принятую запись нот без необходимости.
- `detectKey` сначала использует первую пригодную исходную сигнатуру партитуры. Без `mode` профили
  сравниваются только для её относительных мажора и минора. MIDI и XML без пригодной сигнатуры
  сохраняют текущий алгоритм; чтение не меняет исходный XML.
- `SongSettings` строит варианты через ту же чистую транспозицию ключа. React только передаёт сдвиг;
  семитоновый выбор и кнопки сохраняются.
- Для XML без пригодной начальной сигнатуры `useSong` передаёт определённый по нотам исходный ключ в
  XML-проход; тот добавляет целевую сигнатуру. Такая исходная тональность подписана «исходная», а не
  «как в нотах». Неподдерживаемый явный лад не выдаётся за мажор/минор.
- XML-проход выносится из `musicxml.ts`, чтобы соблюдать предел модуля. Диатонический интервал
  выводится из исходной и целевой тоники; `alter` и `octave` рассчитываются для точной MIDI-высоты.
  Общая таблица чёрных клавиш не сохраняет гармонический минор и потому исключается.
- Контекст исходной сигнатуры хранится отдельно для каждой партии и каждого `key number`/`staff`.
  Общая сигнатура применяется ко всем станам; атрибуты меняют контекст по ходу тактов.
- Ненулевая транспозиция по-прежнему удаляет старые пальцы и явные accidental, чтобы renderer
  выставил знаки для новой записи. Нулевой сдвиг возвращает исходную строку.

## Risks / Trade-offs

- Неверная октава у энгармоники → независимые проверки MIDI-высот для всех сдвигов `−11…+11`.
- Неверный лад короткого фрагмента без `mode` → выбор ограничен двумя относительными ключами; явный
  авторский лад всегда имеет приоритет.
- Неверное перенесение хроматических ступеней → тесты диатонических гамм и гармонического минора.
- Пересчёт стана → выполняется только при изменении песни/транспозиции, вне кадрового цикла.
- Нетрадиционные ключи остаются вне охвата; их нельзя интерпретировать как обычные `fifths`.
