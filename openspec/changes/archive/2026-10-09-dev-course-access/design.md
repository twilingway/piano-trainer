# Политика доступа к курсу

## Context

См. proposal.md. Сейчас `lessonUnlocked` и `blockingLessonNumber` учитывают только прогресс;
карточки, команды и восстановление вызывают их независимо.

## Goals / Non-Goals

Передавать одинаковый явный режим `progression` или `review` всем проверкам доступа. Режим не
попадает в Redux или localStorage и не влияет на зачёт упражнения, очки, музыку и время.

## Decisions

Чистая модель принимает `CourseAccessMode`, по умолчанию `progression`. В `review` предыдущий урок
не блокирует доступ, но отсутствие подготовленных фраз или этапов по-прежнему запрещает запуск.
Контроллер и адаптер восстановления тоже сохраняют безопасный default `progression`.

Оболочка выбирает `review` только при `import.meta.env.DEV` и явно передаёт его store, контроллеру,
определению текущего курса и карточкам. Production build получает `progression`; настройка, URL и
сохранение не могут включить обход. Альтернатива с фиктивными зачётами отвергнута: она искажает
прогресс и сохраняется после dev-проверки. Обход только в карточке недостаточен: команда или reload
снова закрывают упражнение.

## Risks / Trade-offs

- Несогласованные режимы в оболочке → тесты открытия, смены рук и восстановления; ревью точек
  вызова.
- Доступ к непроверенному содержанию → независимая проверка готовности, негативные тесты.
- Случайное изменение production → безопасные defaults и проверка обоих режимов одним набором
  тестов.

Кадровый цикл и OSMD не меняются: проверка доступа выполняется при выборе и восстановлении.

## Migration Plan

Формат сохранения не меняется. Доставить через PR в dev; пользователь сливает PR и проверяет
существующий localhost:5190. До слияния браузерная приёмка изменения ожидается. Откат коммита
возвращает прежнюю блокировку, сохраняя реальные отметки.
