# Design

## Context

См. proposal.md. Предыдущее изменение разрешало находить действия прокруткой всей учебной комнаты.
Это не обеспечивает их видимость в низком обычном окне. Media-правило объединяет инструкцию и
счётчик в разные колонки; инструкция центрируется относительно остатка ширины. Учебная ветка `Staff`
игнорирует обычный `zoom`, а `fitCourseInk` повторно уменьшает изображение до CSS-предела.

## Goals / Non-Goals

**Goals:** выделить непрерывную учебную сцену и отдельную боковую/верхнюю область действий,
обеспечить независимый учебный масштаб и исключить прокрутку из-за пустой нотной страницы.

**Non-Goals:** новый музыкальный clock, изменение заданий/политики помощи, новая реализация
клавиатуры, перенос OSMD в чистое музыкальное ядро или изменение обычного масштаба песни.

## Decisions

1. `LessonWorkspace` размещает сцену и управление отдельными ограниченными flex/grid-областями.
   Широкий/альбомный экран получает левую область action/hint/answer, узкий портретный — верхнюю
   полосу. Под нотами нет закреплённого footer, отнимающего место у их рисунка. Действия результата
   используют ту же отдельную область. Body сцены содержит только score; input hint находится в
   заголовке. Короткие feedback/result summary занимают контекстную строку заголовка вместо общей
   инструкции, пока присутствуют; без них видна инструкция. Переиспользуются существующие slots и
   контент с прежними правилами помощи, без повторного вычисления ответа в представлении. Короткий
   текст переносится и целиком виден, не прячется в маленькую прокручиваемую боковую область.
   Длинные подробности продолжают открываться через существующие окна урока/результата. Граница
   определяется фактической доступной высотой workspace и существующей высотой клавиатуры,
   промежуточные flex/grid-области получают `min-height: 0`. Увеличение `z-index` не решило бы
   конфликт геометрии и зоны нажатия, а прокрутка для поиска основных действий не выполняет
   требование видимости. Инструкция центрируется по области сцены независимо от счётчика.

   Горизонтальная опорная ось нотного рисунка — середина всей `.workspace-main`, а не середина body,
   оставшегося справа от кнопок. Левой панели соответствует симметричный правый резерв; мобильная
   учебная область использует полную ширину с согласованным резервом бокового меню. На портретном
   экране отступы также сбалансированы. По вертикали помещающийся ink центрируется внутри доступной
   нотной сцены. Приёмка сравнивает реальные экранные центры с допуском 1 CSS px отдельно для X и Y;
   непомещающийся рисунок сохраняет прежний приоритет видимости головок.

2. Отдельное числовое предпочтение `lessonZoom` хранится в существующем объекте `StaffPrefs`:
   default `1.5`, допустимый конечный диапазон `[0.5, 2]`, шаг интерфейса `0.05`. Нормализация
   принадлежит чистой функции `normalizeStaffPrefs`; Redux и существующий persistence только
   сохраняют значение. `SettingsView` показывает через `StaffSettings` управление «Масштаб нотного
   стана в уроках» рядом с обычным масштабом в группе «Размер и прокрутка». В области управления
   уроком нет дублирующих кнопок размера. Переиспользование обычного `zoom` нарушило бы
   независимость сохранённой партитуры.

3. Учебный адаптер OSMD вычисляет стабильный базовый размер для зарезервированного диапазона
   упражнения, затем применяет `lessonZoom`. Последующий fit не отменяет ручное увеличение.
   Измерение ink и подгонка SVG viewport учитывают итоговый размер. Пустая бумага над и под учебным
   рисунком удаляется из SVG viewport без изменения нотных координат; курсор и notehead hit-test
   учитывают тот же сдвиг. Один владелец пользовательской вертикальной прокрутки — body учебной
   сцены; отдельная вложенная прокрутка стана не создаётся. Если реальный ink с отображаемым
   содержимым помещается, body не переполняется из-за исходной OSMD page. Запас крайних нот
   сохраняет стабильный baseline и не превращает пустую страницу в высоту scroll-контента.
   Перемасштабирование всего workspace через CSS transform изменило бы клавиши, hit-test и действия,
   поэтому не используется.

   При настоящем переполнении после layout адаптер/связующая оболочка согласует прокрутку с
   реальными экранными границами текущих notehead. Граница сравнения — видимая область сцены,
   отделённая от бокового/верхнего управления, а не полная страница или прежний CSS max-height. Если
   весь ink помещается, автоматическая прокрутка не нужна. Если не помещается ключ вместе с нотами,
   приоритет получают головки. Физически непомещающийся диапазон нескольких головок остаётся
   доступен ручной прокруткой без уменьшения выбранных 200%; одновременная видимость всех в таком
   случае не обещается. Проверка повторяется на смену prompt, zoom и доступной высоты/fullscreen, не
   меняет музыкальную позицию и не создаёт кадровый polling.

4. Чистое музыкальное поведение остаётся в существующих модулях упражнений и `PracticeSession`.
   Размер является предпочтением представления и не создаёт нового поведения оценки. Адаптер
   `src/staff` владеет DOM/OSMD, React связывает параметры, `LessonWorkspace` только компонует
   переданные данные и элементы. Действующие профили урока продолжают скрывать недопустимые
   названия, пальцы и ответы независимо от размера.

## Risks / Trade-offs

- Большой стан занимает больше места → сохранять отдельное управление и клавиши, удалять пустую
  бумагу, вводить одну прокрутку только при настоящем переполнении; проверить 100/150/200% с
  добавочными линиями и результатом на 568×320, 667×375 и 320×568, отдельно случай непомещающегося
  диапазона нескольких головок.
- Автоматический fit может незаметно отменить ручной размер → сравнить реальные размеры одного ключа
  и notehead при 100/150/200%, а не только процент в DOM.
- Потеря фокуса/зоны нажатия после переноса slots → проверить реальный hit-test центров кнопок,
  клавиатурный ввод и смену задания, не пересоздавая canvas.
- Короткая подсказка исчезает в тесной боковой панели → размещать её в контекстном заголовке вместо
  инструкции; проверить полный RU/EN текст и отсутствие внутренней прокрутки до/после завершения, а
  не только наличие текста в DOM.
- Лишние перерисовки партитуры → пересчитывать только по изменению размера, viewport либо учебного
  материала; не добавлять измерений, записи настроек или OSMD render в кадровый цикл.
- Разница обычного окна и fullscreen → проверять реальный переход Fullscreen API с внешними панелями
  приложения, дополнительно к изменению viewport.

## Migration Plan

Отсутствующее либо нечисловое значение получает 1.5; конечные значения ограничиваются диапазоном.
Другие сохранённые поля не меняются. Откат возвращает прежний UI; добавочное поле старый код может
игнорировать. Новых зависимостей и миграции музыкальных данных нет.
