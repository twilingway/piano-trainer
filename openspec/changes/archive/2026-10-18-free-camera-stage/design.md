# Design

## Context

См. proposal.md. ThreeKeysHost включает мировые эффекты только для performanceWanted. ThreeStage
включает площадку только для performanceEnabled и передаёт ей камеру постановки. Свободная камера
поэтому оставляет экранные Pixi-эффекты при движении пианино в мировых координатах.

## Goals / Non-Goals

Цель — повторно использовать единственную сцену и эффекты с ручной камерой. Автоматический маршрут,
форма нот, ввод и сохранённые настройки сохраняют текущие контракты.

## Decisions

- Видимость декораций определяется performanceEnabled или freeEnabled; выбор камеры остаётся
  отдельным.
- PerformanceWorldStage получает фактическую активную камеру для ориентации billboard-эффектов.
- Свободный осмотр использует полностью открытые свет и площадку без вступительного затемнения и
  финальной шторки. Временные кадры эффектов читают исходное время PracticeSession.
- Существующие правила музыкального огня сохраняются: нота или бас вызывает огонь; пустая песня не
  создаёт вымышленных атак.
- Для ручной камеры не рисуются экранные дубликаты дыма/огня даже пока атласы загружаются. После
  загрузки эффекты появляются в мировой сцене; при отказе 3D возвращается штатный запасной вид.
- Pure core не меняется: поведение музыкального времени принадлежит PracticeSession, оболочка
  Three/Pixi только выбирает вид и рисует имеющиеся данные.

## Risks / Trade-offs

- Дополнительная сцена увеличивает стоимость свободного осмотра → переиспользовать ограниченные
  существующие пулы без второго экземпляра сцены или покадровой пересборки геометрии.
- Неверная камера разворачивает спрайты → тестировать передачу free.camera и реальный поворот.
- Изменение освещения постановки → отдельные проверки её переходов и обычного учебного вида.
- Нотный стан не затрагивается; его рендер не получает дополнительных обновлений.

## Migration Plan

Миграция настроек не нужна. Откат — возврат изменений оболочки рендера.
