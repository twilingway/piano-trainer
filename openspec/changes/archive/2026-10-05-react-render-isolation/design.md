# Дизайн изоляции обновлений React

## Context

Context в src отсутствует. Горячая цепочка: Trainer.publish → useTrainer.setSnapshot → App → все
окна и представления. Закрытый dialog остаётся смонтированным, библиотека строит весь каталог.
Настройки должны сохранять выбранную вкладку при закрытии.

## Goals / Non-Goals

Цели: исключить обновления оболочки от времени/статистики; оставить реактивными видимые показатели;
автоматически кешировать стабильные JSX, значения и функции. Не меняем игровую механику, время,
скорость, внешний вид, предпочтения и формат данных. Не переписываем Pixi/OSMD и не добавляем общий
Context.

## Decisions

1. Адаптер снимков принадлежит одному экземпляру useTrainer, хранит последний опубликованный объект,
   даёт стабильные subscribe/getSnapshot. Это доставка состояния тонкой оболочки, без таймеров,
   собственной симуляции или глобального хранилища.
2. useSyncExternalStore с селекторами: App читает playing/finished/waiting/timingPolicy; небольшой
   app-коннектор читает time/stats/noteStatuses там, где они видны. Команды читают актуальный
   снимок, чтобы не замкнуть устаревшие playing/finished.
3. Подключённые компоненты app/ соединяют подписки с существующим props-only UI. App остаётся
   композицией; CODE_STYLE уточняет разрешение тонких коннекторов и локального адаптера снимков.
4. Библиотека и результат не строят закрытое содержимое. Оболочка SettingsPanel хранит active
   независимо от наличия содержимого; содержимое и его live subscriptions создаются при открытии,
   выбранная вкладка сохраняется.
5. Конфигурация timing и input interceptor получают явные зависимости и trainerReady; диагностика
   читается локально в открытой панели. Один MIDI/ПК/мышиный маршрут и один Pixi instance
   сохраняются при StrictMode, перезагрузке урока и смене режима.
6. Стабильный официальный Babel React Compiler через @rolldown/plugin-babel и reactCompilerPreset
   для установленного @vitejs/plugin-react 6. React19 runtime встроен; только devDependencies.
   Экспериментальный Rust port не используется. Компилятор работает в dev/build; unit tests могут
   оставаться без compiler, чтобы он не маскировал ошибочные архитектурные подписки. Проверяем
   generated code и отсутствие непреднамеренных compiler bailouts на границах App/окон.
7. Существующие useMemo/useCallback, защищающие trainer.load, стабильный liveBeat и lifecycle,
   сохраняются. Для стабильных новых UI-поддеревьев полагаемся на Compiler. Кеширование не заменяет
   корректные зависимости эффектов.

## Проверяемые сценарии

- При 30 сек игры snapshot обновляет HUD, прогресс, текст и статистику; App и закрытые окна не
  повторяют render из-за time/stats. Тесты со счётчиками исполняются без Compiler.
- Открытая библиотека выбирает урок и экспортирует его прежними обработчиками; закрытие не
  сбрасывает урок/предпочтения.
- После выбора раздела, закрытия и открытия настройки показывают прежний раздел; открытая
  статистика/диагностика актуальна, FPS доступен в обоих режимах и сохраняется при reload.
- Пауза/продолжение/перезапуск/seek/завершение/прослушивание/сравнение сохраняют прежние часы,
  актуальные значения команд и блокировки Ranked.
- Смена песни/режима и StrictMode не оставляют лишних listeners/input interceptors/canvas. Удаление
  подписки не доставляет ей новые снимки.
- Видимый Chrome: одинаковый встроенный урок, режим, viewport и async stack depth до/после;
  фиксируем p95/max/число длинных кадров и работу controls. Гарантии FPS на любом устройстве нет.

## Risks / Trade-offs

Селектор должен возвращать кешированное значение, иначе useSyncExternalStore может зациклиться.
Закрытие настроек не должно забыть вкладку или оставлять включённым editor/interceptor. Компилятор
может пропускать несовместимые функции: это явно проверяется, пропуски разбираются или
документируются. Новые dev dependencies повышают стоимость transform; проверяем HMR и сборку. Чужие
изменения styles.css сохраняются, готовая работа интегрируется в основную папку для localhost:5190.

## Open Questions

Нет. Поведение сохраняется; пользователь запросил общий рефакторинг и автоматическую мемоизацию.

## Проверка реализации

Тесты без Compiler проверяют 30 секунд публикаций без повторного render оболочки, независимость
источников, selectors, закрытые окна, async-команды, StrictMode и timing cleanup. Проверка реального
выхода Compiler: 87 функций компилируются; три существующих ограничения перечислены в
`docs/react-compiler.md`. Dev и production используют кеши, тестовый режим обходится без них.

Видимый Chrome, встроенный гимн, интервал 8 секунд, async stack depth 32:

| Режим            | App / закрытые окна до | После | Кадры >33,4 мс до / после | Максимум до / после |
| ---------------- | ---------------------- | ----- | ------------------------- | ------------------- |
| Пианино          | 114                    | 2     | 1 / 0                     | 36,3 / 18,3 мс      |
| Печатать мелодию | 112                    | 0     | 14 / 0                    | 42,4 / 24,3 мс      |

Это измерение отдельного прогона, а не гарантия FPS. Прогресс продолжал обновляться. Evidence:
`.browser-artifacts/react-render-baseline.json`, `react-render-after.json` и снимки 320×568,
390×844, 667×375; горизонтального overflow нет. Проверены pause/seek/restart, актуальная статистика,
сохранение вкладки и FPS после reload, мобильный выбор раздела, экспорт MIDI без закрытия библиотеки
и выбор урока с закрытием. Canvas остаётся один. Звук и физический MIDI по этим проверкам не
оценивались.

Полный `pnpm check` и `pnpm spec:validate` прошли. Независимое ревью не выявило блокирующих ошибок.
Готовый код интегрирован в основную папку с сохранением параллельных изменений; preview —
localhost:5190.
