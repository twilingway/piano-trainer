# Design

## Context

Причина в proposal.md. Каждый базовый курс имеет отдельный controller и UI; P2 является прогрессом
чтения, а не вторым курсом. Образец представления — MusicCourse.

## Goals / Non-Goals

Цель: компактное представление без изменения параметров команд. Не создавать универсальный учебный
движок, новую навигацию по этапам, искусственное продолжение или миграцию прогресса.

## Decisions

- Небольшой LessonDetails использует native details/summary, стабильный data-window-detail и ленивый
  монтаж содержимого после открытия. Общие названия guide/settings/progress/more локализованы в
  одном месте.
- Карточки чтения и баса показывают основное существующее задание notes; остальные режимы доступны в
  «Другие задания». Интервалы начинают с прежнего see-and-play. Знакомства остаются доступными
  второстепенным действием.
- Статус, текущий счётчик, ошибки, восстановление, ответ, выход и текущий итог остаются вне закрытых
  раскрытий. Подробная история, общая теория и настройки раскрываются отдельно.
- IntervalHelp и активные подсказки не переносятся в справку. Открытие общей теории не вызывает
  onHint/onHelpPresented. Контроль не получает ответ из скрытого содержимого.
- Кнопка ритмического удара и её release handlers сохраняют постоянный монтаж. Изменение учебной
  настройки по-прежнему вызывает существующую команду, включая прежнюю отмену серии.
- Фильтр источника P2 сохраняет своё значение для следующей адаптивной подборки, а не получает
  ложное название только фильтра истории.
- Стабильные существующие внутренние ключи памяти окна сохраняются. Новые внешние раскрытия имеют
  уникальные постоянные ключи.
- Нет работы на кадр: открытие справки меняет только локальное представление; тяжёлая история не
  строится в закрытом разделе.

## Risks / Trade-offs

- Ложный показ помощи → оставить активную подсказку в прежнем пути; проверять отсутствие callback от
  раскрытия справки.
- Потеря органов ответа → тесты реальных команд и браузерная проверка ритма/кнопок без MIDI.
- Память окна и ленивые дочерние разделы → проверить восстановление открытого внешнего раздела и
  прокрутки.
- Настройки менее заметны → открытая короткая инструкция и доступная подпись раздела, сообщения
  ошибки всегда видимы.

## Migration Plan

Не требуется. Откат UI не меняет сохранённые задания и результаты.

Сохранённый initialOpen читается из памяти живущего окна через context: открытое внешнее раскрытие
монтирует содержимое до восстановления внутренних разделов и прокрутки. Перед ленивым
размонтированием вложенные раскрытия запоминаются отдельно; отсутствие их DOM при закрытой внешней
секции не стирает эти значения.
