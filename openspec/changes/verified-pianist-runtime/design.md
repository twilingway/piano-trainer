# Устройство приватного исполнения

## Context

См. proposal.md. NativePianistClip уже проверяет identity полного исходного исполнения и семплирует
время песни. Keyboard88Performer использует отдельный публичный LBS-атлас: mirrored LEFT,
приближённую композицию корпуса и runtime IK. Этот путь не доказывает новую нативную геометрию.

## Goals / Non-Goals

**Goals:** воспроизводимые контакты и деформации, нативная LEFT, общий корпус, детерминированное
семплирование паузы/seek/replay и сохранность приватных файлов.

**Non-Goals:** публикация лицензированных производных, смена камеры, изменение музыкальной оценки,
новые runtime-оптимизаторы и выдача диагностических кадров за проверенный атлас.

## Decisions

### 1. Выбранный основной риг и доказательство поверхности

28 октября 2026 пользователь после просмотра обеих моделей выбрал серую основную модель на 52 кости.
Для итогового пути сохраняются её существующий rig/rest/bind/root и геометрическая основа. Отдельная
приватная модель на 68 костей не входит в перенос; проведённые исследования её несовместимости
остаются диагностикой.

До применения поз сравниваются parent order, local rest, root/mesh/bind и inverse bind matrices.
Actual public GLB и saved Blender имеют точно одинаковые 6890 Basis вершин, 13776 faces и top4
weights. Rest/bind отличаются лишь Float32 округлением. Совпадение имён само по себе недостаточно.

Различия полного веса, PSD, subdivision, GN PAD/SIDE и ногтей требуют приватного corrective export.
Отдельный offline-аудит сравнивает фактические skin/pad/nail vertices Blender и Three.js на
endpoints и дробных отсчётах. Костная точность не заменяет поверхность: нужные correctives
сохраняются либо экспорт отклоняется. Неподтверждённые поправки и stretch не вводятся. Старый public
bank не выдаётся за новые проверенные позы, public assets не переписываются.

### 2. Приватный путь и происхождение

Файлы расположены только в ignored local-models; загрузчик существует под import.meta.env.DEV.
Manifest фиксирует source/model/code/export SHA, rig profile и результаты независимых гейтов. Нет
допущенной позы — нет заявленного проверенного исполнения: остаётся существующий fallback. Полный
source-performance clip сохраняет действующий identity gate. Public assets не переписываются.

### 3. План вне кадрового цикла

Чистый TypeScript-модуль строит план по нотам с назначенными пальцами и одним torso. Тяжёлый поиск,
контактная коррекция и проверка всего пути выполняются offline. Самpler получает абсолютное время
PracticeSession и заполняет готовую позу без собственного clock, таймера и состояния интеграции.
Удерживаемые контакты ограничивают обе руки и общий корпус; независимые PASS нельзя усреднять.

### 4. Проверка этапов

Порядок допуска: numerical bilateral/world → saved Blender → export surface → browser → visual.
Новый эксперимент не меняет frozen C4/source и не получает PASS по отдельному тестовому клипу. Все
непройденные случаи остаются в ledger с причиной, coverage и точными путями.

## Risks / Trade-offs

- LBS не воспроизводит PSD/SIDE → сравнение skin, отдельный corrective export до допуска.
- Неизвестный аккорд/переход → явный отказ проверенного плана без смены пальцев/нот.
- Переезд второй руки сдвигает контакт → общий offline bilateral proof на всём переходе.
- Частные данные попадают в release → DEV gate, ignored inputs и проверка build output.

## Migration Plan

Сначала совместимость и negative controls, затем допущенные локальные позы и offline-переходы,
приватный loader и реальная проверка в задаче на 5191–5199. Публичный fallback сохраняется при
отсутствии либо несовместимости private asset. Визуальная приёмка пользователя записывается
отдельно.
