# Руки пианиста по примерам из видео

## Why

Решатель рук пианиста (`tools/hand-rig/hand_solver.py`, вызывается из `pianist_pose.py`) сам
придумывает кисть: нейтральный поворот, глубину пальцев, «яблоко» под ладонью. Потом он борется с
собственной моделью: кисть отворачивается от клавиш, запястье упирается в предел, октавы и широкие
растяжки ломаются. Пользователь хочет, чтобы постановку руки решатель брал из настоящих примеров:
запомнить, «эти ноты нажимают вот так», и пополнять запас вариантов с каждой новой композицией.
Первый источник — локальный разбор видео Seven Nation Army (пакет Codex `claude-handoff-v4`: ноты,
руки по цвету ролла, 21 точка MediaPipe на кисть при 60 кадрах в секунду).

## What Changes

- Индекс видео: ноты песни группируются по рукам в удары, каждому удару подбирается кисть из трека
  MediaPipe и её точки вокруг удара. Клавиатура калибруется по кадру: где в кадре каждая клавиша на
  любой глубине и сколько пикселей в сантиметре.
- Пальцы: автоматические кандидаты по движению нажатия, затем проверка по кадрам из исходного видео.
  Неподтверждённый палец остаётся пустым и потом считается алгоритмом аппликатуры с пометкой
  `computed`.
- Библиотека поз: постановка кисти на клавишах по кадру (место костяшек, поворот), пальцы и
  состояние большого пальца для каждой формы нажатия, а также форма пальцев — радиус «шара» и
  разведение каждого пальца, подогнанные под точки кадра; повторы одной формы сливаются. Библиотека
  — только числа — хранится в git.
- Механическая кисть вместо подбора весов. Фаланги рига — жёсткие звенья, суставы — шарниры с
  пределами-стенами (PIP и DIP сгибаются только в плоскости пальца, разведение — только в MCP,
  большой палец в пределах CMC). Естественный сгиб пальца — одна величина: фаланги лежат хордами на
  шаре своего радиуса.
- Поза руки — три слоя: `root` (место и поворот кисти), `shape` (шар и разведение каждого пальца из
  примера) и `press` (небольшой ход вниз только у нажимающих пальцев). Касание доводится по порядку:
  кисть по нажатым кончикам, затем шар пальца в узкой полосе вокруг примера. Что не доводится, не
  ломает позу, а помечается `strained` или `impossible`. Нет похожего примера — форма по умолчанию с
  пометкой `canonical`; прежний решатель с весами из пути пианиста уходит.
- Кисть планируется по времени: заранее встаёт к удару, не отпускает удерживаемые ноты, движется не
  быстрее предела. Где предела не хватает — пометка `degraded`, без телепорта.
- Отчёт и контрольные примеры: выход суставов за пределы, зазор между соседними пальцами, промах
  кончика, скачки кисти между кадрами, число пометок; по каждому примеру PASS или FAIL.
- Второй источник формы — видео сбоку (локально, правая рука): по нему сверяется сгиб пальцев,
  который вид сверху занижает.
- Вся песня (1243 ноты) анимируется в Blender в реальном времени с отчётом по каждой ноте.

## Goals

- Постановка кисти и форма пальцев берутся из наблюдённого исполнения, а не из штрафов с весами.
- Поза никогда не выходит за пределы суставов и не ломается ради касания: недоступное помечается.
- Происхождение каждого пальца и каждой позы видно в отчёте.
- Новая песня добавляет примеры в библиотеку без правки кода решателя.

## Non-Goals

- Игра в браузере (three.js) — следующий этап, не это изменение.
- Плечи и корпус по видео: в кадре их нет, тело решается как сейчас.
- Распознавание нот по видео: ноты берутся из пакета разбора как есть.
- Кадры, звук и тайминги песни в репозитории.
- Кожа кисти (кольца на сгибах вместо «сосисок»): отдельное изменение. Позы здесь проверяются на
  скелете и наложением на кадр, а не на коже.
- Перекрещивание рук и подкладывание большого пальца в быстрых гаммах: в этом изменении — помеченный
  упрощённый путь, без отдельной модели.

## Decisions to note

- Библиотека поз в git — только числа (постановка, пальцы, ссылка на источник). Кадры, звук, ноты и
  время песни остаются в git-игнорируемой папке `local-lessons/`.
- Кадры для проверки пальцев режет делегированный агент Codex (процедура `codex-worker`), проверку
  делает Claude; палец не угадывается под накрывающей рукой и по смазанному кадру.
- Новых зависимостей в репозитории нет: скрипты — обычный Python (Pillow, numpy) и Blender в фоновом
  режиме; ffmpeg уже есть на машине. Видео сбоку разбирается MediaPipe и yt-dlp в версиях из
  `tools/video-capture/requirements.txt`, в локальном окружении вне репозитория.
- Видео сбоку — чужая запись с YouTube: только локальный разбор в `local-lessons/.analysis/`, в git
  — лишь числа формы без кадров.

## Capabilities

### New Capabilities

- `pianist-hand-poses`: библиотека поз руки из видеопримеров, происхождение пальцев, механическая
  кисть с пределами суставов, поза в три слоя с пометками, план кисти по времени и анимация песни с
  отчётом.

### Modified Capabilities

Нет.

## Impact

- `tools/hand-rig/`: новые `video_hands.py`, `hand_features.py`, `hand_library.py`, `hand_mech.py`
  (механическая кисть и поза в три слоя), `hand_plan.py` (кисть по времени), `song_bake.py`,
  `compute_fingers.ts`, контрольные примеры `fixtures/*.json`; примеры в `pianist_pose.py`;
  библиотека `tools/hand-rig/poses/library/<song>.json`. Подбор кривизны и поворота в
  `hand_solver.py` из пути пианиста уходит; путь студии (`studio_pose.py`) не меняется.
- Код приложения (`src/`) не меняется; `assignFingering` используется как есть.
