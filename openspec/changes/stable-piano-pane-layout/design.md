# Design

## Context

См. proposal.md. `Workspace` сейчас выбирает `full/keys/hidden`, а `.lanes--keys` получает
`clamp(110px, 24vh, 260px)`. `viewGeometry` и `naturalNativeViewHeight` считают ограничения от
фактической высоты canvas, поэтому скрытие нот меняет и геометрию клавиш, и масштаб 3D-проекции.
`NativeKeyboardScene` и `RoadLayer` уже различают геометрию клавиш, их камеру и локальное
размещение.

`StaffHandle` для `singleLine` вызывает только `onZoom`; `fitHeight` затем сам назначает высоту по
одной строке. Мобильные селекторы для всех видимых дорожек, включая `lanes--keys`, дополнительно
ограничивают стан 150/200 px. `FpsMeter` добавляет свой DOM-элемент в `.lane`, поэтому его
координаты отсчитываются от уменьшающегося canvas.

## Goals / Non-Goals

**Goals:** разделить опорную геометрию пианино и доступный прямоугольник рендера; дать UI сведения о
минимальном месте для клавиш без второй независимой формулы; дать стану доступное место над
клавиатурой, сохранив одинаковый жест масштабирования нот на телефоне и компьютере.

**Non-Goals:** изменение времени песни, создание отдельного кадрового цикла, смена камеры или её
сохранённого профиля, уменьшение качества, новые зависимости, перестройка курсов и печати. Области
сравнения используют прежние размеры и отдельные якоря FPS. Свободная камера и сценический режим
также сохраняют прежнее поведение: изменение относится к обычной закреплённой клавиатуре, а не к
произвольному ракурсу всей сцены.

## Decisions

### 1. Одна опорная высота и одна формула места для клавиш

`Workspace` отмечает обычную закреплённую область пианино отдельно от курсов, печати, сравнения,
свободной камеры и сценического режима. Тонкая оболочка через `ResizeObserver` измеряет её
`.workspace-main` целиком, до вычитания стана и изменения `lanes--keys`. Это опорная высота; не
`window.innerHeight` и не уже уменьшенный `.lane`.

Предлагаемый совместимый интерфейс:

- `FallingNotesView.setLayoutReferenceHeight(height?: number)` принимает изменение измеренной
  высоты, проверяет конечное положительное значение и инвалидирует layout только при изменении.
- `layoutFallingKeyboard` получает необязательный `referenceHeight`; `KeyboardViewport` передаёт его
  в `RoadLayer`. Без него сохраняется существующий путь для курсов, печати и сравнения.
- Чистые `viewGeometry`/`nativeKeyboardFraming` рассчитывают естественную геометрию при опорной
  высоте, заданных ширине, диапазоне, камере, `keysScale`, `keysLift` и положении. Ограничение
  высоты клавиш одинаково при видимых и скрытых падающих нотах.
- Из этого же результата `publishOverlayLayout` публикует `--piano-required-height` — место для
  видимых клавиш, felt, подъёма и нижнего поля — и координаты верха/низа клавиш. Существующие
  `--hit-line`/`--keys-bottom` остаются локальными координатами canvas для ручек и HUD.

`.lanes--keys` только для отмеченного обычного пианино резервирует опубликованную высоту вместо
универсального `vh`-размера. UI не угадывает высоту 3D-модели по формуле классики. Первое измерение
до готовности модели использует безопасный прежний размер; после готовности применяется
опубликованный результат. Корректное повторное измерение не накапливает коэффициент масштаба.

Альтернатива «увеличить всем фиксированную полоску» не решает разные камеры/масштабы; вычисление от
новой высоты полоски создаёт обратную связь между CSS и камерой. Поэтому опорная высота всегда
принадлежит внешней рабочей области.

### 2. Размещение проекции без повторного вписывания

Фактическая высота canvas нужна для нижней привязки, обрезки и выбора клавиши, а не для повторного
уменьшения рассчитанных размеров. В 3D одна и та же опорная высота проходит через
`naturalNativeViewHeight`, `metricKeyboardCamera` и native camera layout; затем существующие
`dockKeyboardCamera`/смещение проекции размещают её в локальном прямоугольнике. Недостаточно
поменять только прямоугольники `viewGeometry`: повторное вычисление focal/fit от уменьшенного canvas
вновь уменьшит реальную модель.

При переносе проекции сохраняются сохранённые `camera`, `keysScale`, `keysLift`, `keysX/keysY` и
поза свободной камеры. Экранный render и обратное преобразование pointer picking используют
одинаковую окончательную проекцию. Для стабильности измеряются видимые белые и чёрные клавиши, а не
только CSS-высота контейнера. Изменение viewport допускает новый естественный размер, но последующее
переключение видимости на этом viewport вновь сохраняет его.

### 3. Доступное место и единая ручка стана

Режим применяется только при обычном пианино: стан доступен и показан, клавиши показаны, падающие
ноты скрыты; нет курса, печати, сравнения, транскрипции или второй нотной панели. `Workspace`
вычисляет этот признак для CSS-ограничений доступного места.

`StaffHandle` сохраняет прежнее поведение: однострочная ручка вызывает `onZoom` в пределах 50–200 %,
многострочная меняет `staffShare`. Поведение не зависит от телефона и видимости нот. Независимый
режим изменения пустой области вместо масштаба не вводится. Дорогой layout стана выполняется после
отпускания. Размер клавиш не изменяется при увеличении стана.

`Staff`/`fitHeight` сохраняют существующую естественную высоту по масштабу нот и целые строки
многострочного вида. Доступная область ограничивается рабочей областью за вычетом опубликованного
места клавиш и обычного зазора. На слишком низком окне доступна прокрутка стана, а настройки камеры
и масштаб клавиш не переписываются. Измерение доступного места публикует CSS-переменную без
отдельного React-состояния высоты стана.

CSS снимает мобильные caps только под явным признаком этого режима. Селекторы для обычной дорожки,
курсов, `course-score-stack`, печати и колонок сравнения сохраняются. Хранение использует
существующие zoom и `screen-layout.staffShare`; дефолты и проверка повреждённых значений
сохраняются, миграция формата не нужна.

### 4. Якорь FPS принадлежит видимой области

`FpsMeter` сохраняет существующий ticker и расчёт FPS. Для основной одиночной области его output
монтируется в позиционированный `.workspace-main`, а не в `.lane`. Небольшой метод перемещения якоря
либо явный необязательный anchor при создании позволяет обновить цель при переключении сравнения без
второго счётчика и новой подписки. При сравнении каждый output размещается в своей позиционированной
`.lane`; основной счётчик не накладывается на второй. CSS сохраняет отступ от мобильных кнопок,
`pointer-events: none` и правильный слой над станом.

## Risks / Trade-offs

- Цикл ResizeObserver/CSS/3D → опорная высота измеряется только у внешней области, публикация
  выполняется при изменении layout, повторное равное значение ничего не инвалидирует.
- Видимый прямоугольник стабилен, но сама модель уменьшилась → чистые тесты проекции и реальные
  замеры клавиш проверяют обе оси, сохраняют picking по центрам белой и чёрной клавиш.
- Ранний неизвестный размер/битое сохранение → конечные положительные значения, нормализация
  существующего layout и повторный расчёт после готовности модели; без записи derived-высоты в
  профиль камеры.
- Избыточный OSMD render при drag → перемещение только ручки во время жеста, один commit области
  после отпускания, без рендера нот на каждом кадре.
- Чужой режим получил новые caps → явный узкий признак режима и регрессии курсов/печати/сравнения.

## Migration Plan

Сначала строгая валидация и ревью этих артефактов; production-реализация начинается только после
подтверждения основного агента. Затем проверки, PR ветки в dev и отдельная пользовательская приёмка.
Основная папка на dev и сервер 5190 сохраняются. Откат PR возвращает прежнюю компоновку; музыкальные
данные и сохранённые профили не мигрируют.
