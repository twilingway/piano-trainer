# Design

## Context

База — dev a6d165b после #157. Roadmap и границы — proposal.md. PracticeSession группирует ноты
одинакового onset (допуск 30 мс), но wait засчитывает их по одной навсегда; noteOff не отменяет hit.
Это группировка партитуры, а не окно исполнения. ReadingSession/Prompt и useReadingCourse рассчитаны
на одну текущую высоту и двадцать ответов; ReadingPolicy видит down после обычной оценки. Pointer
binder и KeyboardLayer сейчас держат одну клавишу.

## Goals / Non-Goals

**Goals:** отдельная pure-политика пары, атомарная интеграция с одной PracticeSession, настоящий
мультитач, самостоятельный sibling прогресса без ветвления старого ReadingSession. **Non-Goals:**
новый аудио/нотный backend, универсальный движок аккордов, второй музыкальный clock, изменение
обычных chord/wait правил и переоценка P2.

## Decisions

### Генератор и два стана

Отдельные twoHandTypes/twoHandGenerator в src/reading задают skillId=two-hand-coordination,
task=simultaneous, generatorVersion=1. Генератор строит две квотные последовательности с
детерминированным исключением соседних одинаковых пар и MusicXML с явными staves/hands. Парсер
должен дать десять onset-групп, двадцать нот, точные диапазоны и обе партии. Solver используется по
существующим правилам, fingers скрываются проходом XML для задания. Проекция текущей пары сохраняет
оба связанных стана и общий cursor. XML/OSMD обновляются только при смене пары/помощи/размеров; не
на каждое событие и не в RAF. Альтернатива наложить два независимых одноставных курса создаёт два
предъявления и два зачёта.

### Pure парная сессия и журнал событий

TwoHandSession в src/reading принимает только явные события: презентация, активность, down/up, показ
помощи, текущий monotonic timestamp. Он хранит run/presentation/attempt identity, журнал физических
событий, квитанции помощи, активные интервалы и десять результатов. Часы не запускает; оболочка
передаёт now, PracticeSession остаётся владельцем song time. Поведение задано
specs/two-hand-coordination/spec.md, включая retry/full-release.

Raw используется для допуска после реального presentation receipt; corrected=raw−fixedOffset для
разброса/перекрытия. Offset фиксируется на начало попытки, источник, MIDI device/channel должны
совпасть у двух атак; origin не включает touch pointerId, но физическое владение включает. При смене
timing/выбранного input route через UI кандидат отменяется без ошибки, timestamps прежние. Атака
другого origin/device/channel внутри попытки даёт одну mixed-origin ошибку. Смена источника между
попытками допускается и сохраняется, внутри попытки — ошибка.

Принимается 0 <= received−raw <= 250. Bounded журнал переигрывается в порядке raw, deliverySequence
при равенстве. Старый ReadingAttackGate в callback-порядке не служит доказательством парного
удержания; его прежние callers не меняются. Предварительный успех на втором down не продвигает
песню. Финальность наступает после all-release и watermark now−250 строго позже последнего release;
до этого late off/down может отменить кандидат. Неполная попытка закрывается только при now >
firstRaw+450. Ошибка выдаётся ровно один раз; новая попытка начинается после подтверждённого полного
отпускания и нового admission boundary. Физическое up важнее педали. Raw до новой границы не
освобождает её новую атаку. Некорректные/дубли/stale события исключаются; журнал хранит snapshot
подтверждённого владения и tail горизонта 250 мс, максимум 256 событий; при переполнении кандидат
отменяется без успеха с сообщением. Доказательство попытки сохраняет необходимые down/up отдельно от
tail. Age251 off активного владения отменяет кандидат/reset input без зачёта и открывает
восстановление fresh boundary. Альтернатива финализировать по callback второго down ошибочно
засчитывает late off и третью ноту.

### Тонкая интеграция Trainer

Новый bounded pair-policy путь получает down/up до обычного pressKeyAt; аудио локальной клавиатуры
реагирует сразу, не ждёт оценщика. Существующие single-reading/rhythm/ordinary пути сохраняются.
После окончательного pure-успеха оболочка проверяет run/presentation и актуальные due noteIds и
атомарно подтверждает оба события в PracticeSession. Не отправлять их по одному в обычный wait при
первом down и не откатывать уже выставленные hits. Узкий pure API commit текущей ожидающей группы в
PracticeSession должен валидировать exact set текущих due IDs без subset/дубликатов и отсутствие
чужого перехода; при отказе никаких мутаций. Исходные времена атак остаются evidence парного
результата. Tests доказывают одну публикацию результата/продвижение и невозможность частичного hit.
Это исключает повторную timestamp-компенсацию и попытку оценить старую атаку обычным API после
горизонта доставки.

useTwoHandCourse в src/app владеет оболочкой; UI получает props. Множественная cue-проекция
отображает только реально подтверждённую текущую помощь. Stale async Staff callbacks отсекаются по
run/presentation, первая квитанция не стирается retry. Pause/hidden/seek/exit закрывают кандидат и
ресурсы, восстанавливают обычные настройки без auto-start. Альтернатива расширять useReadingCourse
очередными isTwoHand ветками закрепит одноголосные допущения и рискует превысить лимит модуля.

### Мультитач по всему пути

bindKeyboardPointer, KeyboardLayer, FallingNotesView и shell input используют единый registry
pointerId→pitch и счётчики владения pitch. Stage и sprite flat/road handlers проходят один маршрут;
down/up сохраняют исходный timestamp и pointerType. Перемещение указателя отпускает его прежнюю
высоту и нажимает новую; cancel/outside/cleanup отпускают его владение, blur/hidden все.
Cancel/cleanup/потеря capture сначала отменяют попытку, затем очищают владение: синтетические up не
доказывают full-release. Реальный pointerupoutside сохраняет physical up/timestamp и может завершить
попытку. Две pointer-атаки одной высоты не заменяют набор двух разных нот. Обычная мышь и drag
сохраняются, автоматического latch нет. Проверять оба активных представления клавиатуры и отсутствие
двойной доставки одного события. При отсутствии нужных custom bindings настройки не меняются;
знакомство показывает их и экранную альтернативу.

### Результаты, помощь и IndexedDB

Только отдельный TwoHandResult/агрегатор: попытки хранят down/up и причину, final outcome,
presentation/active intervals и помощь. Задержка решения измеряется до второго down успешной
попытки; момент окончательного commit после release/horizon хранится отдельно. Показанная помощь до
финальности делает пару несамостоятельной. Медианы отсутствуют при пустой выборке; source filter
выбирает пару по успешной попытке, сохраняя её прежние ошибки/помощь.

ReadingState schema 6 добавляет coordination={seed,generatorVersion,sourceFilter,history},
activeCourse=two-hand-coordination; ReadingPreferences общие. Валидатор повторно получает пары из
seed/version и проверяет все десять доказательств атаки/перекрытия/full-release, идентификаторы,
времена, помощь и метрики. Не доверяет сохранённому boolean correct без событий. Migration v1–v5,
changed-field atomic merge, runId dedupe/late hydrate сохраняют прежние siblings. Future/corrupt
блокируют destructive write; abort и quota оставляют память и исходные данные с ошибкой.
Альтернатива новая база повторит lifecycle и затруднит атомарность. Старые вкладки схемы 5 после
schema 6 должны отказать в записи; перезагрузка обновляет клиент без сброса данных.

## Risks / Trade-offs

- Дополнительная задержка финальности → предварительный статус и просьба отпустить, локальный
  звук/рисунок немедленно; тест delayed off и observable граница перехода.
- Мультитач меняет общий ввод → ownership/cancel/drag тесты и регрессия обычной игры двумя руками;
  проверить настоящий touch отдельно от синтетических событий.
- Узкий экран уменьшает клавиши → минимальные viewport 320×568/390×844/667×375, обе целевые позиции
  доступны одновременно, локальный scroll панели без body overflow.
- 200 мс — учебное решение, не научная граница освоения → явно описать в знакомстве/документации.
- MIDI/ПК не определяют руки и аппаратный rollover → без показателя правильной руки/пальца,
  физический ввод и слышимость остаются отдельной приёмкой.

## Migration Plan

Сначала согласовать конкретный proposal; затем реализовать задачи, reviewer, check/spec:validate и
PR в dev. Пользователь сливает; основная папка ff-only на dev, проверка прежнего 5190 без запуска
сервера. Rollback сохраняет базу, схема 6 не понижается и не стирается. Аппаратную приёмку и hidden
явно оставить открытыми до подтверждения; предшествующие P4a/P4b не архивировать лишь из-за
готовности нового плана.
