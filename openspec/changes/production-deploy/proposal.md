# Proposal

## Why

Сейчас Piano Trainer запускается локально и не имеет повторяемого выпуска на Mac mini M4. Нужен
публичный HTTPS-адрес и автоматический выпуск проверенного `main` по уже работающей схеме
Towerdefander. Основной адрес — `keys.twiling.ru` под имя Twiling Keys; первый адрес
`piano.twiling.ru` остаётся рабочим, потому что данные игроков привязаны к его origin.

## What Changes

- Публиковать собранный Vite-сайт на `keys.twiling.ru` и `piano.twiling.ru` через существующий Nginx
  Proxy Manager с TLS.
- Проверять pull request и `main` в GitHub Actions; Mac mini выпускает только коммит `main` с
  успешным CI.
- При неудачном выпуске сохранять работающую версию либо возвращаться к предыдущей.
- Описать первоначальную настройку и ручное восстановление.

## Capabilities

### New Capabilities

- `site-deployment`: доступность публичного сайта, правила выпуска и восстановления.

### Modified Capabilities

Нет.

## Impact

Добавятся конфигурация статического контейнера, CI, локальный агент выпуска macOS, документация и
запись в Nginx Proxy Manager. Игровая логика, состав хранимых данных и зависимости приложения не
меняются. Пользовательские песни и дубли остаются в браузере на неизменном origin. Внешние шрифты и
сэмплы, уже используемые приложением, остаются внешними запросами браузера; их доступность
проверяется при приёмке.

Цель — релиз после зелёного CI без входящего доступа к SSH из интернета. В область изменения не
входят серверное хранение песен, игровой режим техобслуживания и изменение существующих доменов
Towerdefander. Новых production-зависимостей нет; совместимость Web MIDI требует HTTPS и
Chrome/Edge.
