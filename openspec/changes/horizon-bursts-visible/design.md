# Размер экранного взрыва

## Context

Мотивация описана в proposal.md. `HorizonBurstLayer` уже получает координаты источника, цвет и
возраст взрыва. `noteArrival` вычисляет фазы из времени песни.

## Goals / Non-Goals

Цель — крупная яркая вспышка в обычном виде. Не менять проекцию, окно будущих нот, геометрию дороги,
свободную камеру или длительность анимации.

## Decisions

- Ограничить экранную ячейку диапазоном 160–240 px вместо 32–72 px. При исходной ширине клавиши
  масштабировать её в пять раз. Нижняя граница даёт светлую сердцевину примерно 32 px даже при
  сходящихся дорожках; верхняя ограничивает перекрытие. Масштабирование по перспективной ширине ноты
  отвергнуто: у горизонта она исчезающе мала.
- Применить существующее смешивание `screen`: вспышка осветляет фон, сохраняя цвет пальца.
- Не вводить новый pure-модуль: формула локальна единственному потребителю. Чистые фазы остаются в
  `noteArrival.ts`; слой только выбирает кадр и рисует его.
- Использовать прежний пул из 32 спрайтов и атлас из 15 кадров, без новых ресурсов и вычислений на
  ноту за пределами простого ограничения размера.

## Risks / Trade-offs

- Перекрытие вспышек в аккорде → ограничение размера и существующий предел 32 спрайта.
- Яркость зависит от фона → проверить светлый и тёмный фон в видимом браузере.
- Маленький экран → проверить 320×568 и альбомную ориентацию.
- Нотный стан не затрагивается; время песни остаётся единственным источником фазы.

## Migration Plan

Миграции нет. Откат — вернуть размер и смешивание в единственном слое.
