# Решения

## Context

См. proposal.md. MusicXML и PracticeSession сохраняют прежние роли. Глобальная видимость стана
сейчас игнорируется курсом, а вид курса имеет только tabs/staff.

## Goals / Non-Goals

Цель: единые команды и проверяемые ограничения доступа. Музыка не публикуется, серверы не
запускаются, зачёт и часы исполнения не меняются.

## Decisions

- Добавить optional `finalTask` — назначенную пару both/phraseId. По последнему заданию или названию
  нельзя достоверно определить целую мелодию. Старый урок без поля остаётся доступным по правилам
  цепи, но не открывает следующий.
- Чистые функции модели считают пройденные фразы этапа и проверяют актуальный зачёт финала каждого
  меньшего номера. Первый урок доступен при наличии проверенного содержания. Неизвестный или
  неподготовленный предшественник закрывает цепь.
- Один guard используется карточками, controller.open/continue/chooseStage, activeCourse и
  восстановлением. Заблокированное сохранённое задание не загружается; чужие и прежние отметки не
  удаляются. Завершение урока по всем этапам остаётся отдельным показателем от открытия следующего.
- Курсный вид расширяется до `tabs | staff | hidden`. Меню «Вид» и настройки получают одинаковые
  команды: нажатие активного представления скрывает его, включение другого заменяет его. Вид обычных
  песен и сравнение дубля не зависят от скрытой области курса.
- Панель курса содержит название, фразу, зачёт и явную кнопку следующего задания. Удаляются
  повторные кнопки рук и вида. Селект имеет постоянную ширину/высоту при заданном viewport,
  мобильная компоновка ограничивает его доступной шириной.
- Манифест первого локального урока получает финал whole/both; шаблон переноса описывает проверку
  финала.

## Risks / Trade-offs

- Исправление финальной партитуры закрывает цепочку → использовать существующий hash/version ключ;
  не стирать остальные зачёты.
- Старое сохранение без hidden → совместимое чтение прежних tabs/staff.
- Переключение вида вызывает перегрузку тренажёра → не связывать действие с выбором песни или этапа,
  проверить позицию и паузу.
- OSMD и кадровый цикл → считать прогресс только при изменении курса, не подписывать карточки на
  часы.
- Новый код не виден на пользовательском dev до слияния PR → проверить синтетические UI через
  существующий Vite, полную интеграцию проверить после слияния.
