# Постоянные метки октав

## Context

`KeyboardLayer` уже рисует наклейки в общей текстуре клавиатуры; она переносится на native top.
Существующие полные наклейки показывают имена и октавы на всех клавишах. Их переключатель нельзя
переиспользовать: начальные уроки специально выключают полные наклейки.

## Goals / Non-Goals

Цель — отдельные номера на C без изменения геометрии. Не вводить новый world-space renderer, новые
масштабы, подсветку, изменения MIDI или обновления React на каждый кадр.

## Decisions

- Чистый расчёт `pitch % 12 === 0` и `floor(pitch / 12) - 1` определяет наличие и номер. Фактический
  88-клавишный диапазон 21–108 содержит C1–C8; C0 не добавляется искусственно.
- Небольшой отдельный владелец меток рядом с `keyStickers`: запечь постоянный текст в текстуру,
  разместить спрайты при layout и уничтожить owned textures при destroy. Не раздувать
  `KeyboardLayer` за ESLint 500 строк.
- Прокинуть отдельный boolean через StaffPrefs и существующий applyLaneLook для основного и
  сравнительного видов. Использовать прежний persisted staff объект; нормализация missing→true,
  explicit false→false. Профили уроков сохраняют выбранное значение.
- Когда полные наклейки видны, отдельный слой скрыт: буква с октавой уже есть на полной наклейке.
  Это устраняет дубль, не меняя старый переключатель.
- Настройка и доступное имя идут через t() и каталог RU/EN. Обозначение C4 — международная
  музыкальная нотация; формат новой подписи тоже оформить через локализованный шаблон.

## Risks / Trade-offs

- 88 клавиш на узком экране → проверить реальные снимки и выбрать размер/место без наложения
  соседних C и цифр пальцев; не расширять физические клавиши ради текста.
- Смена layout/style → новый слой обновляет позиции и не оставляет старых подписей.
- Native texture path → проверить фактические 3D-ракурсы, а не только плоский слой.
- Кадровый цикл → никаких Text/Graphics или новых textures в update; OSMD не затрагивается.

## Migration Plan

Миграция хранения не нужна. Новый boolean нормализуется поверх существующих предпочтений.

## Уточнение после проверки на экране

Первая запечённая метка имела высоту около 6 px и не читалась. В плоском виде принята высота ячейки
до 18 px с ограничением реальной свободной поверхности; текст может умеренно выходить за ширину C,
поскольку между соседними до семь белых клавиш. Разметка клавиш не меняется.

Native UV берёт только собственную полосу клавиши с боковыми отступами. Широкая подпись в общей
текстуре разрезается; простой предел ширины, наоборот, снова делает её нечитаемой на 390 px. Поэтому
native-вид использует небольшой экранный слой спрайтов поверх существующего финального прохода
ThreeKeysHost. Источник — те же заранее запечённые текстуры, с одним владельцем destroy. Сами
камеры, шейдеры и renderer не меняются.

Точный якорь берётся из фактической C-клавиши и её текущего hinge/dip; используется выбранная
ThreeStage камера клавиатуры (включая свободный и сценический виды), актуальная matrixWorld и
NDC→экран. Отсекаются отсутствующие UV, скрытые клавиши и точки за камерой/вне viewport. Новый слой
не участвует в picking, не дублируется в baked native paint и скрывается при fallback. Его экранный
размер не зависит от ширины одной физической клавиши; рядом стоящие C не пересекаются.

Обычная цифра пальца сохраняет прежнее положение. Только для C при включённых отдельных метках и
выключенных полных наклейках её максимальная высота ограничивается оставшимся местом под полосой
метки и небольшим зазором. На узкой C прежняя небольшая цифра не уменьшается. Native-якорь метки
отдельно проверяется с активной цифрой пальца.

Обычный номер пальца и учебный бейдж — разные пути. Учебный П1/Л1 имеет приоритет: пока уже
разрешённый fingerCue рисует бейдж на C, отдельная метка этой C временно не показывается ни в
плоском, ни в native слое. Размер бейджа и правила разрешения подсказок не меняются. После удаления
cue метка возвращается; данные берутся из уже разрешённых frame.fingerCues, а не выводятся заново по
pitch или raw MIDI.

Высота native якоря — box.top + текущий hinge dip: исходный key mesh имеет локальный top=0, а
mesh.position.y=22 уже учтён в box.top. Повторное добавление 22 не допускается; тест должен
сравнивать с фактической белой поверхностью, а не повторять ошибочную формулу.
