# Design

## Context

Исходный экран и причины тесноты описаны в proposal.md. Изменения относятся только к курсу.

## Goals / Non-Goals

Цель — одновременная доступность нот, клавиш и действия. Оценивание, партитуры и обычная игра
сохраняют прежнюю семантику; не создаются новые песни или универсальные позы всех пальцев.

## Решения

Компактный профиль определяется шириной окна ≤1024 CSS px; desktop — большей шириной. Поворот и
изменение размера меняют только отображение. Диапазон desktop: raw fixed preference либо 88 для
`song`; compact: диапазон learner material без accompaniment. Высотный бюджет клавиатуры задаётся
отдельно от displayRange и продолжает действовать на desktop. Изменение профиля не сохраняет
временные значения и не перезапускает попытку.

У курса собственная компактная композиция: строка выхода/прогресса/меню, короткая цель, область
персонажа и стана, одно основное действие. Длинная исходная инструкция, повтор показа, скорость,
настройки, язык и fullscreen доступны из меню/подсказки. Скорость меняется до попытки по прежним
правилам; открытие глобальных настроек соблюдает действующий протокол остановки. Меню возвращает
фокус, закрывается Escape и нажатием снаружи. В обычной игре остаётся прежняя панель.

В 667×375 и 320×568 главный стан и клавиатура видны без прокрутки стартовой карточки. При нехватке
места сначала убираются декоративные персонажи, затем используется компактное размещение статуса;
информация об удержании, ошибке и результате не скрывается. Общий масштаб партитуры и его
предпочтение не изменяются ради сокрытия ошибки раскладки. Teacher-slot допускается только при
height≥640 и height>width; его ограниченный размер не вытесняет стан. На desktop допускается
полноценный инструмент при сохранении компактной высоты.

## Данные и время

Чистый mapper в `src/songCourse/characterPresentation.ts` выбирает позу и эмоцию из уже принятых
событий/времени, не оценивает исполнение. Controller/тонкий адаптер публикует визуальное состояние
на существующих onFrame/onInput. Проверяются presentationId, runId, sourceHash и идентичность
learner-note; stale callback не меняет новую картинку. Палец читается из song.notes по
runtimeNoteId. Учитель показывает только exact C4/1, D4/2, E4/3 правой руки. Показ demo основан на
[start,end), ответ ученика — на принятом физическом удержании; ошибки, accompaniment, другие октавы
и пальцы не превращаются в подтверждённый контакт. В паузе, rehold, hidden и после release
используется нейтральная поза. Новая генерация нейтрального кадра проходит проверку прозрачности и
геометрии; если пригодного кадра нет, нажатая поза скрывается, а не остаётся ложным удержанием.

Растровые персонажи восьмых — отдельные компаньоны только guided-контекста, не замена головок
партитуры. Existing SVG сохраняет полость, штиль, флажок и длительность. Independent/performance не
показывает персонажа ожидаемой высоты. Эмоции читаются из существующего feedback-канала, не создают
результат. Декоративное время CSS/RAF допускается только для кадров эмоции; оно не продвигает песню.
При reduced-motion показывается статичная эмоция. Hidden останавливает декорацию, mute не скрывает
результат, отсутствие рисунка оставляет рабочие ноты и действия.

## Производительность и границы

Атласы загружаются только при использовании персонажей и не перезагружаются на ноту; исходные
генерации не входят в runtime imports. Не подписывать весь player React tree на каждый кадр. Никаких
новых библиотек, таймеров музыкального времени и изменений pure session/recording core.

## Risks / Trade-offs

Компактный диапазон временно перекрывает сохранённый фиксированный выбор: это объясняется в меню
урока. Непригодный нейтральный рисунок приводит к скрытию учителя и не задерживает компактную
оболочку. Смена canonical target немедленно возвращает neutral и может прервать короткую реакцию;
одинаковый feedback/rerender её не перезапускает. Runtime использует только512×544 кадры из
teacher/sheets/ и нормализованный idle, а не исходные1536px изображения генерации.

## Приёмка

Видимый браузер: 320×568, 390×844, 667×375, 768×1024, 1024×768, 1920×1080; дополнительно 200% zoom.
Проверить ready/demo/playing/wait/hold/pause/result, краткое меню и полную инструкцию RU/EN,
Tab/Enter/Escape, смену ориентации без новой попытки, правильный target и отказ изображения.
Проверки: узкие unit/component tests, `pnpm check`, `pnpm spec:validate`, независимое review.
