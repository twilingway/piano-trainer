# Design

## Context

Звук стартует из первого pointerdown/keydown и отдельно из команд исполнения. Основной Play уже ждёт
boolean readiness через отсчёт; старый ensureSound возвращает void даже после отказа.
ToneAudioBuffers сейчас сам загружает MP3. Смена рук заменяет PracticeSession и заново передаёт
неизменный Song визуализации, включая sprites и план 3D-рук.

## Goals / Non-Goals

Цель — видимая подготовка с правдивыми стадиями, без потери исходного действия, прежней позиции и
отмены. Не меняем звуковые файлы, чистую музыкальную логику, шкалу оценки и стартовый HTML-лоадер.

## Decisions

- Единственный audio-owner хранит per-file pending/decoded cache и immutable snapshots. React
  подписывается через useSyncExternalStore, предпочтения остаются в существующем Redux.
- Размеры 120 фактически публикуемых MP3 вычисляются при dev/build из public. 30 файлов v10
  обязательны (сейчас 2 926 230 Б), прочие 90 (8 537 867 Б) загружаются фоном. Сеть/кеш не выдаются
  за одно и то же: UI показывает полученное содержимое; сетевой трафик допустим только из измерения.
- Один fetch с чтением stream и decodeAudioData на файл, готовый AudioBuffer передаётся Tone. Нельзя
  предварительно скачать и снова дать Tone URL. Нельзя ждать ToneAudioBuffers.onload для готовых
  AudioBuffer: используем собственное завершение загрузки/декодирования.
- Tone.start вызывается в исходном жесте. Автоматический прогрев показывает неблокирующий статус,
  чтобы не поглотить initiating pointerup/click. Явно ожидающая звук операция повышает тот же
  прогресс до фортепианной панели подготовки; отмена остаётся доступной. Ошибка не запускает игру.
- Отмена снимает намерение конкретного потребителя, общий кеш и полезная загрузка сохраняются.
  Повтор готовит недостающие файлы, не запускает старое отменённое исполнение.
- Подготовка партии публикует busy и даёт браузеру отрисовать его до синхронной работы. Поколение
  запроса защищает смену песни, быстрый новый выбор, размонтирование и запоздалое завершение.
  Занятие снимается после кадра актуальной конфигурации; скрытый/недоступный renderer не вешает UI.
- До оптимизации измеряем load/session, NotesLayer и план рук. Identity-cache может пропускать
  только неизменную подготовку; замена PracticeOptions, очистка FX/поз, дубля и прежняя семантика
  позиции сохраняются. Во время ожидания clock PracticeSession приостановлен; второго clock нет.
- Первая загрузка сессии не открывает поздний modal до начального HTML-индикатора. Тёплый звук
  возвращает готовность без foreground-панели; повтор фоновых слоёв остаётся фоновым. Любой
  autostart и resume проходит общий audio-readiness gate, начатый исходным жестом; ожидание после
  кадра не пытается впервые разблокировать AudioContext.
- CPU показывает неопределённый индикатор, без выдуманных процентов. Компактная панель и действия
  помещаются на 568×320/667×375, RU/EN добавляются одновременно. Дополнительный звук не закрывает
  игру.

## Risks / Trade-offs

Старые void-caller пути требуют явного обработки отказа без unhandled rejection. Общий кеш нельзя
отменять одним потребителем. Синхронный JS может остановить анимацию индикатора, но первый paint
должен произойти заранее. Удержанные клавиши, звучание и дубль очищаются прежним владельцем. Нельзя
переиспользовать hand-plan по новым массивам, игнорируя изменения immutable Song.

## Validation

Управляемые fetch/decode тесты: холодный/тёплый кеш, shared callers, ошибка одного файла и повтор,
100% байтов до декодирования, фоновая ошибка. Компонентные tests: инициирующий Play не потерян,
нулевой отсчёт ждёт звук, отмена/поздний promise, быстрый выбор рук и смена песни. Видимый Chrome:
замедленная сеть и искусственная задержка CPU, стадия видна до работы, новый кадр после неё,
компактные RU/EN окна. Полные pnpm check, pnpm spec:validate и независимое ревью.
