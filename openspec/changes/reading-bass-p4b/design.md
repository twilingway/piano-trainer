# Design

## Context

База — dev cc9a3a2 после PR #155. Мотивация и границы — в proposal.md. Текущий
src/reading/generator.ts закрепляет C4–G4, скрипичный ключ и пять тактов. READING_PRACTICE_OPTIONS и
useTrainer закрепляют правую руку. Простое переключение руки не создаст нужную левую партию:
MusicXML должен явно содержать её. P2 progress/adaptation обходят прежние пять высот; басовые
результаты нельзя направлять в их профиль. ReadingState и readingMigration поддерживают схему 4,
intervals/rhythm и атомарное обновление через существующий ReadingRepository.

## Goals / Non-Goals

**Goals:** переиспользовать чистые оценку, предъявление, помощь и ввод чтения с явным профилем
упражнения; гарантировать басовый ключ/левую партию и изолированные данные.

**Non-Goals:** универсальная платформа всех будущих упражнений, второй clock, новый
audio/render/input backend, изменение политики P2 и расширение P4a.

## Decisions

### Профиль чтения в чистом модуле

В src/reading явный профиль задаёт id, MIDI-высоты, written octave/clef и руку. Прежний профиль
остаётся C4–G4/right/G; новый — C3–G3/left/F. Генерация seeded порядка и XML параметризуется
профилем, прежние seed/версии/XML P1/P2 не меняются. Басовое упражнение имеет отдельные id и
generatorVersion=1, без ReadingPlan P2. MusicXML парсится один раз; результат проверяется на
двадцать left-событий. Существующий парсер назначает единственную партию по handByPitch с границей
MIDI 60: все пять выбранных басовых высот ниже неё. Дополнительного remap рук для этого среза не
нужно; тест фиксирует эту границу. Solver работает с левой партией; его пальцы скрыты в задании.
Альтернатива UI-only hand switch не задаёт ключ и маршрутизацию.

### Общая оценка, отдельный контракт результата

ReadingSession остаётся чистым механизмом оценки предъявления/ответа/помощи. Общие evidence-типы
допускают явный skillId; прежнее значение по умолчанию сохраняется для legacy и всех старых callers.
Басовый result имеет отдельный дискриминант bass-note-reading и task notes/phrases. В P2 reducers и
adaptation проходят только прежние note-reading результаты. Отдельный чистый агрегатор либо
параметризованная общая часть строит сводку по C3–G3 без дублирования алгоритмов. Идентификаторы,
времена первой атаки/решения и показанная помощь сохраняются; median самостоятельных первых задержек
отсутствует при пустой выборке. Альтернатива складывать всё в ReadingResult/P2 скрыла бы басовые
наблюдения.

### Runtime и UI подключают профиль

Профиль формирует wait-options с выбранной рукой, без accompaniment и обычного take. PracticeSession
остаётся единственными музыкальными часами; монотонные timestamps только измеряют активные интервалы
ответа. Порядок допуска сохраняет исправление #153: предъявление не раньше фактического
подтверждения оболочкой, stale callbacks отсекаются. Существующие нейтральные клавиши и guidance
скрывают помощь до её реального показа. Экранное пианино обязательно показывает C3–G3. Компьютерный
ввод сохраняет существующие bindings и octave/modifier controls: реальная сыгранная высота поступает
без remap по ожидаемой ноте. Знакомство показывает действующие назначения и путь выбора подходящей
раскладки в обычных настройках. Если custom bindings не содержат нужных нот, гарантированным
локальным вводом остаётся экранное пианино. Предпочтения ввода автоматически не меняются. Пресс до
due/предъявления, held duplicate и callbacks чужого run не оцениваются.

Карточка и знакомство используют существующий каталог курсов; hook в src/app соединяет профиль и
состояние, UI получает props. Знакомство отдельно показывает позицию пальцев 5–1; в упражнении
пальцы скрыты. Задержка фразы подписана как время последовательного ответа на заранее видимые ноты,
а не время одиночного распознавания. Общие ReadingPreferences используются обоими курсами; фильтр
источника басовой сводки отдельный. Каждая новая player-facing строка одновременно получает t() и EN
каталог.

### Сохранения: схема 5 и bass sibling

ReadingState расширяется bass-состоянием: task, seed, generatorVersion, sourceFilter и history.
activeCourse включает bass-reading. Двадцать результатов на notes и двадцать на phrases; сводки
описывают именно это окно, без обещания пожизненной статистики. Миграция v1–v4 добавляет пустой
sibling без переписывания P2 profile, fingerprints, intervals и rhythm. Валидатор басового
результата проверяет дискриминант, высоты, квоты и согласованность завершённых ответов.

Ключ reading-course-v2 в прежней IndexedDB не меняется. changed fields, localProgressSince и
атомарный merge получают bass, идемпотентность runId и late hydrate guards. Незавершённые
ответы/runtime не сохраняются. Ошибка чтения блокирует destructive write; неизвестная версия не
нормализуется в пустое сохранение для записи. Альтернатива отдельной базы ухудшает атомарность и
повторяет persistence lifecycle.

## Risks / Trade-offs

- Одноставный F clef может определять не ту руку → XML/Song unit tests и полный проход доказывают
  left и отсутствие автоаккомпанемента; обычный two-hand Song остаётся прежним.
- Скрытые пальцы/подсветка могут раскрыть ответ → tests guidance и проверка реального стана/клавиш.
- Общий оценщик может задеть P1/P2 → регрессии прежних seeded XML, правильной/неверной атаки, active
  intervals, помощи, адаптации и сохранений до интеграции.
- OSMD rebuild на каждом ответе дорог → переиспользовать нынешнюю границу текущей ноты/четырёхнотной
  фразы, не генерировать XML и не создавать аудиоресурсы в RAF.
- MIDI не определяет руку/палец → явно говорить об этом в знакомстве; не выдавать показатель
  правильной руки.
- Физическое MIDI и слышимость не проверяются mock-тестами → отдельная приёмка, не объявлять
  неподтверждённое выполненным.

## Migration Plan

После согласования реализовать группы tasks на отдельной ветке от свежего dev, пройти reviewer, pnpm
check/spec:validate и PR в dev. После пользовательского merge ff-only обновить основную папку и
проверить существующий 5190 без запуска сервера.

При первом чтении мигрировать в памяти, записывать лишь допустимый atomic merge. Старые вкладки
после схемы 5 перезагрузить: версия со схемой 4 должна блокировать запись новых данных. При откате
сохранить базу; не преобразовывать схему 5 обратно разрушительно. Legacy localStorage остаётся
резервной копией, не местом новых басовых результатов.

## Согласование

контракт, в реализацию не перенесено.
