# Дизайн: общее хранение курсов чтения

## Context

`intervalPersistence`, `rhythmPersistence`, `bassPersistence`, `twoHandPersistence`,
`heldBassPersistence`, `independentRhythmPersistence` повторяют гарды, нормализацию и слияние
истории. `readingCourseMigration`, `mergeReadingState` и `changedReadingFields` перечисляют курсы
вручную.

## Decisions

1. `src/app/courseStore.ts`: `normalizeCourseState` (проверка объекта, `generatorVersion === 1`,
   проверка истории, парсеры полей, где `undefined` значит «невалидно, значение по умолчанию») и
   `mergeCourseHistory` (опции `validate`, `distinctIds`, `groups`, `copy`). Опции повторяют
   нынешние различия курсов: ритм и интервалы не валидируют при слиянии; дедупликация по `id` только
   у двух рук, держаного баса и независимых ритмов; бас и интервалы держат по 20 на группу.
2. Курсовые модули сохраняют все экспорты и сигнатуры; слайс и тесты не меняются.
3. Реестр `READING_COURSE_STORES` в порядке курсов: ключ, id курса, первая версия схемы,
   нормализация, слияние истории, поле выбора (с учётом selectionRevision или без), поля
   предпочтений, условие возобновления курса. Миграция, слияние вкладок и список изменённых полей
   проходят по реестру; порядок полей в списке прежний.

## Ownership

Правила валидности результатов остаются в курсовых модулях; хелпер владеет только общим каркасом.

## Risks

- Тонкие различия курсов (seed без верхней границы с `>>> 0` у ритма и интервалов, сброс `task` и
  `mode` при чужой версии генератора) теряются при обобщении. Митигация: они задаются парсерами
  полей, тесты хранения каждого курса и миграции остаются приёмкой.
