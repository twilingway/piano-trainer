# Design

## Context

Мотивация в proposal.md. Сейчас единая сетка включает 4 + 24 удара с периодом 600 мс. Сопоставление использует ближайший удар и допуск ±45% периода.

## Goals / Non-Goals

Цель: добавить время подстройки, сохранив исходные timestamp и критерий завершения 4/4 + 24/24. Не менять анализ median/MAD, периоды, поправки, профили и PracticeSession.

## Decisions

- Чистый CalibrationSession владеет классификацией: T(n)=T0+n×600 мс, n=0..2 вступление, 3..6 разминка, 7..30 замер. Вступительные нажатия не входят в samples или дедупликацию разминки.
- Сохраняется окно ±270 мс: T3−100 принимается как ранняя разминка; T2+250 остаётся вступлением. Проверка raw < T3 запрещена, поскольку потеряет корректное раннее нажатие.
- useCalibration владеет таймерами и этапом preparation/lead-in/warmup/measurement. Переходы по расписанию, не количеству принятых нажатий; warmup/measurement начинаются с открытия соответствующего окна.
- UI только показывает этап и счётчики; все новые строки RU/EN через t().
- Уход с раздела синхронизации отменяет запрос запуска, таймеры и запланированные звуки через существующий onCancel. Старые callbacks не сохраняют результат после отмены.
- Не вводить новый таймер кадра или нагрузку на staff: несколько одноразовых таймеров на запуск.

## Risks / Trade-offs

- Пограничные и отложенные события → тесты исходных timestamp, раннего первого warmup и позднего intro.
- Больше длительность → инструкция явно отделяет 3 вступительных, 4 разминочных и 24 измерительных щелчка.
- Пропущенная разминка → результат остаётся неполным, прежний профиль не перезаписывается.

## Migration Plan

Миграция не требуется. При откате возвращается прежний запуск 4 + 24 без изменения сохранённых профилей.
