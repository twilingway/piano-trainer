# Семантические поля левой руки: запись и повторное чтение

## Why

Диагностическое сохранение literal631 само по себе не доказывает сохранение native LEFT полей. Нужна
отдельная проверка происхождения, реальной интерполяции и повторного чтения этих полей, прежде чем
обсуждать дальнейшие физические проверки рук.

## What Changes

- Только приватная копия успешно сохранённой и независимо принятой diagnostic-сцены.
- Один набор из 11 новых POINT/FLOAT полей LEFT: кисть, пять pads и пять непрерывных finger weights.
- Проверка исходных значений, actual evaluated полей, ROW correspondence и сохранения/reopen.
- Полная сохранность прежних данных; любой mismatch даёт FAILED без физического допуска.

## Goals / Non-Goals

Цель — воспроизводимый semantic readback proof. В задачу не входят новые позы, контакт, nails, arm
baseline, анимация, экспорт, Three.js loader, интерфейс, музыка или production-данные.

## Capabilities

### New Capabilities

- `pianist-left-semantic-readback`: диагностический контракт происхождения и сохранения LEFT полей.

### Modified Capabilities

Нет: контракт игровых живых рук не изменяется.

## Impact

В Git входят OpenSpec и текстовые результаты. Python, массивы, модели и .blend остаются ignored.
Новых зависимостей, лицензий, пользовательских настроек и внешней публикации данных нет.
Материальные продуктовые решения не вводятся. `physical_class=null`, `calibration=null`,
`eligible_for_write=false`, `serialization_ready=false` сохраняются при любом результате.
