## Context

`PracticeSession` делит ноты песни на `playerNotes` и `autoNotes` по одному признаку
`options.hands.has(note.hand)` (`src/practice/session.ts`). Тот же признак независимо повторён в
звуке аккомпанемента (`src/audio/sessionAudio.ts`), в отрисовке (`NotesLayer`, `FallingNotesView`:
сгорание, удары, прокрутка) и в разборе дубля (`src/recording/compare.ts`). Настройка вида «Клавиши»
(`KeyRange` в `useFallingView.ts`) влияет только на экранную клавиатуру. Ввод MIDI и компьютерной
клавиатуры проходит через `useKeyInput`, у которого уже есть `intercept`. Транспозиция песни —
состояние `transpose` в `useSong` в пределах ±11 и сбрасывается со сменой песни. Мотивация — в
proposal.md.

## Goals / Non-Goals

**Goals:** один чистый признак «нота за игроком» для сессии, звука, вида и разбора; поведение
покрыто тестами сессии и разбора без DOM.

**Non-Goals:** переделка `HandsLayer` (картинки рук не зависят от диапазона), изменения нотного
стана, новый стиль нот.

## Decisions

### D1. Признак владения нотой живёт в практическом ядре

`src/practice/playableRange.ts` экспортирует тип `PlayableRange { low; high }` (MIDI-номера,
включительно) и чистую функцию `ownsNote(note, hands, playable?)`; отдельный модуль, потому что
`session.ts` упирается в лимит 500 строк. `PracticeOptions` получает необязательное `playable`.
Сессия строит `playerNotes`/`autoNotes` через `ownsNote` и даёт метод `owns(note)`. Всё остальное
(счёт, удержания, аккорды, ожидание, `keyHints`, финиш) уже работает от `playerNotes` и меняться не
должно — поэтому вся логика правила живёт в одной точке.

Альтернатива — фильтровать песню (вырезать ноты из руки игрока, переложив их в другую руку).
Отвергнуто: сломало бы цвета рук, пальцы и стан и разошлось бы с разбором дубля.

### D2. Потребители спрашивают сессию, а не руки

- `sessionAudio` заменяет `options.hands.has(note.hand)` на `session.owns(note)`.
- `FrameState` получает `owns: (note) => boolean`; `NotesLayer` и `FallingNotesView` (сгорание,
  удары, прокрутка) используют его вместо `state.hands.has(note.hand)`. `hands` в `FrameState`
  остаётся для `HandsLayer` и «есть ли игрок вообще». Trainer передаёт `session.owns` как ссылку на
  связанный метод, созданный один раз на сессию — без новых замыканий в каждом кадре.
- `Take` получает необязательное `playable`; `TakeRecorder` пишет его из опций сессии, `compareTake`
  фильтрует ноты через `ownsNote`. Нет поля — нет ограничения, старые дубли не меняются.

### D3. Модель диапазона — чистый модуль ввода

`src/input/deviceRange.ts` (чистый): пресеты, `parseDeviceRange(unknown)` с проверкой
`21 ≤ low < high ≤ 108`, `rangeCaptureStep(state, pitch)` — автомат захвата
(`idle → awaitingLow → awaitingHigh → done`, повтор первой клавиши игнорируется),
`outsideCount(notes, hands, range)` и `bestOctaveShift(notes, hands, range)` (перебор −2…+2, строго
меньше нот вне диапазона, при равенстве меньший |сдвиг|). Хранение —
`src/app/deviceRangePreferences.ts` по образцу `keyboardPreferences.ts`, ключ `device-range-v1`.

Пресеты (крайние ноты как у распространённых инструментов; захват поправляет октавный сдвиг
контроллера):

| Клавиш | Диапазон | MIDI   |
| ------ | -------- | ------ |
| 88     | A0–C8    | 21–108 |
| 76     | E1–G7    | 28–103 |
| 61     | C2–C7    | 36–96  |
| 49     | C2–C6    | 36–84  |
| 37     | C3–C6    | 48–84  |
| 25     | C3–C5    | 48–72  |

88 клавиш означает «без ограничения»: в опции сессии попадает `undefined`, а не 21–108, чтобы ноты
за пределами фортепиано (в MIDI-файлах бывают) по-прежнему оставались за игроком.

### D4. Где применяется диапазон

`useTrainer` добавляет `playable` в `practiceOptions` только при игре за пианино: не при
прослушивании, не в словесном режиме и не в Ranked. Объект диапазона мемоизируется по `low/high`,
иначе каждая отрисовка React перезагружала бы прогон (`trainer.load` срабатывает на смену опций).
Смена диапазона перезагружает прогон так же, как смена рук.

### D5. Захват через существующий `intercept`

Хук `useDeviceRange` держит диапазон, состояние автомата и отдаёт функцию для
`useKeyInput(…, intercept)`. Пока захват активен, `intercept` поглощает нажатия (`true`) и кормит
автомат; отпускания нажатых при захвате клавиш тоже поглощаются, даже после его конца, чтобы прогон
не получил «висящих» отпусканий. Раздел «Пианино» отменяет захват при размонтировании: закрытие
настроек или переход в другой раздел прекращают его без отдельной проводки в `App`. Компьютерная
клавиатура при этом продолжает звучать — это полезная обратная связь.

### D6. Октавный сдвиг — отдельное состояние песни

`useSong` получает `octave` (−2…+2), сбрасываемый вместе с `transpose`; песня строится с
`transpose + 12·octave`. Отдельное состояние нужно, потому что ступенчатые кнопки тональности
ограничены ±11, а список тональностей вычисляет сдвиг через `shiftBetween` и стёр бы октаву.
`transposeMusicXml` для кратных 12 не меняет ключевые знаки и только переносит `<octave>` — это
закрепляется тестом. Заголовок получает итоговый сдвиг, как сейчас. Раздел «Песня» показывает
текущую октаву с кнопками ±1, иначе сдвиг по подсказке нельзя было бы вернуть. Подсчёт и подбор
сдвига — `useRangeFit` рядом с `useDeviceRange`.

### D7. Предупреждение Ranked

`GameSettings` (там переключатель Ranked) показывает подсказку, когда диапазон не 88 и
`outsideCount` по текущей песне и рукам больше нуля. Само правило — в D4.

## Risks / Trade-offs

- [Изменение `FrameState` трогает все места, рисующие кадр, включая зеркало сравнения] → зеркало
  передаёт `session.owns` той же сессии; тесты `FallingNotesView` получают `owns` из рук.
- [Кадр: лишний вызов функции на видимую ноту] → два сравнения чисел; кадр уже обходит те же ноты,
  заметной стоимости нет. Нотный стан не затронут.
- [Октава ±2 уводит ноты далеко за стан] → OSMD рисует добавочные линейки; сдвиг только по кнопке.
- [Поправки пальцев привязаны к песне в тональности] → сдвинутая песня получает свой набор поправок,
  как при транспозиции; это ожидаемо.
- [Нет железа для проверки] → тесты сессии, разбора и автомата захвата; ручной прогон с компьютерной
  клавиатуры при суженном диапазоне. Поведение на реальном 25/61-клавишном контроллере остаётся
  непроверенным.

## Migration Plan

Новый ключ хранилища, по умолчанию без ограничения; старые дубли без `playable` разбираются как
раньше. Откат — удалить ключ, поведение вернётся к прежнему.
