# Design

## Context

См. proposal.md. Сейчас каждая фраза обязательна на каждом этапе, а контроллер выбирает фразы из
общего списка.

## Goals / Non-Goals

Цель — одна чистая последовательность заданий для навигации и зачёта. Часы, музыка, записи и
renderer не меняются.

## Decisions

- `CourseLesson.tasks` — необязательный упорядоченный список `{phraseId, stage}`. Без него
  используется прежнее произведение этапов и фраз. Не создаём дополнительные типы сложности и
  фиктивные одноручные задания координации.
- Чистый model вычисляет последовательность и фразы конкретного этапа. `resolveSelection` отвергает
  отсутствующую пару, включая восстановление сохранённого выбора. Зачёт и карточки читают тот же
  список.
- Catalog отвергает пустой, повреждённый, повторяющийся или неполный список: все объявленные этапы и
  фразы должны встречаться, ссылки должны существовать. XML проверяется на наличие рук только для
  назначенных этой фразе этапов.
- Необязательное название фразы показывается существующим локализованным dropdown. Фразы независимых
  упражнений не склеиваются: целая песня получает отдельный XML с исходными паузами, басами и
  лигами.
- Музыкальное время пропорционально длительностям партитуры:
  `seconds = quarterBeats * 60 / quarterBpm`. Атаки каждого исполнения сопоставляются отдельно;
  фиксируются единица BPM, ошибка подгонки и учебный темп. Неопределённые note-off и метр упражнения
  записываются как редакционные решения в локальном evidence.

## Risks / Trade-offs

- Старый клиент игнорирует tasks → подключать проверенный манифест после слияния кода в dev; до
  этого хранить подготовленный манифест отдельно.
- Бас фразы может продолжаться за границу мелодии → сохранить хвост баса в самостоятельном
  упражнении и проверять целую песню отдельно.
- Учебная сетка сглаживает rubato → сохранять измеренные атаки и выбранную пропорцию, не выдавать
  сетку за точное исполнение автора.
- Обработка небольшого списка вне кадрового цикла не добавляет работы renderer или OSMD на каждом
  кадре.

## Migration Plan

Проверить старые манифесты и синтетический смешанный порядок тестами. Подготовить локальные XML и
receipt, затем после слияния PR активировать локальный манифест и проверить на существующем стенде.
Откат локального подключения сохраняет XML и прогресс.
