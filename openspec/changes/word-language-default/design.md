## Context

Текущий адаптер сохраняет язык вместе с любыми настройками режима, не различая ручной выбор и
исходный RU. Прямое чтение locale для worker меняет раскладку посреди текущего исполнения.

## Goals / Non-Goals

Цель: отделить ручное предпочтение текста от автоматического языка интерфейса. Вне задачи:
собственные игровые часы, изменение генератора, UI автоматического режима и сброс остальных данных.

## Decisions

- В существующий объект добавить `languageManuallyChosen`. Только изменение языка текста
  пользователем выставляет true; изменения остальных предпочтений сохраняют маркер.
- Чистые функции нормализации и обновления рядом с адаптером получают данные и язык интерфейса.
  Чтение localStorage и интерфейсного store остаётся в оболочке. Старый RU становится auto, старый
  EN — manual: миграция согласована пользователем.
- Синхронизация React подключается после snapshot тренажёра в App как отдельный хук композиции. При
  playing=true эффективный язык не меняется, после паузы auto следует locale.
- Автоматическая синхронизация меняет только состояние, без записи языка как ручного. Один
  prefs.language используется для кеша, worker, tokens и клавиатуры.
- Ручной выбор и текущий активный прогон независимы от интерфейса. Вместо запрета кнопки HUD
  фиксируем только язык текста на время исполнения: интерфейс переключается сразу.

## Risks / Trade-offs

- Старый ручной RU неотличим от автоматического → согласованная миграция; новый ручной выбор
  однозначен и сохраняется.
- При смене языка нужна новая генерация → worker выполняется после паузы, ввод заблокирован до
  результата, игровой счёт не сбрасывается.
- Запрещённое хранилище → выбор остаётся в памяти; тесты отказа чтения/записи.
