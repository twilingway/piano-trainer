# Design

## Context

Причины описаны в proposal.md. App содержит большой массив JSX вкладок. Настройки принадлежат существующим хукам. Режим ожидания и прослушивание не используют учебное окно независимо от сохранённого флага.

## Goals / Non-Goals

Выделить композицию настроек, сгруппировать существующие компоненты и показывать достоверный статус. Часы, очки, калибровку и формат предпочтений не менять.

## Decisions

- PlayerSettings составляет панели из существующих компонентов и переданных свойств; App остаётся композицией. Это уменьшает связанность без переноса состояния или обобщённого конструктора настроек.
- SettingsPanel сохраняет выбранный раздел и обеспечивает навигацию; на desktop список слева, на телефоне компактная навигация над содержимым. Содержимое прокручивается, закрытие доступно.
- Чистая функция определяет политику по PracticeOptions: пустые hands означают прослушивание, wait — ожидание, иначе learning/strict. Trainer публикует её в snapshot. UI не выводит учебный режим из одного сохранённого предпочтения.
- Статус расположен рядом с механикой игры, чтобы оставаться видимым независимо от компоновки HUD и скрытых нот/клавиатуры. Подробности допуска доступны в подписи/подсказке.
- Все existing controls сохраняются; настройки пианино и синхронизации завершают список. Не скрываем технические разделы при смене механики, чтобы не менять текущие профили устройств.

## Risks / Trade-offs

- Длинные панели → внутренний скролл и проверки phone/landscape.
- Прослушивание и ожидание → pure policy тесты и тест wiring Trainer.
- Изменение группировки → тест структуры разделов и ручная проверка обеих механик.
- Старый активный player-ui описывает прежние вкладки → синхронизировать только соответствующие указания навигации.

## Migration Plan

Ключи localStorage остаются прежними. Изменение интегрируется в текущий PR учебного окна после проверок; основная папка получает готовый результат до отчёта.
