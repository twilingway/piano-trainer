# Design

## Context

Vite собирает один HTML, Nginx уже обслуживает каталоги с index.html. Текущая карточка имеет
запечённые русские надписи; одной смены alt недостаточно. React не нужен для чтения карточек ботами.

## Goals / Non-Goals

Цель — согласованные метаданные и изображения для принятых двух языков. Серверное определение
браузера бота, новая маршрутизация приложения и изменение механики практики не входят в задачу.

## Decisions

- Чистая таблица `src/i18n/siteMetadata.ts` хранит локализованные значения; HTML-генератор
  использует экранирование и заменяет только помеченную секцию head. DOM-оболочка применяет те же
  значения.
- Vite преобразует HTML в dev по запрошенному пути и после build копирует уже собранный HTML с
  хешированными ассетами и Метрикой в ru/index.html и en/index.html. Три копии JS не нужны.
- Приоритет языка: ручное предпочтение, подсказка URL, язык браузера, EN. URL не меняется; history и
  загрузка песни не затрагиваются.
- Canonical и og:url зависят от запрошенного пути, а описания в живом DOM — от интерфейса. `/ru` и
  `/ru/index.html` нормализуются к `/ru/`, аналогично EN. Неизвестные пути имеют корневую
  идентичность. Все три HTML имеют симметричные hreflang. Начальный HTML корня всегда EN.
- Карточки экспортируются из существующего SVG с локализованными надписями и общим кадром игры; PNG
  проверяются визуально. Никаких новых production-зависимостей.

## Risks / Trade-offs

- Соцсети кешируют карточки → новые версионированные имена PNG; реальное превью проверяется после
  публикации отдельно от локального HTML.
- Ручной язык может отличаться от языка ссылки → это сохраняет одобренный приоритет предпочтения;
  сценарий явно описан в спецификации.
- Метрику легко потерять при копировании HTML → копировать финальный build и проверить все три HTML;
  dev должен оставаться без счётчика.
- Изменения находятся вне кадра и часов практики → применение метаданных только при смене языка.
