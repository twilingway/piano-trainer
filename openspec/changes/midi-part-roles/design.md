## Context

`songFromMidi` (`src/song/midi.ts`) отбрасывает ударные и пустые дорожки, сортирует остальные по
средней высоте и отдаёт верхнюю правой руке, следующую — левой, прочие — по высоте ноты. У `Song`
нет партий, у `SongNote` есть только `hand`. Транспонирование MIDI-песни (`transposeSong` в
`src/app/useSong.ts`) копирует ноты через spread, аппликатура (`withFingering`) тоже. Мотивация — в
proposal.md.

## Goals / Non-Goals

**Goals:** роли — чистая функция над статистикой дорожек, проверяемая без файлов; `Song` и
`SongNote` расширяются необязательными полями, так что MusicXML, дубли и уроки не меняются.

**Non-Goals:** интерфейс выбора партии и сессия (`practice-parts`).

## Decisions

### D1. Роли считает чистый модуль над статистикой

`src/song/midiParts.ts`: `TrackStats { onsets; chordOnsets; meanPitch }` и
`trackRoles(stats): PartRole[]` по правилам спецификации; `songParts` строит партии с названиями и
порядком. Статистику по дорожке считает `midi.ts`: начала нот группируются по тикам, аккордовое
начало — где нот две и больше. Пороги (7 полутонов разноса, четверть оживлённости, 15 % аккордов, 5
полутонов) — константы модуля.

### D2. Партии — необязательные поля модели

`Song.parts?: readonly SongPart[]` (`{ id; role; title; hand }`), `SongNote.part?: string`. Id
партии — `p<номер дорожки>`. Название — русский исходный текст; интерфейс переводит его через `t()`.
Песня с одной дорожкой и MusicXML партий не имеют, поэтому весь существующий код, который о партиях
не знает, работает как раньше.

### D3. Руки только из ролей

`hand` ноты — рука её партии. Прежнее правило «по высоте ноты» остаётся только для песни без партий.

## Risks / Trade-offs

- Пороги эвристики подобраны на нескольких файлах; странная аранжировка получит странные роли.
  Смягчение: выбор партии в `practice-parts` позволяет играть любую партию, а правила записаны в
  спецификации и покрыты тестами.
- Кадровый цикл и стан не затронуты: всё считается один раз при чтении файла.
