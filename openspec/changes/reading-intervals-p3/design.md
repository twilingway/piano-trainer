# Design

## Context

База — `dev ff324dc`, P2 принят и архивирован. Объём первого этапа указан в proposal.md. Аудит
текущих исходников выявил следующие точки повторного использования и ограничения:

| Область          | Текущий код                                                                | Решение P3                                                                      |
| ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Время песни      | `practice/session.ts`, `Trainer`                                           | Прежний PracticeSession для 20 визуальных нот                                   |
| Допуск атак      | `practice/readingPolicy.ts`, `useReadingCourse.ts`                         | Повторное использование gate и подтверждения показа с run identity              |
| Чтение           | `reading/session.ts`, `types.ts`, `progress.ts`                            | P2 оценивает одну высоту; отдельная типизированная оценка пары/выбора           |
| Стан             | `reading/prompt.ts`, `generator.ts`                                        | Чистый XML-проход для текущих двух нот с исходными ID                           |
| Прогресс         | `reading/progressTypes.ts`                                                 | Общая идентичность события и отдельные payload/сводки P3                        |
| Хранилище        | `app/readingRepository.ts`, `readingMigration.ts`, `readingPersistence.ts` | Один прежний listener/repository, schema 3 и intervals subtree                  |
| Звук             | `audio/pianoSound.ts`, `scheduledVoices.ts`                                | Готовность, отменяемые callbacks и голоса с owner identity                      |
| Готовность звука | `pianoSamples.ts`, `app/useSound.ts`                                       | Сейчас ошибка загрузки может resolve; P3 должен явно проверять доступные буферы |
| Клавиши          | `app/useKeyInput.ts`, `useTrainer.ts`                                      | На слуховом экране отключить piano bindings, ответы обычными кнопками           |

`Trainer.onInput` уже используется калибровкой. `useKeyInput.intercept` не перехватывает pointer и
получает keyboard после озвучивания; эти callback не заменяются для выбора категории. `soundAllOff`,
`cancelScheduledVoices` и `Trainer.silence` глобальны: их нельзя использовать как отмену только
одного эталона. `scheduledNoteOff(id)` разделяет release, но не предоставляет scoped dispose будущих
источников. Простое `await ensureSound()` не является подтверждением предъявления.

## Goals / Non-Goals

**Goals:** сохранить P2 и единственные часы песни; отделить чистую оценку от показа/звука; расширить
один существующий владелец сохранения; сделать ошибки аудио и stale callbacks проверяемыми.

**Non-Goals:** универсальный редактор курсов, новая база/сервис, переделка App.tsx, замена штатных
input/audio потоков, обобщение всех будущих навыков и педагогическое расписание интервального курса.

## Decisions

### Генератор и чистая оценка

`src/intervals` владеет типами, классификацией, seed-генератором, оценкой и сводками. Пять категорий
— `repeat`, `step-up`, `step-down`, `third-up`, `third-down`; подписанная диатоническая разность
равна 0, ±1, ±2. Например E→F — один шаг, D→F — два, независимо от полутонов. Полный план содержит
версию и по две пары категории. Публичный генератор использует только явные входы, без
Date/DOM/таймеров.

Визуальные 20 нот образуют одну Song из исходного MusicXML. Каждая пара — отдельное предъявление
двух нот; PracticeSession продвигает их штатным wait-вводом. Интервальная сессия только оценивает 10
пар по событиям и timestamps. Она не продвигает время и не переиспользует P2 ReadingSession как
кнопочный quiz. Вся помощь, включая первую ноту пары, относится к паре; ошибочная опора исключает
верность первой попытки пары. Ручная помощь не меняет настройки P2.

Слуховая сессия получает `listeningStarted`, `listeningCompleted`, `listeningCancelled`, `answer`,
`helpShown`, `activeChanged` с identity и монотонным временем. Первый полный эталон открывает
допуск; любой повтор закрывает его до завершения. Ошибка не продвигает вопрос. После паузы/hidden
нужен новый полный эталон, неполный не увеличивает счётчик. Тайминг суммирует только открытые
активные интервалы, а не весь wall-time; при повторах он приостанавливается и возобновляется.

Общая идентичность результата P2/P3 остаётся общей, payload различается по skillId и responseKind:
`piano-pair` хранит ожидаемые/сыгранные MIDI и роль ноты; `category-choice` — категорию. Для кнопки
keyboard означает активацию клавишей, pointer — мышью/тапом. Это не экранная клавиша пианино. Сводки
по модальности не объединяются; визуальный показатель называется игрой пары по нотам.
`firstListeningCorrect` означает первую верную попытку после одного полного эталона, без помощи и
прежних частичных проигрываний этого вопроса. Отмена после реально начатой ноты увеличивает
`partialListeningCount`, но не число полных прослушиваний. Повтор эталона не превращается в hint.
Обычная самостоятельность без явной помощи остаётся отдельной.

Визуальная пара относится к источнику завершающей правильной атаки второй ноты. Все ошибки,
источники и помощь обеих нот сохраняются независимо от фильтра. Первая попытка пары верна только при
первых верных атаках обеих нот; ошибка второй ноты после верной опоры также делает её ложной.

### Аудиоэталон

Тональный эталон — конечное расписание двух нот относительно `audioTime()`, не вторые часы песни. Во
время слухового режима обычная PracticeSession стоит; её song time и намерение воспроизведения не
меняются callbacks эталона. Визуальный режим продолжает пользоваться прежней практикой.

`src/audio` предоставляет ресурс предпрослушивания с owner/run/question/generation и отменой своих
callback IDs и своих голосов, включая уже созданные будущие атаки. Нужны per-owner dispose и
идемпотентная отмена; глобальный all-off для этой цели не подходит. Переключение/hidden/pause и
unmount синхронно инвалидируют generation до очистки. Глобальная отмена Trainer также инвалидирует
активный эталон; ложного listeningCompleted после неё нет. Обычная практика и эталон не конкурируют.

До запуска подтверждаются пользовательский жест, работающий AudioContext, доступные буферы обеих
высот и ненулевая громкость приложения. Ошибка загрузчика не считается ready, повтор действительно
перезапускает неудавшуюся загрузку. Shell сообщает pure-сессии полное предъявление только после
завершения обеих успешно запущенных нот текущей generation. Повторные клики во время звучания
игнорируются; два эталона не накладываются. Системную громкость/внешние колонки приложение проверить
не может; слышимый звук проверяется отдельно в браузерной приёмке.

### Хранение и подключение

Прежний ключ `settings/reading-course-v2` получает `schemaVersion: 3`; P2-поля остаются на месте,
добавляется `intervals` с отдельными выбором, фильтрами и историей двух режимов. Новая БД или второй
сервис не создаются. Срок и журнал новизны P2 относятся только к P2. Общая идентичность/дедупликация
и существующий путь транзакций используются для P3, а P2-агрегация по высотам не расширяется
фиктивными нотами выбора категории. Runtime, незавершённые ответы и аудиоресурсы не сохраняются.

Listener пишет только изменённые поля соответствующего поддерева. Read-modify-write внутри прежней
транзакции сохраняет sibling-данные и объединяет истории по runId. `readingPersistence` расширяет
baseline и local-progress-since-load для P3: поздний load не заменяет более новый выбор, помощь на
текущем проходе или завершённый локальный результат. Будущая схема и ошибка чтения блокируют запись
defaults; put подтверждается только transaction complete. Лимит — 20 результатов на режим.

Hooks `src/app` соединяют policy, renderer readiness, чистую сессию, сохранение и аудиоресурс.

Корневой `activeCourse: "note-reading" | "interval-training" | null` — единственный discriminator
активного курса; null соответствует обычной песне. Сохранённые выборы обоих курсов могут остаться,
но активен только один runtime. Выбор P3 снимает P2 policy; выбор P2/обычной песни освобождает P3
сессию, policy и аудиоресурс. При миграции activeCourse выводится из прежнего активного P2-выбора,
иначе null. После reload запускается только сохранённый активный курс; поздний load не отменяет
более новый activeCourse и не создаёт второй runtime. Baseline/revision охватывает общий выбор.
`src/ui` получает props/команды; App.tsx только компонует. Источник режима не подменяет глобальные
предпочтения игрока. Слуховой экран не показывает стан, падающие ноты, имя цели и клавиатурные
подсказки; MIDI не служит выбором категории. Вид и обычный ввод восстанавливаются при выходе. RU/EN
через `t()` и каталоги; таблицы прокручиваются внутри панели, мобильный rail сохраняет место.

### Производительность

MusicXML и seed-пары строятся при выборе серии; XML-проход пары — при смене предъявления, не каждый
кадр. Сессия не создаёт массивы и не перерисовывает OSMD на каждое нажатие/тик. React подписывается
на узкий snapshot; звуковые ресурсы создаёт один owner, async callbacks проверяют identity. Проверка
renderer readiness не создаёт второй кадровый либо музыкальный цикл.

## Risks / Trade-offs

- Звучание молча пропускается при отсутствии семплов → явное ready/error и retry; нет оценки до
  успешного завершения пары, отдельный ручной тест слышимого звука.
- Общая отмена звуков или старый callback портит новый режим → owner dispose, generation guards и
  тесты переключения во время первой ноты, паузы/hidden и глобальной отмены.
- UI назовёт игру по нотам измерением распознавания → разные skillId/responseKind и ясные сводки.
- Проигрыш P3 при позднем restore/записи другой вкладки → расширение hydration baseline, sibling
  merge и регрессии двух store/транзакций.
- Старая v2-вкладка видит schema 3 → прежний future-schema guard блокирует её запись; данные не
  стираются, для сохранения требуется обновлённая страница.
- Баланс в C4–G4 не доказывает чтение неизвестной музыки → нет гарантии новизны/освоения; весь
  остальной P3 вводится отдельными изменениями.

## Migration Plan

1. После согласования добавить validator/migration 2→3 в прежнем хранилище. P1 проходит существующую
   миграцию до 2, затем до 3; настройки, результаты, profile и fingerprints не переоцениваются.
2. Добавить пустое intervals subtree и merge/dedup по runId, не записывая defaults при load error.
3. Подтвердить повторную миграцию, повреждённый P3, late-load, две вкладки и abort после put.
4. Доставить через task PR в dev; после пользовательского merge — ff-only основного dev и приёмка на
   прежнем 5190. Серверы не запускать. Пакет и зависимости не менять.
5. При откате код v2 не записывает schema 3 благодаря future-schema guard. Исходная legacy-копия
   localStorage сохраняется; не понижать схему с удалением P3 ради отката.
